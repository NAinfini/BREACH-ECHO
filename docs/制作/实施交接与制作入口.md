# 实施交接：从文档开始制作

## 当前事实

整体美术方向与模型档位按所有者要求重新比较，分层壁垒仅为候选。[Meshy工作流研究与美术重选计划](../表现与资产/Meshy工作流研究与美术重选计划.md)已整理网页免费重试、多视角输入、模型、绑定/动作、作品参考与材质需求；[六种对照图](../表现与资产/六种美术风格对照图.md)已按所有者纠正重做为游戏画面概念。实际账户权益、模型样件和引擎测试未验证。下一项是审阅游戏美术方向，再制作选中资产的单件参考图规范样张；这不提前启动游戏或收费生成。

终局链的现行入口为[Operation撤离扫描](../玩法/系统化战术行动模式.md)、[分项收益](../玩法/知识永久进度与壁垒.md)、[前端续局](../玩法/前端房间与会话流程.md)及[终局数据](../技术/数据命令事务与存档合同.md)。规则是共享扫描一次结束、区内撤离/区外被留下，不是个人撤离；文档与有限算术已补，不代表真实结算/恢复实现。当前批次的具体验证与下一项只在[准备度交接](游戏开发准备度与责任覆盖矩阵.md)维护。

本仓库目前是文档基线。本次变更中没有可玩的 Unity 项目、游戏构建、实测基准、已购资产清单、已部署服务或已完成试玩。下列每个里程碑在附上证据前均为**尚未开始**。文档检查只验证文档，不能替代里程碑验收。

贡献者必须交付可运行构建和容易理解的测试指南，不能交付一堆需要手工拼装后才能评估的脚本。

当前文档讨论与跟进动作见[待办清单](待办清单.md)。完成条件满足后移除待办，将结论留在责任文档；本页继续拥有制作里程碑与游戏验收，不复制短期待办。

黑启动重资产、首轮战斗/工具数值、倒地动作与探测边界已收敛，分别见[战斗参数](../内容/装备/战斗原型数值.md)、[生存](../玩法/生存倒地与失败恢复.md)和[初始参数](初始测试参数.md)。三件专用近战的普通/蓄力、命中、取消和无补给消耗规则见[近战合同](../内容/装备/首轮近战攻击与资源合同.md)。完整一局与三种任务差异已汇入[玩家体验走读](首轮配装三任务走读与风险验收.md)，[全动作手感验收](../表现与资产/全动作手感与舒适性验收.md)约束首轮所有动作。左键任意蓄力释放与右键取消已修正；[两敌人攻击与弱点布局](../内容/敌人/首发敌人目录与行为卡.md)、[同步与传播](../玩法/潜行唤醒与持续追杀.md)、[战报归因结果](../玩法/任务战报与行动回放.md)已有可核对合同，数值和近邻反应仍为TEST。设施库存、跨阵营模拟计数、任务结果与来源停机、固定补给单位及断线身体连续性已收敛，见各责任文档和当前决策登记。代号已确认，下一创作域为OWNER-01的人物经历、关系与收藏事实审阅；全部不替代OWNER-05批准，不启动游戏实现。

Gate批准后的第一项可执行任务为M0。

阅读根目录`AGENTS.md`、项目文档技能、[开发准备度矩阵](游戏开发准备度与责任覆盖矩阵.md)、首发范围、技术栈、架构与数据合同。获准后在`game/`创建Unity 6.3 LTS URP项目，目录统一采用[工程结构](../治理/选型依据/智能体优先工程结构与模组运行时.md#项目结构影响)；只创建本里程碑实际消费的包与数据，不预先搭空SDK、Mod编辑器或全网络系统。第三方授权导入走独立访问控制的资产流程，测试放在责任包旁。这是计划结构，不代表已有可运行代码。

创建 `Bootstrap` 与 `CombatSandbox` 场景、一名本地权威胶囊玩家、一台相机、一个命中扫描靶、一个原创灰盒武器、一份 Input System 动作映射和一个小型调试 HUD。只安装运行这条路径必需的依赖，并锁定实际构建过的准确版本。运行一个 EditMode 数据验证测试、一个 PlayMode 命令到伤害测试，以及一个 Windows x64 独立构建。游戏代码与 Steam 解耦，使该构建无需在线服务凭据也能运行。

**M0 验收：**干净检出配合已记录且获准的资产来源，能按书面步骤复现同一构建；不得存在 Inspector 引用丢失、编译错误、无许可可再分发内容、内嵌凭据或手改机器路径。交付包/版本清单、测试日志、可执行文件或制品位置，以及“启动、移动、瞄准、射击靶子、退出、报告结果”的操作指南。仅能在 Editor 中打开场景不算通过 M0。

## 接口所有权与审查

M4地点环境与M4b活动规则均按[共享Modifier运行合同](../技术/关卡与活动修改器编译及运行合同.md)实施，引用[环境候选](../内容/设施与资源/关卡环境修正器候选与验证.md)、[活动候选](../内容/活动/特殊活动修改器候选库.md)和[玩家/敌人强化](../内容/活动/玩家与敌人强化修改器候选.md)。先验证单项真实消费者，再测试组合；首批包含槽位/伤害、有限/无限供给、风暴阶段与工具并发。无限资源仍需最坏合法输出、实体预算、迁移与结算验证。候选池不是首发产量；当前仍不启动M0，也未创建活动或安排自动运行。

Kernel 拥有命令、状态、实体身份、效果与事务；Operation 拥有当前模式政策与任务生命周期；Content 拥有定义与已验证能力；Simulation 拥有可变世界真相；Network 只拥有传递、预测和投影，不建立竞争真相；Persistence 拥有序列化与领取幂等性；Platform 拥有 Steam/云绑定；Presentation 拥有相机、动画、UI、声音与视觉密度；测试必须实例化与正式环境相同的玩法合同。

实现 PR 必须列出所实现的规则 ID，包含正向与负向测试，并说明仍存在哪些设计风险。全局事件总线不得掩盖必需的数据所有权。服务接口必须有真实消费者；不能仅因为未来模式可能需要，就添加通用扩展点。对所有者明确要求的改动走 OWNER-04；普通的证据驱动实现变更仍属于受托决策。

任务长度与难度使用不同配置轴：首个短图、Standard七阶段长局和五档长局派生不能混用。三任务文件拥有实例，难度矩阵拥有算法，`tools/check_standard_run.py`与`tools/check_long_difficulties.py`复算各自范围；后者首补前检查不能代替全程混编弹药与动作验证。工业故障用`tools/check_industrial_hazards.py`核算窗口，裸母线电弧仍是接地变体候选，不进入首个相位丢失灰盒。静态测试PASS不升格任务配置或解除OWNER-05。

[高难后段验算](高难后段火力补给与行动窗口验算.md)补充两组四席固定分工与54项压力库存对照，包含明确缺口；`tools/check_late_run_windows.py`同时复算补给、搬救、换弹和扫描下界。各任务LATE-SPACE和MIS-LATE-WINDOW是后续实体空间验收输入，不是已搭建地图。M4扩展高难前必须完成LATE-ACCEPTANCE：实际抵达时序、预清/工具支出、1至4人、失去关键设备与扫描中救援，尤其复查最高难正面硬打的第六/七段缺口；不得把通过静态脚本当高难已通过或跳过M1/M2依赖。

## 单项功能的完成定义

单人与Bot按[合作命令及验收](../玩法/合作单人机器人与公共匹配.md#单人与bot验收清单)、三任务SOLO-WITNESS及[AI-BOT-CONTROL](../技术/人工智能运行架构.md)实施。M2先在0Bot微型黑启动证明放物、腾手、顺序开关和前向扫描；M4扩展到取证/货运及各长度。M3用现存身体验证换控制者不复制物资或奖励；M5再做最多三Bot的合法感知、停火、局部工具指令、受阻救援与真人接替。记录误唤醒、挡路、人工命令负担、资源账和控制epoch；不能用纸面顺序路径代替实体可达，也不能先造Bot补救M2无解。当前全部尚未实现，PRE-GAMEPLAY不因此关闭。

首局学习按[ONB-001至008](../玩法/新手教学首局与长期学习.md)与[UIFLOW-TRAINING](../玩法/前端房间与会话流程.md)实施。M1随实际动作加入独立可重置的操作夹具，M2接终端/携物/警报和共享撤离例子；M3检查不同本地教学状态不影响同一Run及接管，M5a完成首启、跳过、分项入口、Bot练习及8名新手/设备验证。不要先建整套教学引擎或专属任务池；练习与正式动作共用合同，资源/奖励和本局秘密不得跨环境导出。A-ONBOARDING仍NOT RUN，所有开工前置保持。

现场信息实施先由[设施查询/事务](../玩法/设施信息与控制规则.md)提供合法事实，再由[Ping沟通](../玩法/合作单人机器人与公共匹配.md)和[UX-FIELD-FEEDBACK](../表现与资产/界面信息与可访问性.md)呈现；输入、声音和对白复用同一阶段/因果标识，不签发世界结果。M2用一台终端、一次配置预览/提交/失效和现有危险验证单人反馈；M3验证四人并发、重复Ping、断线与迁移；M5再过完整设备/语言/声音/陌生人理解Gate。七个现场情境和负例是未来测试输入，当前未实现；不为通知系统抢先制作通用工作流引擎。

任务板至入场按[前端UIFLOW-BRIEFING](../玩法/前端房间与会话流程.md)和[UX信息边界](../表现与资产/界面信息与可访问性.md)实施：共用公开规则投影，区分预约与Run锁定，不将实例图/作者槽交给通用详情控件。M0只交付上文Bootstrap/CombatSandbox最小路径；M2用一项本地黑启动合同验证最小卡片、配装、确认入场及终端合法授知。M3再测多人Ready版本竞争、下载/补位/重连；M4扩展三任务，M5补完整前端与目录/活动体验。十一条流程正负用例、九修改器披露表和中英模板是验收输入，不是已运行测试；不得为展示候选而提前实现整套控制面或解除开工Gate。

M4/M4b的具体输入补充为[修改器任务映射与组合准入](../内容/任务/修改器任务映射与组合准入.md)。先按原任务通过基础图，再做四环境、三趣味与两强化的单项对照及九组组合；不得让M0/M1先实现全部修改器。`check_modifier_mappings.py`只是文档白名单与算术检查，不是可复用游戏运行时；实体绑定、空间/声学、同Tick竞争与恢复仍需真实实现验收。
