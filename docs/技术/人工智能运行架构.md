# AI决策、感知、群组与导航架构

## 单一责任与选定模型

AI-001 · DECIDED。

AI分为`Wake Detection → Active Targeting → Cohort → Intent → Action → Motor`六层。Wake Detection只负责休眠体能否被合法刺激唤醒；进入Active后，Active Targeting持续从Authority持有的存活玩家中选择可达目标，Cohort协调占位，Intent选择动作，Action管理多帧前摇/Commit/恢复，Motor在权威模拟中执行移动和碰撞。任何层不得读取玩家输入、客户端相机或未复制秘密；持续追杀使用服务器玩家实体状态，不由客户端签发目标。

首发采用“顶层有限状态机 + Active内共享行为树”：虚空兽FSM负责Dormant/Stirring/Active/Disabled/Dead等少量模式，进入Active后本局不可回到Dormant；设施单位使用Standby/Tracking/Engaged/Controlled等协议状态。行为树处理选择可达玩家、接近、攻击、改道、协同和部位失能后的优先级，不存在调查、放弃追击、回巢或恢复平静分支。暂不引入全局Utility AI、在线LLM或每敌人独立脚本框架；只有真实行为复杂度无法由共享树清楚表达时再评估。

## 频率与权威

AI-002 · DECIDED。

Authority拥有所有AI真相。感知采样、Belief更新和高层Think默认5–10 Hz TEST并按Cohort错峰；已选择Intent的移动、碰撞、攻击Commit和受击在60 Hz权威时基执行。可见/交战单位提高Think频率，远距单位降低，Dormant对象只响应事件。降频不能延长已公开攻击前摇、跳过合法受击、重置冷却或改变资源事务。

每次Think读取一个固定tick的只读世界快照，输出`IntentCandidate`；统一提交阶段按稳定EntityID排序验证目标、部位、路径、动作阶段和成本后写入。工作线程完成先后不影响选择。行为随机只使用RunSeed派生的`AI/{entity-id}/{purpose}`语义RNG流，不用帧时间或全局随机。

## Blackboard与Belief合同

AI-003 · DECIDED。

每个实体Blackboard至少包含：当前FSM状态、是否已永久激活、目标EntityID/generation、当前路径与revision、Intent/Action阶段、冷却、部位能力快照、传播群/CohortID、SourceID和Stuck状态。Dormant/Stirring额外保存最近合法刺激；Active保存目标选择与路径失败信息，不保存用于脱战的怀疑、记忆时限或回巢计时。Blackboard只存稳定ID和有界数据，不保存Unity对象引用或行为节点私有世界真相。

Wake Evidence记录`stimulus-kind/source/position/strength/observed-tick`，只决定休眠体是否进入Stirring。Active Targeting读取Authority上当前存活、未撤离的玩家实体，优先选择可达性、距离和敌人职责最合适的目标；失去视线只禁止不合法的精确射击，不取消追击。目标不可达时尝试合法改道或切换另一名可达玩家；所有玩家都不可达时保持Active并停留在最近合法阻隔处，不生成调查状态、不回巢、不传送。

## 感知与通信

AI-004 · DECIDED。

感知通道为视觉、声音、接触、伤害、能量梯度和明确设施信号。每种敌人内容卡声明通道、范围/角度、遮挡层、采样频率、刺激阈值和记忆；UI或渲染不可成为感知源。视觉必须做视锥与遮挡，声音通过房间/门传播图衰减，接触与伤害为Authority事件，能量只指向已供能区域而不是玩家坐标。

通信需要发送能力、接收范围/拓扑、前摇和真实响应Source。Scout完成呼叫只向已存在且有budget、Ingress和路径的Source提交请求；所有入口封闭时请求失败或延迟，不能生成隐形单位。部位破坏、门隔离、失去供能或协议重写可中断通信，并产生可读反馈。

## 行为树与动作合同

AI-005 · DECIDED。

共享树节点只返回`Success / Failure / Running`，多帧Action在Running时保存游标，不允许每个Think从头播放。Condition无副作用；Action只能请求明确Command，资源与世界变化仍由Simulation事务提交。Dormant树只处理合法唤醒刺激；Active树的顶层优先级为：致命状态/失能→已提交动作续行→近距反应→选择或切换可达玩家→接近/攻击/协同→阻隔处等待路径变化。Active树没有调查、守区、取食、Idle或回巢出口。

每个动作定义：前置能力与部位、目标范围、最小/最大距离、路径要求、诚实前摇、Commit点、恢复、取消来源、冷却、输出事件和失败原因。选中Action后使用短期承诺与明确重评事件，避免每个Think在两个目标间振荡。攻击必须留出可由侧移、冲刺、蹲闪、跳跃、滑铲、翻越、门或高低差中至少一种方式处理的可读窗口；不靠无前兆自动转向命中玩家。目标评分只用距离、可达性、威胁、任务角色和最近互动等公开事实，不读取玩家血量UI外的秘密Build来克制。

## Cohort与遭遇Source

AI-006 · DECIDED。

Cohort负责阵形、占位意图和目标角色分配，不决定Active敌人是否继续追杀。Cohort可让Runner逼位、Suppressor封线、Flanker走侧路，但每个单位仍需合法路径与动作；切断通信只削弱协同，不会让已激活敌人放弃玩家。

Director/Source决定“哪些单位可以在何处进入”，AI决定“已经存在的单位如何行动”。AI不能自行创建单位，Source不能给单位写玩家位置。每个已经投入的非玩家自主单位按[遭遇预算](../玩法/敌人遭遇与难度.md)登记自身`ActiveSimulationCost`，包括Controlled友军与中立设施；Director在提交新实体前原子检查来源ThreatBudget、全局在场成本、远程/重型槽位与入口。任一上限已满即零生成，不能先创建再删除来伪装守恒。Source预算、Ingress和上限归[遭遇系统](../玩法/敌人遭遇与难度.md)。

## 导航与局部移动

AI-007 · DECIDED。

使用Unity AI Navigation：每个手制Cluster提供已烘焙NavMesh数据与显式门/梯/维护口/特殊体型链接，程序图拼接后验证连通区和链接revision。普通3D路径使用NavMesh，不自研密集网格A*；房间级战术选择使用Cluster Graph，多个单位前往同一区域时可共享房间级路径或flow cost。

路径只在目标跨过显著阈值、门/链接revision变化、超时或Stuck时重算，不每帧寻路。全局Path Queue有每tick预算与优先级，交战近距、脱困和任务关键单位优先。Motor沿下一个路径拐点Steer，局部避让不能把角色推出NavMesh、穿门或永久软占位卡住玩家。连续无进展进入`Stuck`，先重寻路，再选合法替代Intent；禁止传送到玩家身边，开发构建可以在明确日志后重置到最近合法点，发行版必须通过关卡/行为避免该状态。

## 设施单位与阵营改写

AI-008 · DECIDED。

设施炮塔、机器人和维护机复用感知、Belief、Action与Faction合同，但使用不同FSM。协议改写原子更新Faction、AllowedCommands、FacilityControlRevision和当前目标合法性；已经Commit的弹体/维修保留，未Commit的敌对前摇取消。己方命令限定为守区、跟随、守门、停火和指定合法目标等战术命令；不能接受玩家任意脚本或代替任务决策。

## 外勤队友控制

AI-BOT-CONTROL · 2026-09-07受托DECIDED，运行验证NOT RUN；行为边界唯一见[合作合同](../玩法/合作单人机器人与公共匹配.md#机器人命令与战斗边界)。队友Bot不接入虚空兽的Active Targeting，不读取全场存活目标表来自动瞄准；它是玩家Seat的一种输入所有者，走相同Gameplay Command、枪械Action、资源及Motor路径，不另造AI专用伤害或免费交互。

首轮复用有界行为树与多帧Action，队友树独立于敌人树。优先处理生命/控制权失效、已提交动作续行、眼前可规避危险、按合作合同有资格的救援、当前显式命令和跟随防御；停火与战略权限是共同硬约束，不被自卫绕过。常规战斗只选合法感知到的Active目标；休眠攻击须关联一次明确授权。命令完成后恢复跟随/守点锚及开火政策，不遗失停火状态。

队友Blackboard记录SeatID、控制epoch、当前CommandID/revision、发令人、目标版本、授权物件/最大支出、跟随或守点锚、开火政策、动作游标、合法知识来源及失效时间、救援目标与路径阻隔。目视和有效面罩点标可追踪目标；失效后只保留允许的最后已知信息。导航可读取实体碰撞，但不能借全地图导航向玩家泄露未发现房间、敌人或秘密路线。人物性格不改变命中、救援优先权或职业权限。

命令状态为已接受、前往、执行、暂受阻、完成、取消或失败。接受只表示权限、能力与目标初检通过；到达及每次成本提交仍重新校验。并发命令携带期望Bot命令版本，统一接受首个合法者，其他返回当前任务；覆盖须看到新版本后显式重发。取消不退回已有效的弹药/部署，不自动重试一次性消费，不在路径失败后改买物资。

自动救援在同一提交阶段预约伤员的实际救援位，预约不赋予无敌，也不排斥真人接手。真人合法开始救援优先接管尚未完成的自动预约，Bot取消读条并让位；已成立恢复恰好一次。伤员移动、搬运、Out或施救者失能时释放预约。无路径时按门/导航revision及目标变化重评，沿AI-007有限重寻路，不逐Tick通知或伪造进展。

真人接替原子递增控制epoch、切换输入所有者、取消Bot未提交动作与预约、清除旧命令和意图回应；已提交库存/攻击/世界状态保留。旧epoch命令均拒绝。Host迁移保留同一epoch、命令、开火政策、动作提交游标与资源账；未提交占手交互按原恢复规则取消，不重新领取。命令的实际完成和资源消耗不依赖语音回应。

调试记录命令来源、拒绝原因、感知依据、瞄准/开火时点、受阻、救援中断及交接前后库存。反应和瞄准须M5实测建档，不能随机故意打偏掩盖错误目标/枪线，也不能因服务器知道结果就无耗时锁弱点。按COP-BOT-ACCEPTANCE验收，未测不宣称等同真人水平，不实现新的通用AI框架。

## 存档、复制与调试

AI-009 · DECIDED。

恢复状态包含FSM、Belief、Blackboard有界字段、Cohort/Source、Intent/Action阶段、冷却、RNG和路径目标/revision；具体NavMesh path可在恢复后重算，不把Unity内部引用序列化。客户端只接收表现所需的状态、目标提示和动作阶段，不复制完整Blackboard或未发现位置。

开发构建必须能显示实体ID、FSM、当前Intent/Action、最后刺激、Belief置信度、Cohort、Source、路径、NavMesh链接和Think耗时；能冻结/单步AI并导出Seed+事件，不修改正式结果。性能Profile按Perception、Think、Path、Motor、Animation分桶。

## 验收与未证明项

AI-010 · TEST。

固定Seed验证休眠体不会因隔墙玩家移动无故苏醒；Active敌人失去视线仍追杀、门关闭后改道、无路径时停在合法阻隔而不传送；Scout无已触发Source不召怪；警报/节点来源不超过合同预算；部位破坏取消能力、协议改写换阵营、Host迁移不重置攻击，以及100/500/1000轻量敌人分频负载。代表性四人场景中AI Think错峰不得产生周期性帧尖峰；准确预算由性能Spike确定。行为、导航与性能当前均NOT RUN。

## 基础攻击与苏醒的跨层一致性

AI-ACTION-COMMIT-BOUNDARY · 受托DECIDED；实现NOT RUN。

苏醒倒计时是独立权威事实，不以动画或普通硬直暂停。受击动作可以与Stirring表现组合，但不能把倒计时重新放进每次Running动作的起点。到期与死亡沿统一提交顺序结算，Dead不会在下一次低频Think补发脉冲。保存和恢复必须保留苏醒截止、已发脉冲标志、每接收者刺激去重键和当前累积量。

逐能体一次近击只有一个伤害提交；压射体三连射拥有逐弹提交序号，不以整轮起始一次性生成全部伤害。恢复必须保留锁定方向/点、轮起点、已提交弹序号和再攻击截止；不能从动画进度猜测漏了几发，也不能重播已射弹。能力破坏、死亡与切换目标不倒退提交游标。具体动作相位由[战斗参数](../内容/装备/战斗原型数值.md)拥有。

近邻受击刺激属于Wake Detection的离散权威事件，不读取布娃娃碰撞、客户端画面或音频是否被虚拟化。对每个合法接收者按TP-WAKE去重，与同根声音只取更强贡献。已死亡接收者不进入Stirring；不先把整个Cohort唤醒再回滚不应醒者。开发记录须能解释距离、朝向、遮挡、根事件、阈值和首次激活原因。

Cohort的占位协调不能成为幕后攻击令牌：在真实站位满足条件时，多个敌人可以各自提交攻击。局部避让不得让实体层叠成不可读的一团；无法形成合法攻击位置的敌人继续寻路，不隔着同伴身体延长攻击距离。攻防可读性与攻击上限不能靠删除已经存在的敌人来达成。

## 全目录部位与多段动作的一致性

AI-ENEMY-PART-ACTIONS · 受托DECIDED；实现NOT RUN。数值与几何从[战斗参数](../内容/装备/战斗原型数值.md)读取，布局和玩家应对由[敌人目录](../内容/敌人/首发敌人目录与行为卡.md)拥有，行为树不另存一份伤害表。

每个动作实例保留能力依赖、锁向结果、起点/截止、提交游标和实际命中过的目标集合。部位事务先更新能力，再取消尚未执行且确实依赖该能力的部分；不会因为任意断肢就全身眩晕，也不会取消已飞出的弹体。破阵冲刺的逐接触扫掠保留已命中集合；破腿或合法硬直停止未来扫掠，不回滚已成立接触。切动作、失去目标和恢复存档不刷新已有再攻击截止。

探讯体保留CallBinding实例、调用截止和已成功提交标志；冠破坏只取消未提交呼叫。来源请求单独按既有准入事务检查预算/入口，重复恢复不重复提交。缝行体保留当前特殊链接和合法出口，断攀行肢不在链接中央掉出世界；到出口后只用剩余能力可通行的路径。投涌体保留已锁落点和真实弹体，换目标不搬动落点，不靠天花板后生成来补偿非法弧线。

猎界体的肌体、再生囊、有限储备、局部装甲、失能截止共同决定能否恢复；Disabled仍是同一存活实例，不释放成本、不签发死亡结果。在同Tick中先结算已提交伤害和部位破坏，再判断合法恢复，囊已毁者不恢复；Dead只提交一次。零肌体阶段可推进实体甲/囊损坏，但不伪造生命扣除。修复与失能恢复都由同一储备事务扣除，不在表现动画中补血。设施重写同样保留损伤、库存和电池，不自动修复失去的功能。

待运行验收：断肢前后各一个Tick、首弹/末弹间、冲刺已撞一人后中断、通信刚提交后击杀、猎界体恢复截止同Tick破囊、Disabled迁移、炮塔射击间接管、维修提交前断臂。核对旧结果恰好一次、未来无能力动作零次、库存与来源总量守恒；静态文档检查不能宣称这些运行测试通过。

## 阵营与预算事务

AI-FACTION-ACCOUNTING · 受托DECIDED，未实现。

FacilityControl修改的是同一实体的阵营、命令集和控制版本，不创建替代友军。事务同时更新敌对职责计数与目标合法性，自主模拟成本登记保持；Source已花预算和生成历史不回滚。登记只由Authority实体生命周期拥有，不能在行为树、OnEnable、画面LOD或音频启停回调中各维护一份。

恢复记录保存已登记标志、成本档、阵营版本和来源事务ID；恢复后从存活实例核对计数，而非重新执行一次接管奖励或Spawn。死亡和新增竞争按统一稳定提交顺序处理；后来的合法新增只能使用已经实际释放的成本。现存实体唤醒不等待准入，超额时阻止新增并记录压力样本，不用AI暂停掩盖设计错误。
