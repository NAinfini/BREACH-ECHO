# 关卡与活动修改器编译及运行合同

## 架构结论与范围

MOD-RUNTIME-SCOPE · 受托DECIDED；只有设计合同，未创建运行时、DTO或测试代码。

普通地点条件、每日/每周/临时挑战共用`ModifierDefinition → ModifierBundle → RunRulesSnapshot`。排期只决定玩家何时能选某份Offer，不决定如何执行伤害、槽位、资源或环境。普通Run的活动引用为空；有无Event都用同一编译与命令路径。环境可作用于地点，双倍伤害/禁槽/无限供给等趣味规则仅进入明确声明的特殊挑战，不改变普通任务默认值。

在线目录与认证、排期、发布、缓存和回滚由[在线活动控制面](在线活动控制面与版本快照.md)拥有；本文唯一拥有Modifier的编译结果、运行时消费和动态状态。内容候选不是任意字段编辑器，也不要求先写一套通用引擎。只为已经登记的环境、槽位、伤害、工具成本和端口供给实现有真实消费者的能力；更多修正器通过现有能力组合，缺能力则正常开发与验证后发布。

## 定义与编译结果

MOD-RUNTIME-COMPILE · DECIDED。

| 数据 | 必需内容 | 边界 |
|---|---|---|
| `ModifierDefinition` | 稳定ID/版本、名称/说明键、允许入口、目标Tag/作用域、类型化操作与有限参数、能力/包依赖、读写集合、叠加/互斥规则、复杂度、验证配置 | 模式入口至少区分普通地点与特殊挑战；不能以反射路径、任意表达式或远程代码写字段 |
| `ModifierBundle` | 精确版本引用与参数、合成顺序、已解析内容目录/语义槽和冲突诊断 | 锁定时解析内容Tag与布局约束；实际EntityID生成后绑定；缺目标、重复ID或不合法叠加显式拒绝 |
| `RunRulesSnapshot`中的编译结果 | 基础规则/任务/难度与内容hash、地点和活动修正器精确列表、最终槽位合法性、数值修正、成本/供给政策、环境配置与阶段定义、奖励政策、最终hash | 普通与活动Run共用；所有参数都是有界值，所谓无限只用类型化政策，不使用Infinity/最大整数库存 |
| `ModifierRuntimeState` | Run内实例ID、定义引用、Zone/设备目标、当前阶段、阶段截止Tick、RNG状态及revision、已提交操作关联 | 仅保存动态事实；设备库存/损伤/阵营仍归原设备，不能再复制一份Modifier库存 |

锁定过程：解析基础任务/难度与地点条件，合入活动候选，验证能力/冲突/预算/合法配装与资源可解性，生成最终任务卡，Ready冻结精确快照，再派生任务实例。完整实例在Authority开始前必须通过空间/资源检查；失败返回生成错误，不算玩家团灭，不悄悄删掉某条Modifier。客户端在Loading前核对hash，迟加入也读取同一快照。

操作只进入其明确政策通道：槽位合法性、现有Stat通道、资源成本、资源来源供给、设备可用性和环境状态。互斥写入无“最后写入者赢”；标量只有显式声明同通道合成方式才可叠加，相同倍率不能因重复Bundle引用执行两次。数值统一使用[修改与效果系统](../玩法/统一改装与效果系统.md)的通道与取整，不另建伤害引擎。具体序列化DTO仍须首个实现PR冻结并测试。

MOD-RUNTIME-TARGET-BINDING · 受托DECIDED。Ready前冻结的是精确内容、参数、语义Zone/设备槽、预期目标数量和保护约束，不是假装随机地图的EntityID已经存在。生成后、开始模拟前，将这些槽绑定到唯一实体/连续体积，保存绑定清单及hash；客户端核对规则hash与实例绑定hash两者。缺槽、目标数量不符、绑到任务必要能力或找不到安全路均拒绝该实例，保留原Seed与诊断，不重新抽目标或静默关闭效果。

MOD-RUNTIME-PUBLIC-VIEW · 受托DECIDED。编译结果分别供实际规则消费者和玩家公开说明使用；后者只投影已声明效果、最终参数/名单、范围类别、禁槽、例外、反制类型及奖励条件，不包含作者语义槽、实际绑定、逐房数量或生成诊断。未被公开说明覆盖的有效操作是发布错误，不能靠通用字段浏览器把内部结构全部展示。任务板、Lobby、Ready与加载共用同一版本的公开说明；现场位置/设备余量/相位由合法知识与观察另行授予，边界见[UX-BRIEFING-BOUNDARY](../表现与资产/界面信息与可访问性.md)。核对hash不表示玩家获得完整地图；这是呈现合同，不新增网络反作弊或防数据挖掘服务。

同一实体的供电、权限、损伤与环境抑制分别由原消费者读出，不能让多个Modifier争写一个最终Enabled布尔值。恢复先还原真实设施状态，再计算当前可用性；解除风暴不等于接通被玩家切断的馈线。具体组合只有在内容明确列出合成方式时才能同时写相关通道，复杂度合格本身不证明兼容。

## 单一消费路径

MOD-RUNTIME-OWNERSHIP · DECIDED。

| 消费者 | 从编译结果读取什么 | 禁止建立的第二路径 |
|---|---|---|
| 配装与Ready校验 | 当前槽位是否允许、合法目录与精确禁用原因 | UI隐藏Secondary但服务器仍允许携带/使用 |
| 攻击与伤害结算 | 动作提交时的来源实例/固定槽、已编译Stat修正 | `if weekly`的额外伤害、伤害事件再次翻倍 |
| 工具/补给事务 | 按动作、实例类别和ResourceKind解析的实际成本与供给模式 | 先扣再每帧补满、反复生成补给包、客户端无限库存 |
| 设施与环境模拟 | 设备可用性、作用区、动态阶段及权威Tick | 每台炮塔各自随机风暴、用渲染帧或音频长度推进阶段 |
| 网络、存档、回放与战报 | 同一快照引用、当前状态和已提交事实 | 重连按当前活动重编译、回放重新扣费、统计制造资源 |

每Tick先提交到期的环境阶段转换，再按既有稳定命令顺序验证动作及资源，最后发布事实。处于风暴开始Tick的炮塔新开火因停机被拒绝；上一Tick已提交的弹体继续结算。设备恢复按正常前兆重新获得开火资格，不补发被拒绝的动作。玩家主机、本地单人、远端玩家和Bot走同一命令验证，无主机直写捷径。

有限成本使用`Consume`，已公布无限工具模式使用`WaiveUseCost`，供给来源使用`FiniteStock / InexhaustibleSource`。这些是同一事务求值器的明确策略，不是独立经济。实际支出、实际补入和免除原因分别记账；零支出不生成退款或“消耗资源后回收”事件，免费供给不写回收记录和账号货币。具体玩家语义由[ECO-MODIFIER-RESOURCE-POLICY](../玩法/资源回收额度与公共物资.md)拥有。

## 必须能表达的四个样例

MOD-RUNTIME-EXAMPLES · 所有者要求的能力范围；具体合同受托，未实现。

| 样例 | 类型化操作与作用域 | 关键边界 |
|---|---|---|
| 电磁风暴 | 已登记Zone中的易受干扰设备，定时可用性阶段与已声明屏蔽条件 | 阶段改变可用性，不改库存/阵营；同类敌我设备同结果；内容规则引用环境目录 |
| Primary伤害×2且无Secondary | Primary来源伤害倍率2.0，加Secondary槽禁用，作为一个完整Bundle原子验证 | 禁用槽在Run内为空，保存配装预设不被永久删除；无合法Primary则Ready拒绝；近战、Tool、Utility、重资产不因持有人有Primary而增伤 |
| 工具无限使用 | 对批准工具清单的自身使用/部署/射击资源成本执行WaiveUseCost | 保留动作、冷却、可用性、部署数量与目标验证；非工具材料不免除；破损不自动治愈 |
| Energy充能端口无限供能 | 指定固定端口的供应模式为InexhaustibleSource，接收方必须为Energy枪 | 来源不耗尽，枪容量仍有限；接入、供电和补给动作正常；不是任意资源生产口 |

攻击来源在动作提交时固定，不能靠切槽改变在途弹体倍率；同一伤害事实不再次套用规则。合法的后续效果继续按既有因果链与明示来源处理，不因为玩家名下拥有强化枪就扩大作用域。Secondary禁用时该槽的Ammo权益不能转换到Primary；既有双路包可保留其未使用余额给其他合法接收者，但本配置没有Secondary接收者时不会自动变成Primary资源。

工具无限资源不意味着无限并发：批准清单必须有明确同时部署数、持续效果预算、有限动作频率与失败反馈。达到已公开部署上限时先拒绝新部署，不暗删已存在设备；零时间/零成本/零状态推进的循环在编译时拒绝。消耗已免除的工具资源不能被转交、拆解或退款为有限资源。环境停机优先于可使用性，免成本不能使停机设备继续攻击。

## 扩展强化能力

MOD-RUNTIME-EXTENDED-CAPABILITIES · 受托方向，具体处理器未实现。

[玩家与敌人强化候选](../内容/活动/玩家与敌人强化修改器候选.md)需要的能力分为目标/部位过滤、动作时序、有限弹道派生、限时防护/协作效果、已验证敌人Profile与有限来源。这些在现有Damage/Effect/Action、AI与Encounter消费者中实现，仍通过本文同一编译结果绑定，不创建Isaac模式、DRG模式或按候选ID散落的事件分支。每个处理器声明读写集、状态Owner、提交阶段、能力版本和有界输出；条件只能引用当前消费者合法取得的事实。

内容编译阶段计算双联/裂片/链击/反射的组合输出界限、效果因果环与合法目标数，检查敌人变体所需动作、部位、导航和前兆资产。没有该能力或组合超出已证明的预算就拒绝发布，不能动态删部分弹体/伤害。受击、死亡和目标完成的派生Effect各自记录已消费资格，恢复不再触发；携幼体等新增实体先在任务源账预留有限集合，不绕过EncounterDirectorLedger。

动作时序修正必须同步动作阶段、Commit、冷却及表现；不改变60Hz timebase，不能只加速动画。新的运动/能力轮换使用现有权威Tick与局部状态，不能创建第二套全局时间。仅有schema可表达而没有处理器/内容验证的条目仍是缺实现候选，控制面不得宣称可启用。

## 状态、版本与恢复

MOD-RUNTIME-RECOVERY · DECIDED。

不可变规则进入RunManifest引用的完整快照，动态阶段进入StateSnapshot/Journal，资源事实仍由OperationResourceLedger和设备状态唯一拥有。恢复在隔离世界校验包、规则hash、阶段Tick、实例目标、部署归属及资源模式一致后切换；迁移冻结期间SimulationTime不前进。不能以活动当前Revision重新初始化相位、端口或工具。

旧包缺失或不兼容时明确拒绝恢复并保留原存档，不静默转普通规则，也不凭空构造兼容设备。已发布Run所需的包保留/迁移遵循内容版本政策；没有已发布持久化约束时不维护两套旧运行时。活动暂停/到期/目录回滚仅影响新Run；严重事故仍遵循发布前已经声明的HardStop政策。

## 最小实现顺序与验收

MOD-RUNTIME-ACCEPTANCE · TEST NOT RUN。

先完成M0至M3基础命令、设施和恢复路径；M4用无活动服务的本地配置验证地点环境；M4b加入完整Bundle编译和趣味资源例外。首先用Primary×2/禁Secondary与有限/无限端口证明编译结果被现有消费者真正使用，再验证风暴相位与无限工具并发。已有低层政策在对应系统首次实现时保留此真实消费者，不为所有未来修正器一次性造通用编辑器。M5/M6才接活动目录与实际发布。

| 测试 | 必须证明的结果 |
|---|---|
| 同一Bundle分别作为每日、每周与本地特殊合同加载 | 除排期/奖励元数据外玩法编译结果一致；普通环境无Event也正常 |
| 固定Primary来源一次合法命中，倍率1与2对照 | 在同一Stat阶段翻倍且只执行一次；切槽/在途弹体/重复事件不改变结果；其他来源不增伤 |
| 禁用Secondary的键鼠/控制器/伪造命令与恢复 | 槽位为空、切换跳过、使用被权威拒绝；结束后普通配装预设仍在；补给不转槽 |
| 有限/无限工具同一动作对照 | 仅实际Tool使用成本不同；冷却、阻挡、供电、有效目标和部署上限相同；不生成退款或资源回收 |
| 两人同时接端口、满枪、半满、取消与断电 | 每次合法提交只补真实缺量；有限模式扣对应供给，无限模式不耗来源；无过量、重复补入或非Energy收益 |
| 风暴开始/恢复与炮塔开火/交互同Tick | 全端一致阶段与明确动作结果，已提交弹体持续；恢复无积压突发，已支付结果不丢失 |
| 风暴 + 无限工具；轮换供电 + 无限端口 | 无限不越过设备停机/断电；安全路线成立，重复供给不产Credits |
| 重复ID、倍率越界、缺目标/能力、互斥安保/供电、无端口地图 | 准入时明确拒绝并定位规则；不静默去掉Modifier或临时补生成设施 |
| 重连、迟加入、Host Migration、检查点与目录回滚 | 同一快照和资源模式、阶段进度、部署数量；无重抽、重置库存或重复奖励 |
| 无限工具最坏合法持续输出 | 代表性Host/Deck负载与网络预算通过；失败修实现或公开内容准入，不能运行中丢弃合法效果 |

验收还覆盖每份准入任务的单人/四人、五档难度、Bot、包锁及可访问性。当前只有文档结构检查；不能称架构已通过运行验证，也不新增Unity实现授权。
