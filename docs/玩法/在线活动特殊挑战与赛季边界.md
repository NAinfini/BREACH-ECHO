# 在线活动、特殊挑战与赛季边界

## 玩家承诺

LIVEOPS-001 · 已确认产品方向。

特殊活动让熟悉的Operation提出一次清楚的新问题，而不是用更高血量和更高奖励假装新内容。玩家在任务板上先看见所有规则变化、禁止槽位、强化对象、敌群变化、额外风险、奖励、剩余时间和Mod资格，再决定配装、匹配或忽略活动。普通八Offer永远可用；活动不是登录义务。

活动继续使用同一条`选择合同 → 匹配/建房 → 配装 → Ready → Operation → 战报 → 领取`流程。它不建立第二套角色、战斗、资源、任务、存档或匹配系统。

## 四种活动节奏

LIVEOPS-002 · 已确认方向 / 节奏待测。

| 层级 | 玩家看到什么 | 设计用途 | 默认边界 |
|---|---|---|---|
| 每日信号 | 一份短周期特殊合同或一个轻量Modifier组合 | 给当天任务板一个新配装题 | 无连续登录奖励、无独占内容；错过不影响赛季理解 |
| 每周指令 | 三份可按任意顺序完成的合同组合 | 要求队伍在不同任务中调整装备与路线 | 进度按账号保存；不要求连续三天上线 |
| 每月战役 | 一个主题、数个活动合同与可选社区目标 | 展示新敌人、武器、设施或剧情档案 | 不自动改写正史；永久世界变化必须随版本明确发布 |
| 临时行动 | 运营手动启动的周末、纪念、补偿或实验合同 | 快速回应社区、测试组合或庆祝节点 | 只能使用已验证内容；可随时暂停新Run并回滚 |

具体刷新时刻、持续天数、奖励量和同时展示数量均为TEST。UTC是服务端唯一排期基准，UI按玩家本地时间显示绝对截止时间与剩余时长。

## 任务板与匹配

LIVEOPS-003 · DECIDED。

`MissionBoard`保留普通八Offer，并增加“特殊行动”区域。活动合同拥有独立`EventOfferID`，可引用某个现有任务模板或受验证的新任务包，再叠加一个Modifier Bundle。快速匹配必须让玩家明确勾选普通合同、活动合同或两者，不能为了缩短队列把玩家暗送进限制装备的活动。

房间卡必须显示：活动名称和Revision、任务、难度、全部Modifier及其互相作用、允许/禁止的装备、奖励差异、结束时间、是否允许Mod、所需ContentPackage和预计下载。任何承重字段变化都会清除Ready。Run锁定后活动到期不踢人；成功结算仍按锁定规则。

## Modifier合同

LIVEOPS-004 · DECIDED。

Modifier只能改变已公开声明的规则面：敌群组成与来源预算、装备合法性与性能倍率、资源供给、设施初态与交互成本、环境条件、目标附加约束、撤离条件及奖励。每个Modifier必须定义：

- 稳定ID、版本、玩家名称、简短说明和完整详情；
- 正面效果、负面效果和它服务的玩法问题；
- 可修改字段、参数合法范围和最终取整顺序；
- 兼容Tag、互斥Tag、所需Capability和复杂度成本；
- 对单人、四人、五档难度、Bot、迟加入、断线恢复和Mod局的规则；
- 对ThreatCost、ActiveSimulationCost、远程/重型硬顶、资源账本和奖励的影响；
- 结算、回放、战报和可访问性文案；
- 正常、边界、失败和回滚测试。

Modifier Bundle按固定顺序编译：`基础任务 → 难度 → 活动敌群 → 装备合法性 → 资源/设施 → 环境 → 目标附加条件 → 奖励`。同一字段出现两个不允许叠加的写入就拒绝发布，不采用“最后一个悄悄覆盖”。

基础任务包含普通地点已有的环境定义，不能在活动环境步骤中静默覆盖或重复施加。环境与活动共用[Modifier编译及运行合同](../技术/关卡与活动修改器编译及运行合同.md)；无Event的普通Run也冻结同一规则快照。每日/每周/临时只是排期入口，不能各写一套伤害或资源处理器。环境内容由[关卡环境候选](../内容/设施与资源/关卡环境修正器候选与验证.md)拥有，玩家强化、敌人强化和混合趣味规则由[活动候选](../内容/活动/特殊活动修改器候选库.md)拥有。

LIVEOPS-FUN-MODIFIERS · 所有者明确要求支持玩家强化、敌人强化及趣味活动，并举例Primary伤害×2且禁用Secondary、工具无限使用、Energy充能端口无限供能。上述方向进入候选；无限工具和端口允许为纯有利效果，不强制每条都有惩罚。具体成本/供給边界由[ECO-MODIFIER-RESOURCE-POLICY](资源回收额度与公共物资.md)拥有。强化可以夸张，但不能依靠无法识别的敌人攻击、无限实体、无推进效果环或重复奖励成立；不把“候选可表达”写成已实现或已批准公开活动。

## 复杂度与公平

LIVEOPS-005 · DIRECTION / TEST。

每个Modifier有复杂度成本。标准活动初值建议总成本不超过4，极限挑战不超过6；这是可测试的作者预算，不是代码只能装四个Modifier。单条活动卡必须让陌生玩家在十秒内复述主要改变和最大代价，否则组合过密，应删减。

装备限制必须给所有账号一条合法路径。若活动禁用Secondary并强化Primary，至少一把基础可用Primary必须符合规则；不能要求未拥有的DLC或限时武器。伤害翻倍等夸张规则允许出现在清楚标记的特殊挑战中，但必须配套真正改变决策的代价，且不能进入普通任务或永久平衡。

敌人变化继续受全局在场成本、远程和重型硬顶约束。“无重型、更多小型”只把预算换成已注册轻型单位，不绕过性能上限，也不无限生成。所有新增来源仍须是任务卡公开的Alarm、主节点或活动来源，不把普通休眠敌人改成无限巡逻。

## 奖励与回流边界

LIVEOPS-006 · 已确认方向 / 数值待测。

首次完成、重复完成、每周组合和社区里程碑分别记账。奖励可以是Credits、外观、称号、壁垒展示物、成就、档案或非战力横向解锁；重复刷取必须有公开上限或递减，但不能隐藏降奖。活动不出售战力，不以连续登录Streak放大奖励，也不把关键故事、武器、敌人或任务永久锁在错过即失去的窗口。

战报明确列出每个Modifier如何改变敌群、配装、资源和最终倍率。奖励领取使用唯一`RewardClaimID`幂等提交；网络重试、Host Migration或重复上传不得多发。PvE活动不建设战斗反作弊，但服务仍拒绝未知EventRevision、非法奖励ID、超出schema范围的数值和重复Claim。

每个活动显式声明Mod政策。默认官方活动奖励要求使用活动锁定的官方Content Graph；运营可以为社区活动声明`允许安全Mod包`并接受房主可信结果。玩家始终可以在私人房复制同一Modifier组合自由游玩，即使该组合不产生官方活动奖励。这个边界用于保证奖励和规则含义一致，不扫描玩家进程、不封禁战斗行为，也不阻止私人PvE修改。

## 赛季轨道

LIVEOPS-007 · FUTURE / COMMERCIAL OPEN。

赛季可以组织一个较长主题、活动合集、社区目标和`ProgressionTrack`。轨道只消费经确认的游戏事件，例如完成某类活动、发现指定档案或达成团队条件；不读取私人聊天，不按伤害排名，也不鼓励抢击杀。

当前只准备免费、付费都能使用的中性轨道数据和领取流程。是否存在Season Pass、是否收费、是否双轨、价格和旧奖励回归方式仍须所有者在真实内容产能和商业方案出现后批准。当前推荐即使以后收费，也只出售可明确预览的外观权益，不出售随机奖励、武器强度或任务访问。

## 内容持续扩充

LIVEOPS-008 · CANON DIRECTION。

新武器、敌人、任务、设施和Modifier都以稳定ID、版本、Tag、Capability与ContentPackage进入Registry。活动模板按Tag寻找候选，发布时解析并冻结精确内容列表。新增内容不得自动加入所有旧活动；作者必须重跑兼容性、PCG可解性、性能和配装检查后发布新的EventRevision。

活动是让新内容被看见的入口，不是掩盖内容不足的滤镜。一个新武器若只是旧枪伤害高10%，一个新敌人若只是多50%生命，一个月活动若只是奖励翻倍，都不算有价值的持续内容。

## 玩家体验验收

首轮任务绑定与组合准入由[修改器任务映射](../内容/任务/修改器任务映射与组合准入.md)拥有；复杂度够低不等于自动兼容。普通地点条件一并计账，Ready冻结语义槽与参数，生成后绑定实际实体；缺能力或坏图必须拒绝，不能为发布活动静默退回普通规则。

LIVEOPS-009 · TEST NOT RUN。

至少验证：玩家能区分普通与活动合同；十秒内复述组合；活动规则与实际Run完全一致；活动到期不终止已锁Run；禁用槽位不会产生无合法配装；单人与四人都能完成；迟加入能看到并接受规则；服务中断时不会显示幽灵活动或丢已锁快照；重复领取不多发；无色觉和静音玩家能读懂所有变化。还需测活动是否分裂匹配、是否产生签到焦虑、是否让一种装备成为唯一答案。当前全部NOT RUN。
