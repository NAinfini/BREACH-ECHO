# 验收矩阵与证据要求

所有游戏测试状态：**NOT RUN**。下列是验收合同，不是通过报告。每份结果记录commit/build、实际命令、seed、设备/驱动、分辨率/设置、输入方式、人数、网络条件、原始日志及观察者。设计人员的自评不能代替陌生玩家观察。

| ID | 必须证明 | 样本/条件 | 否决条件 |
|---|---|---|---|
| A-BOOT | 干净环境可构建并运行 | 一个授权干净环境+Windows standalone | 隐藏手工场景引用、缺文件、编译错误或秘密/许可资源泄露 |
| A-COMBAT | 无升级时动作响应、两枪有不同理由、取消不刷资源 | 12人裸战斗30min；30/60/120渲染FPS；键鼠/控制器 | 输入/帧率改变资源结果；≥50%不愿继续；取消复制弹药 |
| A-INPUT | 完整菜单/战斗控制器可操作，FPS/TPS不改变命中规则 | 8新手，目标≥7/8独立完成核心操作；左右持枪及TPS遮挡 | 控制器焦点陷阱、必需动作无绑定、镜头穿墙命中、依赖宏 |
| A-ONBOARDING | 首次启动到短合同能教会核心循环且不替玩家作弊 | 8名无文档经验新手；键鼠/控制器；单人/合作 | 需要口头教学、首次致命测试前未引入、靠长文或暗送资源通过 |
| A-FRONTEND | 启动、离线/在线、房间、设置、结算与错误恢复全程可返回 | 8名新手；720p–4K、16:10/21:9/32:9、200%文字 | 无焦点死页、静默改难度/包、误退Run、半激活Mod、错误无下一步 |
| A-SOLO | 所有主任务可无Bot顺序完成 | 每任务模板×每难度的可达性检查，代表seed人类走读 | 强制多人同时开关、职业钥匙、合法关键Cell耗尽后无解释死局 |
| A-ECONOMY | 物资守恒，Support/废料/奖励去重 | 全Cart合法组合；同时提交、重传、满仓、断线、OOB | 双重消费/奖励、负数、关键任务物丢失、稳定kill→ammo无限循环 |
| A-SURVIVAL | 倒地/搬运/自救/Wipe正确且公平 | 同帧死亡击杀、多Revive、无目标炮塔、全部Downed | 合法已发自救被任意截断；无恢复循环永久拖延；死亡洗资源 |
| A-NET | 所有玩家走同一命令通路，late join看到完整当前态 | 2/4人，0/80/150/250ms RTT，0/2/5% loss，乱序/重复 | Host本地绕验证、过期epoch写入、消息重复造物、delta永久无法解码 |
| A-RECOVERY | 唯一新主、认证状态完整、无法恢复时明确挂起 | 至少20次功能故障注入；覆盖Steam/协调器单边分区和进程睡眠 | 任意双主、认证事务重复/遗漏、缺hash偷偷升级；RPO/恢复时间超目标须解释重测 |
| A-PCG | 可达、资源可解、信息足够且有可感知变化 | ≥1000自动seed约束测试+20seed人工排序+重复队伍 | 软锁率非零；>15%明显无聊/不公平；只是目标换名字 |
| A-AI | AI只用合法感知/记忆/通信，导航和降频不改规则 | 固定Seed；封门/失明/断讯/部位破坏；100/500/1000轻量敌人 | 隔墙全知、无Source召怪、Stuck传送、LOD/Think频率重置动作或冷却 |
| A-CAMERA | FPS/TPS相同权威结果，摄像机和动画阶段不制造第二套玩法 | 30/60/120/144 FPS；近墙、换肩、取消、IK、迁移与LOD | 穿墙窥视命中、动画事件重复扣费/发伤、取消复制弹药、前兆被LOD删除 |
| A-BOTS | 0–3可选Bot同规则、能跟随/战斗/救人、不偷资源 | 门、梯/窄路、搬人、迁移、真人替换、战斗30min | 传送穿锁门、无限弹、无人授权花Cell/支援、真人继承多份物资 |
| A-MODS | 一次同步安全包、拒绝不支持能力、旧hash明确失败 | 新玩家操作+恶意包矩阵+断网/磁盘满/更新竞态 | 任意代码/路径执行、半激活、定义冲突静默覆盖、官方包特殊绕验证 |
| A-REPLAY | 权威统计正确，临时回放不拖垮战斗且退出清理 | 50min四人密集任务、迁移、低磁盘、异常关闭再启动 | 归因假阳性、重复统计、语音录制、未经选择留历史、超预算且隐瞒 |
| A-NARRATIVE | 公共事实不靠秘密解锁，四人清晰且不自相矛盾 | 故事因果走读、三次重复合同对白测试；所有者审阅后独立盲审 | 个人主线/时间复位偷渡、死人复活解释Wipe、人物变职业钥匙 |
| A-ASSETS | 许可/来源可追溯、URP/骨架/LOD有效 | 每资产登记；人物移动/转向/瞄准/受击/倒地/携带动画矩阵 | 无来源许可、公开泄露原资产、坏权重、缺碰撞/LOD、AI输出当直接成品 |
| A-PERF | 真实Gameplay不丢结果地满足目标 | Deck真机30min thermal soak，代表四人Host与Client；PC基准 | Deck目标为99%帧≤16.67ms；没有实测不能宣称达标或Verified；超预算按风险流程处理 |
| A-ACCESS | 关键危险至少两种可感通道，全部关键文字/焦点可读 | 无声、色觉模拟、减少运动/闪光、字幕缩放、重绑定 | 只靠颜色/音频解题；高优先提示被装饰淹没；关键菜单不可达 |
| A-RELEASE | Steam构建、内容权限、存档迁移、demo声明及崩溃恢复 | 实际伙伴账号/构建、合法审查、受控多人测试 | 许可/隐私/AI披露未清楚、未批准花费/日期、把原型宣传成完整产品 |

## 指标解释

比例的分母与排除条件必须预先写明；小样本只作早期否决，不是统计显著市场证明。性能同时报P50/P95/P99和最差段、CPU/GPU瓶颈、Host/Client差异；平均FPS不能掩盖尾部卡顿。网络报告bytes/s、packet/s、快照大小、恢复证书延迟与实际RPO；只报ping不够。

失败时保留原日志，修正原因后以新build重测。设计改变需记录新的阈值理由，不把未过标准悄悄降低。源风险登记里的Lab/未来Descent指标保留为未来测试，不因不在首发而伪标通过。
