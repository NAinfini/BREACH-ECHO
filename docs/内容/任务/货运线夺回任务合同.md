# 货运线夺回：完整任务合同

## 合同身份与玩家承诺

环境与特殊活动的L区绑定见[修改器任务映射](修改器任务映射与组合准入.md)，不改变自主货运、故障数量和隔离/全吞吐承诺；未默认加入基础配置。

FREIGHT-CONTRACT-001 · 受托决定 / 尚未测试。

| 字段 | 当前合同 |
|---|---|
| DefinitionID / 版本 | `logistics/freight-corridor-recovery` / `0.1.0-test` |
| 内容身份 | Primary；Operation；Industrial Route Recovery |
| 合法区域 / Site | 首轮使用限界探索区的仓储、换流或交通设施；无限探索区变体可增加高价值RecoveryRecord/字形并减少固定防御 |
| 目标时长 | 标准长局40–50分钟，采用FREIGHT-STANDARD-LONG；不减慢货物或强制跟车凑时长 |
| 交战合同 | **条件升级**。低特征隔离方案不启用任务增援；全吞吐方案能在接收窗口内回收目标批次及其附属批次，但产生区域级机械刺激和有限迁入 |
| 任务板公开事实 | 回收对象是大宗货批；小队负责鉴别、清路、恢复工业物流和确认接收，不徒手搬运；全吞吐会扩大激活范围 |
| 主要产出 | 货批回收凭据、紧缺材料/设备登记、物流诊断和Credits依据；大宗货物由设施自动交接，不进入玩家背包 |
| Point of No Return | 在路线整备完成后提交“隔离转运”或“全吞吐转运”；选择锁定货物完整度、刺激与后续故障集 |

本任务的核心不是护送慢车，而是让四人像一支危险设施抢修队：先看懂货物要走的真实路径，把两种不同的故障在前方处理好，再选择用更多准备换安静，还是用噪声与敌情换完整、高价值回收。货物不能比玩家走得更慢，也不能要求队伍贴着它站圈。

## 货批、路线与价值模型

FREIGHT-CONTRACT-002 · DECIDED。

每局选择一个作者定义的`FreightBatchDefinition`，声明货物类别、完整回收价值、可拆解价值、危险属性、兼容装卸设备、不能承受的环境和接收方式。现场服务器、库存铭牌和设备诊断可以形成普通RecoveryRecord，但大宗货批、人造太阳燃料、关键冷却介质、控制部件等战略物资使用独立任务凭据，不当作可在局内花掉的LogisticsQuota。

任务只提供两种有实际区别的回收计划：

- **隔离转运：** 先恢复声振隔离、分段门和低速牵引控制。准备路线更长，需要一个额外前向设备动作；货物在玩家处理下一段时并行移动，不制造等待。任务必要机械动作使用FREIGHT-INTERACTION-MAP的局部刺激，完整保全目标批次，但接收窗口不足以处理相邻附属批次。
- **全吞吐转运：** 跳过隔离动作并启用高功率装卸/磁轨，在接收窗口内同时登记目标批次和一批作者声明的附属货物，因而总回收价值更高；机械冲击会产生区域级刺激，使列出的运输Zone进入`Stirring`并启用一份有限来源。全吞吐不自动提高单件完整度，工业异常反而可能让部分货物降级。

若现场证据显示完整设备已经不可安全运输，玩家必须在Commit前完成**现场标准化拆解**，再从隔离或全吞吐中选择运输方式。自动拆解线把货物转为较低价值、低危险标准货，移除一项货物专属环境要求，但不会凭空生成更多LogisticsQuota或RecoveryRecord。它是可理解的降级预处理，不是隐藏的第三条最优路线。

## Beat Graph、故障槽与提交点

FREIGHT-CONTRACT-003 · DECIDED。

`从目标批次上游的检修闸插入 → 读取货单并定位目标批次 → 沿尚未启用的货运方向通过平行人员通道持续向前 → 鉴别货物与路线状态 → 从不同类别中处理两个前向故障槽 → 封闭/控制已知运输入口 → 预览并提交隔离或全吞吐方案 → 货批分段自动前送，队伍沿同方向处理一次动态异常 → 接收闸确认交接 → 从前方人员闸撤离`。

生成器从下列故障类别中选择两个，且不得重复类别：

| 故障类别 | 玩家动词 | WorldOutput | 禁止退化 |
|---|---|---|---|
| 路线障碍 | 用吊车/转盘重排货柜，或用工业切割/维护旁路清障 | Cargo port实体畅通，掩体与敌人路径改变 | 不允许只对障碍物打血条 |
| 轨道与转向 | 现场拨动机械道岔并验证终点，或恢复局部牵引电力 | 货运路径、人员捷径和可用出口改变 | 不允许三个终端按顺序读条 |
| 环境完整性 | 修补压力段、恢复冷却或隔离危险货柜 | 对应区可安全通过，雾/热/压力和货值改变 | 不允许靠不可见倒计时猜失败 |
| 装卸设备 | 修复机械臂、升降台或装载机的不同实体模块 | 批次进入下一运输层，打开新前方通道 | 不做慢速NPC护送 |
| 身份与货单 | 找本地货运凭证、重映射目标批次或强制覆盖 | 设备接受正确货批，错误路线被锁止 | 权限不能只等于更长按键 |

路线整备、回收计划、每项故障、每段货批交接和最终接收各自使用幂等提交。货批只在一段目标路径验证畅通后移动；移动是设施状态，不依赖玩家站在其旁边。若玩家先去前方处理下一故障，货批在后台按确定性速度前送；若玩家与货批同时到达，移动速度不得低于未携带玩家的正常跑速。货批不会碾压玩家、把任务物推出导航域或堵死唯一人员路。

动态异常只允许从已知货物属性和已选方案产生，例如全吞吐使过热制动器需要一次旁路切换，或隔离转运暴露一处先前无法进入的维护断路器。它必须与前两个故障类别不同、位于玩家前进方向，并在发生前给现场预兆；不能为了凑时长随机坏第三台同样设备。

## 空间语法与前向流动

FREIGHT-CONTRACT-004 · DECIDED。

拓扑为两条并行但交错的脊线：货运脊线负责大宗资产，人员维护线让玩家提前到达下一工位并从侧面控制威胁。标准图为：

`L00上游检修插入 → L01货单控制 → L02目标仓 → {L03货运障碍 / L03M人员维护绕路} → L04路线切换 → L05方案配置与准备区 → L06滚动货运段 → L07壁垒方向接收确认 → L08前方撤离`。

玩家从目标仓上游的检修侧进入，通过L01获得目标批次位置；随后实际前进使用与货运线平行的人员路线，货物也从L02向壁垒接收方向移动，因此不会先走到最远仓库再原路押车。L02至L07始终沿接收方向形成新的门、升降台、检修通路或货柜开口；每次货物移动都开放下一段世界。L03M在障碍后方重接，L05可选支线在L06前重接，L08不返回L00。

必需Cluster Tags为`insertion-lock、terminal-hall、storage-grid、cargo-spine、material-handler、route-switch、receiving-bay、extraction-bay`；可选为`maintenance-loop、security-control、coolant-works、glyph-branch`。至少两个Cargo port连续形成可验证大宗路线，同时存在不被货物占满的Personnel/Maintenance路径。门宽、转盘、吊车与货柜包围体必须按三种携带尺寸和敌人导航验证。

节奏为“快速识别 → 仓储潜行/清场 → 第一次设施问题 → 短缓冲与价值决定 → 第二次设施问题 → 回收计划Commit → 滚动高压或安静并行执行 → 接收释放 → 撤离”。Commit前必须有一个可部署重资产、分配Resource Pack和预览入口的准备空间；它不保证免费补给。

## 权限、设施系统与耦合

FREIGHT-CONTRACT-005 · DECIDED。

起始旧制身份允许读取公开货单摘要和操作普通人员门，但不允许启动货运。货运权限必须通过以下至少两条Seed真实路径恢复：找到装卸主管留下的本地凭证；在维护线完成协议重映射；或强制覆盖货运控制并触发L01、L02及相邻安保域的`SecurityIncident`。强制覆盖改变门、旧防御和区域警报，后续安控接管可停广播但不能撤销已经唤醒的敌人。

每局固定运输/物料处理、配电、门/隔离、通信/货单四套系统；再从安保、冷却与工业危险中选择一至两套。至少两项耦合必须成立：

1. 有限可选电力在声振隔离、货运牵引、安保闸和冷却之间竞争；最低标准化拆解路线有固定保底电源。
2. 封闭一条Cargo Ingress能减少全吞吐来源方向，但会迫使货物使用较慢的转盘路线或失去一部分完整货值。
3. 恢复吊车既能清障，也会把货柜变成新掩体/敌人封路；位置变化对玩家和AI使用同一世界状态。
4. 保留完整批次需要冷却或压力稳定；把该资源给任务就不能同时给Energy充电端口、炮塔或可选资源仓。
5. 货单通信恢复提供正确目标和接收确认，但不会解锁所有安保或实时敌人位置。

所有配置通过轨道、货柜、门、吊车、照明、压力、炮塔阵营、地图快照和货物位置真实表现。一个中央终端不能远程完成两个故障槽；终端负责信息与Commit，实体装置负责改变空间。

## 刺激、敌人和有限来源

FREIGHT-CONTRACT-006 · TEST。

四人Standard功能短图初始目标为22–30敌人角色点，分成5–7个传播群；首轮使用逐能体和压射体，基础战斗通过后的设施对照可加入一台哨戒炮塔，库存见首轮支线合同；维护机仅保留后续独立验证，不随机替入此对照。初始名单生成后固定有限。货运设备每段只产生一次AttackRoot/机械刺激，不按每个轮子重复叠加声音。

五档初始实体数、完整角色池、重型/远程比例、设施上限和四人来源总额见[首轮任务难度、敌人和配装用途矩阵](首轮任务难度敌人与配装矩阵.md)。本文的22–30点是Standard功能短图基准；隔离转运在任何难度都不能把更多初始敌人伪装成事件新增波次。

隔离转运的必要动作采用下表局部声学且不启用任务来源；作者仍须检查累计传播与实体路径，不能直接宣称可维持整体安静；仍存活且靠近Cargo路径的休眠体可能被真实机械声音唤醒。全吞吐Commit产生区域级刺激，作用于L05、L06、L07及合同列出的相邻运输Zone，并开启一份`FreightThroughputSource`。功能短图的来源基础总预算12角色点，标准长局取上方配置；再应用TP-DIFFICULTY-COMBAT的难度与有效Seat倍率；预算由最多两个实体Cargo Ingress共享，不是每个入口各一份。

玩家在Commit前封闭的入口从来源图移除且不会把同额敌人平移到背后。来源只在货运经过该区且入口开放时可生成，前兆不少于2秒；货批进入L07接收闸、入口被封或预算耗尽即停止新迁入。现存Active敌人继续追杀。若全吞吐压力被事前清场和封口大幅削弱，这是玩家挣得的结果，不补一波“保证刺激”。
