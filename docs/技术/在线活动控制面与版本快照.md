# 在线活动控制面、版本快照与持续内容合同

## 边界

LIVEOPS-TECH-001 · 已确认方向 / 尚未实现。

Live Operations控制面拥有活动草稿、验证、排期、发布、即时激活、暂停新匹配、延长、结束、回滚、查询和审计。它不运行对局，不成为每Tick依赖，不直接写Simulation，不提供任意脚本执行，也不替代Steam身份、Lobby、内容分发或Gameplay Host。

Gameplay Host只消费一份已认证、schema合法、版本兼容的`LiveCatalogSnapshot`。本地Solo可以使用随构建附带的活动样例和离线默认目录，但不能伪装领取在线活动奖励。

## 最小数据模型

LIVEOPS-TECH-002 · DELEGATED DESIGN。

| 类型 | 必需字段 | 所有权与不变量 |
|---|---|---|
| `EventDefinition` | eventID、revision、名称键、状态、优先级、显示窗、参与窗、offer模板、modifierBundleID、rewardPolicyID、requiredPackages、minimumBuild、modPolicy | 发布后Revision不可变；修改产生新Revision |
| `ScheduleWindow` | startAtUTC、endAtUTC、gracePolicy | 只用UTC比较；客户端本地化显示 |
| `ModifierDefinition` | modifierID、version、allowedFields、parameterSchema、compatibilityTags、conflictTags、complexityCost、capabilities | 只引用已编译处理器；禁止表达式/远程脚本 |
| `ModifierBundle` | bundleID、revision、有序modifier引用、解析结果hash | 编译时拒绝冲突写入、缺Capability和越界参数 |
| `LiveCatalogSnapshot` | catalogRevision、issuedAt、expiresAt、活动列表、完整hash、认证信息 | 客户端/Host只读取；过期策略明确 |
| `RunRulesSnapshot` | eventID/revision、offerID、ruleset/content/modifier hash、seed、rewardPolicy、lockedAt | Ready提交后不可变，进入存档与恢复 |
| `ProgressionTrackDefinition` | trackID、revision、时间规则、里程碑、reward引用、entitlementPolicyID可选 | Gameplay不解释价格；无付费字段也可运行 |
| `RewardClaim` | claimID、account、runID、event/track revision、milestone、resultCertificate | 唯一ID、认证、schema验证、幂等提交 |

ID不使用SteamID、Lobby ID或数据库自增行号作为Gameplay身份。平台账号映射只存在服务边界；内容身份来自BREACH Registry。

## 作者与运营状态流

LIVEOPS-TECH-003 · DECIDED。

活动状态为：`Draft → Validated → Scheduled或ReadyForManualStart → Active → PausedForNewRuns → Ended → Archived`。`RolledBack`是指向前一已发布CatalogRevision的控制操作，不修改历史Revision。

控制台提供：

1. 复制已有活动为草稿，选择已发布任务、Modifier、奖励和内容包。
2. 静态验证schema、时间窗、版本、依赖、冲突、复杂度、合法配装、五档预算和奖励上限。
3. 用固定Seed预览最终任务卡、RunRulesSnapshot和玩家可见文案。
4. 排期发布，或把验证通过的草稿标记为可即时启动。
5. Active期间查看新Run创建、完成、失败、Claim拒绝、客户端版本和错误率。
6. 随时暂停新Run、延长窗口、结束，或一键回滚到前一CatalogRevision。
7. 查看谁、何时、从哪个Revision执行了什么动作；审计记录不可从普通控制台删除。

“随时管理”指能即时切换已经验证的定义。新敌人、新武器、新任务逻辑或新Modifier处理器仍需要正常开发、构建、测试和发布，不能绕过客户端更新。

## 发布、缓存与故障

LIVEOPS-TECH-004 · DECIDED / PARAMETERS TEST。

发布使用原子CatalogRevision：先完整写入、验证并生成hash，再切换`activeRevision`。客户端定期拉取并在进入任务板、创建房间和Ready前刷新；具体轮询间隔由压测决定。推送通知可以加速刷新，但不能成为唯一正确性来源。

服务暂时不可用时：

- 已锁Run继续使用自己的RunRulesSnapshot并可恢复；
- 客户端可以在未过期的最后已知CatalogSnapshot上继续显示活动，但明确显示最后更新时间；
- 超过`expiresAt`后停止创建新的在线活动Run，普通八Offer和离线Solo继续；
- RewardClaim进入本地加密队列并按同一ClaimID重试，不先发奖励再祈祷服务接受；
- 无可验证Snapshot时不从本机时钟自行发明活动。

暂停活动默认只停止新Session创建和快速匹配；现有Lobby在Ready时重新检查。如果是安全或严重经济事故，运营可将Revision标为`HardStop`，此时Lobby不能开始，已在局内Run按公告政策完成、转为无活动奖励或挂起；三种策略必须在发布前定义，不能事故发生后临时改历史。

## 对局与结算一致性

LIVEOPS-TECH-005 · CANON DIRECTION。

Session创建时记录候选EventRevision，Ready提交时重新解析并冻结精确RunRulesSnapshot。所有Client在Loading前验证同一hash；不一致者明确刷新或拒绝加入。Host Migration把快照当作RunManifest的一部分恢复，新Host不能重新查询“当前活动”覆盖旧规则。

Gameplay Authority只提交事实结果，协调服务根据锁定RewardPolicy计算或验证Claim。PvE允许房主修改私人会话，不做瞄准、伤害或移动反作弊；服务仍执行身份认证、字段白名单、数值上限、事件状态、结果证书格式、Claim唯一性和速率保护。这些是数据完整性，不是竞技裁判。

EventDefinition的`modPolicy`决定官方奖励资格：可要求精确官方图，也可允许通过安全验证的Mod包。非合格内容图仍可在私人会话运行同一Modifier，但Claim明确返回“不具官方活动奖励资格”，不伪装网络错误，也不触发封禁。

## 新武器、敌人与内容版本

LIVEOPS-TECH-006 · CANON DIRECTION。

每次内容发布生成新的Content Registry版本。武器、敌人、任务、设施和Modifier处理器分别声明稳定ID、schema、Tag、Capability、依赖、替代关系和最低客户端版本。删除已发布ID必须提供明确迁移或保持旧包可恢复；不能把旧ID静默指向行为不同的新内容。

活动作者可以按Tag搜索内容，但发布器必须把查询结果解析成精确列表并写入Revision。内容后来增加时，旧活动不会自动吸入新枪或新敌人；运营确认兼容并发布新Revision后才生效。活动需要的新包由既有Package Lock和Steam Workshop/游戏构建分发路径取得，不建立第二套活动下载器。

## Season Pass准备而非承诺

LIVEOPS-TECH-007 · FUTURE SEAM。

`ProgressionTrack`、`Milestone`、`RewardDefinition`与`EntitlementPolicy`分离。免费轨道使用恒真Entitlement；未来若批准付费轨道，平台适配器把Steam Entitlement映射成服务侧资格，Gameplay和Save不直接保存SKU或价格。Reward Claim保存轨道Revision和领取结果，保证赛季结束、离线重试和迁移不会重复发放。

首发实现不得因为这个接缝提前建设商店、Premium货币、购买UI、退款逻辑或付费Track。只有OWNER商业批准、内容产能、平台条款、退款/地区/未成年人/隐私评审和玩家价值方案齐全后，才打开相关里程碑。

## 安全与权限

LIVEOPS-TECH-008 · DIRECTION。

运营控制台使用服务端角色权限和短期凭据；至少区分只读观察、活动编辑、发布/暂停、奖励政策和商业Entitlement管理。开发环境、预发布和正式环境使用不同配置与密钥。任何活动定义都不能包含C#、DLL、Luau源码、文件路径、URL回调或数据库查询。

敏感操作记录操作者、时间、旧Revision、新Revision、原因和结果。具体身份供应商、密钥托管和两人审批只在部署设计时决定；当前不虚构账户或云服务。

## 验证矩阵

LIVEOPS-TECH-009 · TEST NOT RUN。

最低自动测试覆盖：UTC边界、闰日、跨时区显示；同一事件并发发布；错误参数与冲突Modifier；最低版本与缺包；正常排期和即时启动；暂停、延长、结束、前一Revision回滚；活动到期时Lobby与Run；服务离线与缓存过期；四人hash不一致；迟加入；Host Migration；重复/乱序RewardClaim；新增内容前后旧活动精确列表不漂移；非法脚本字段拒绝；普通八Offer在活动服务故障时仍可用。

集成测试使用本地假控制面和可控时钟，不要求M0接入真实Steam或云账号。真实部署、容量、区域故障、告警、备份恢复、权限和成本必须在上线前另过Gate。当前全部NOT RUN。
