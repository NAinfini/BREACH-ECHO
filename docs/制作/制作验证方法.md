# 制作验证方法

本文件只负责如何验证任务价值，不制定第二套范围或日程。制作顺序由[实施交接](实施交接与制作入口.md)负责，内容边界由[产品范围](../产品/产品范围与首发合同.md)负责。没有可用工时和构建证据，不承诺30、90或180天交付。

## 任务是否值得重玩

PLAN-004 · TEST · 实验尚未运行。

使用同一套战斗内容比较三种体验：A为轻目标战斗；B增加设施操作、运输与路线后果；C在B上增加少量武器改装。随机或交叉平衡体验顺序，保持时长、敌人和资源条件可比较。

观察玩家是否自发选择再玩以及理由，而不只收满意度评分。候选判断条件：B比A多至少20个百分点参与者选择再玩，至少70%能复述设施选择的后果；C不得明显增加等待或误解。这些是待验证的实验条件，不是已通过结果，也不能由小样本推断销量。失败时分别检查等待、背答案、资源失衡和操作负担，不先增加奖励掩盖。

## 招募与观察

新手、合作核心玩家、陌生无语音队伍和无机器人单人分别记录；开发者与作者的数据另列。每次保存构建与内容版本、场景或种子、输入方式、设备、招募来源、观察与反证。

提问使用“刚才发生什么”“为什么这样做”“下次会怎么变”“愿意自己再开吗”。不先教玩家设计者期待的答案，也不把文档数量换算成开发进度。

## 开发测试数据与隐私

PLAN-007 · 研究方案；尚未采集真实玩家数据。

最小记录覆盖会话开始/结束、区域进入/离开、目标提交、运输与支援、资源转交、改装安装、重资产拾取/放下/耗尽、倒地/救援/失败、知识上传、断线与迁移。只记录伪名会话和席位、版本、动作类型、耗时及结果原因；不默认采集语音、聊天全文或平台秘密。

外测告知、同意与删除机制必须在采集前确定；30天保留期只是候选，不是已批准上线政策。开发测试数据不改变[玩家战报确认后删除](../玩法/任务战报与行动回放.md)的规则。

## 判断与停止条件

裸战斗不成立时，不扩任务、装备和作者工具。任务设施没有增加计划变化与复玩意愿时，重做对应任务动作，而不是靠更多剧情解释。只有实际性能剖析证明瓶颈，才扩大工程架构。

验收阈值及失败处置统一查阅[风险登记](风险登记与否决条件.md)与[验收矩阵](验收矩阵与证据要求.md)。文档结构验证不代替试玩；未执行的构建、性能与玩家测试必须继续标为未运行。
