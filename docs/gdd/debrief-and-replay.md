# 任务战报与行动回放

## 玩家目的与边界

让队伍在任务结束后看懂“发生了什么、为什么会变成这样、下一次能学到什么”，并用简化战术记录回看队伍路线与关键事件。详细团队/个人统计是核心，低体积本地回放是复盘入口；不制作电影级录像，不建立竞技排名，也不把合作任务变成抢击杀比赛。

RPL-001 · CANON/DIRECTION · 来源：SRC-USER-2026-09-05-DEBRIEF-AND-REPLAY；SRC-USER-2026-09-05-SIMPLIFIED-REPLAY-AND-STATS；SRC-USER-2026-09-05-DETAILED-STATS-LIGHTWEIGHT-LOCAL-REPLAY；SRC-USER-2026-09-05-POST-DEBRIEF-DISCARD。

每次Operation成功、失败或真正Wipe后都生成一份含详细统计的`DebriefSnapshot`和一份本地`SimplifiedReplayRecord`。二者只服务本局结束后的复盘：玩家可在结算阶段反复查看统计和简化回放，确认结束并返回Hub后即可删除，不进入永久行动档案。奖励提交不依赖玩家观看完动画，也不等待回放索引生成。

## 结算信息层级

RPL-002 · DECIDED · 来源：SRC-USER-2026-09-05-DELEGATED-DOCUMENT-FINALIZATION；授予决策权后采纳行为合同，数值/效果仍须TEST；原依据：来源：SRC-USER-2026-09-05-DEBRIEF-AND-REPLAY；game-design界面方法。

默认战报展示五层，完整武器/敌人拆分由玩家主动展开：

1. **任务结果：** 成功/失败、主目标、支线、难度、行动时长、带回奖励和未带回损失。
2. **行动摘要：** 以3至7个真实事件组成可点击时间线，例如首次接敌、目标改道、资源跌入危险区、重资产启用、队员倒地与救回、最终撤离或Wipe。
3. **团队数据总览：** 全队有效发射、命中率、总伤害、击杀、弱点命中、友伤、倒地、救援、潜行破坏次数、目标交互与探索发现。它在结算首页可见，不藏进高级分析页。
4. **团队资源账：** 弹药、医疗、工具、任务物资、重资产弹药和废料的带入、发现、消耗、遗失与带出。所有账目必须能由事务事件加总复核。
5. **成员贡献：** 每名玩家各自展示战斗、支援、目标、资源与探索贡献，不给全队排一个单一MVP。

底部固定提供`确认并返回壁垒`、`再来一局`、`观看回放`和`详细统计`。确认前提示“离开后本局战报与回放不会保留”；战报不能用不可跳过的逐项数字动画扣住玩家。

正式统计池按问题分类，而不是堆成一张宽表：

| 类别 | 核心统计 | 解释边界 |
|---|---|---|
| 任务 | 主/支线阶段、关键交互、搬运距离、终端与设施操作 | 不把读条时间称为贡献 |
| 战斗 | 有效发射/命中/未命中、伤害、击杀/助攻、弱点命中、穿透命中、控制/硬直、各武器和各敌人结果 | 可展开到玩家×武器×敌人，显示分子/分母，不用单一命中率掩盖武器差异 |
| 潜行 | 静默击杀、未惊动通过、潜行破坏、直接唤醒数、连锁警戒数、触发动作/刺激、时间、区域与归因状态 | 只依据Authority因果链归因；多人同时触发记共同，证据不足记无法归因 |
| 生存 | 受伤、倒地、救援、自救、搬运队友、治疗有效量 | 不用“承伤最多”自动表扬错误站位 |
| 资源 | 各类弹药/医疗/工具的拾取、转交、有效使用、浪费、带出，重资产消耗与任务资源提交 | “浪费”只用于规则可证明的溢出、遗失或无效事务，不猜玩家意图 |
| 探索 | 新区域、合法情报、字形支路、知识与秘密发现 | 只统计队伍实际获得的知识 |
| 团队风险 | 友伤、误唤醒、断线、重连和关键物遗失 | 作为复盘事实，不扣公开评分 |

团队命中率必须公开分子与分母，定义为可判定命中的有效弹体命中数除以有效发射数。霰弹可同时显示扳机命中率和弹丸命中率；爆炸、持续射线、近战与纯压制行为没有可比较分母时使用各自命中/影响统计，不硬塞进一个漂亮但错误的百分比。团队总数可以继续展开到每名玩家、每把武器、每类敌人、命中部位和任务阶段；同一伤害不能在穿透、爆炸与弱点分组中被重复计入总伤害。

详细统计按结算时已聚合的计数和分组暂存到本局战报，不要求本地回放保留每一发子弹、每一帧位置或完整AI状态。统计页面应提供表格、排序与筛选，但默认首页只展示最能解释本局的少数指标；“详细”指能追到武器、敌人、成员、阶段和关键事件，不是把所有内部调试变量暴露给玩家。玩家确认结束后不保留该统计快照。

不设置总分、K/D排名、S/A/B等级或唯一MVP。可出现描述性贡献卡，例如“完成3次战斗救援”“发现秘密支路”“重资产命中8个高威胁目标”，但卡片不得宣称某人是全队最好，也不得奖励刷弱敌、抢最后一击或故意让队友受伤后再救。

## 行动摘要与因果

RPL-004 · DECIDED · 来源：SRC-USER-2026-09-05-DELEGATED-DOCUMENT-FINALIZATION；授予决策权后采纳行为合同，数值/效果仍须TEST；原依据：来源：本轮设计扩写。

行动摘要完全由已提交事件生成，不用生成式文本猜剧情。自动书签候选包括：任务阶段改变、路线/供电/防御状态改变、Threat Surge起止、首次发现、团队资源跨过公开危险线、重资产取得或耗尽、倒地/救援链、最终目标提交、撤离和Wipe。连续重复事件合并成一段，默认只保留能解释决策变化的节点。

潜行破坏必须是一等事件。`StealthBreakEvent`至少包含发生时间、区域、触发刺激、首批进入警戒的敌人、连锁根事件、归因状态以及零个或多个责任Seat。结算卡可以写成“18:42 · Seat 2使用无消音武器，直接唤醒3个目标，警戒随后扩散至11个”；点击卡片直接跳到回放中的该时刻，并高亮责任玩家、刺激源和首批警戒目标。

只有Authority事件中存在明确`CauseEventID`或刺激链时，摘要才能使用“导致”并写出玩家姓名。两个合法刺激处于同一因果窗口且无法排出先后时记为“共同触发”；只有时间相关而无因果证据时记为“无法归因”。网络延迟、客户端显示顺序和最后一击不能被包装成未经证明的责任归因。玩家点击任意摘要或统计条目，可直接跳到对应回放时间；没有对应空间记录时仍可打开文字事件，不伪造画面。

## 回放查看器

RPL-005 · CANON/DIRECTION · 来源：SRC-USER-2026-09-05-DEBRIEF-AND-REPLAY；SRC-USER-2026-09-05-SIMPLIFIED-REPLAY-AND-STATS；SRC-USER-2026-09-05-DETAILED-STATS-LIGHTWEIGHT-LOCAL-REPLAY；REF-GTFO-REPLAY。

回放使用游戏内简化战术查看器，不是预录视频，也不重建原始第一人称画面。程序房间以简化轮廓显示；玩家、已记录敌人、重资产、关键资源和目标用形状清楚的标记表示，并可显示朝向、生命状态、装备、开火/命中线、交互和移动轨迹。基础控制包含播放/暂停、拖动时间线、逐事件跳转、前后跳跃、跟随指定队员、旋转/缩放地图和速度调整；首轮候选速度为0.25、0.5、1、2、4与8倍。

简化回放明确不记录或重建原始相机、ADS/准星运动、逐帧骨骼动画、布料、粒子、ragdoll、完整弹道、照明、原始音频或电影镜头。时间线以任务阶段为主带，以潜行破坏、战斗、危险事件、倒地/救援、目标提交和玩家书签为图标层。玩家可以按成员、事件类型和任务阶段筛选；筛选只改变显示，不改变原记录。默认遵守行动当时的团队知识，不显示队伍从未发现的秘密房间、未接触敌人或隐藏任务答案。

RPL-006 · CANON/DIRECTION · 来源：SRC-USER-2026-09-05-POST-DEBRIEF-DISCARD。

统计与简化回放只写入本地临时结算区。玩家进入详细统计或回放后可返回结算首页继续查看；每台设备独立确认结束，不要求全队同时关闭。玩家选择`确认并返回壁垒`或`再来一局`后，该设备关闭查看器、提交删除标记并清除本局`DebriefSnapshot`、回放块和索引；删除不影响已经提交的奖励、成就或进度。

首发不提供改名、置顶、导出、分享、云存储或永久行动档案。异常退出留下的完整或临时块在下次启动时清理，不借机建立隐藏的长期记录。记录中仍不得包含队伍语音、文字聊天或平台账号秘密；回放内只使用Seat ID与当局显示名。

## 故障、模组与可访问性

RPL-007 · DECIDED · 来源：SRC-USER-2026-09-05-DELEGATED-DOCUMENT-FINALIZATION；授予决策权后采纳行为合同，数值/效果仍须TEST；原依据：来源：本轮设计扩写；技术责任见[回放记录TRP-001至TRP-006](../technical/replay-recording.md)。

回放记录失败不能使任务结算失败。`DebriefSnapshot`先于回放索引完成并独立生成；损坏或不完整回放明确标出最后有效时间，不伪装成完整记录。简化查看器只读取录制时写入的房间轮廓、实体类别、图标和状态，不加载Gameplay包执行逻辑；详细统计与文字战报在本次结算关闭前仍可用。

查看器全流程支持控制器、键鼠重绑定、事件文字缩放、非颜色图标和低动态移动。回放本身不播放原始语音或战斗音频；玩家仅靠时间线、地图标记与状态面板即可理解事件。

## 验证与停止条件

RPL-008 · TEST · 来源：本轮设计扩写。

用成功、末段Wipe、Host迁移、断线重连、程序秘密支路和高敌人密度六类任务验证，并为单人误唤醒、多人同时刺激、环境连锁、网络乱序各建固定测试。候选通过条件：结算出现后10秒内多数新玩家能指出任务结果、最大资源转折和下一步入口；随机抽取统计与权威事务账差异为0；已归因的潜行破坏与Authority刺激链逐项一致，证据不足的案例不得指名；点击摘要能跳到正确事件；任何玩家可在不看完整动画的情况下两次输入内返回Hub。若玩家只讨论击杀第一名、成员互相指责增加或战报阅读阻塞再开，应先删排名式呈现或收紧归因证据，不靠多发奖励诱导观看。


## 本次定稿：执行边界

详细权威统计与临时本地回放均保留首发。回放是低频位置+关键事件查看器，不是录像/全PhysX可重演证明，不记录玩家语音。离开结算或进入新Run清除临时记录，异常退出下次启动清残留；永久Archive/成就和必要恢复文件属于不同数据域。无MVP/KD公开排名；因果不足则写共同/环境/无法归因，不为故事性编造破坏潜行者。
