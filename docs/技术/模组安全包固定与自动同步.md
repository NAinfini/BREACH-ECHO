# 模组信任边界、包固定与自动同步

## 首版能力决策

MODSEC-001 · CANON/DIRECTION。官方公开 Mod 能力按 `Data → 有界声明式 Graph → Luau Sandbox Script → Cooked Assets` 组合。脚本运行时只使用 **Luau Core Compiler + VM**，Gameplay Script 只在 Authority 执行；客户端表现脚本没有 Gameplay 写权限。Luau 是否随首发开放取决于 Unity 6、IL2CPP、Windows/Proton、CPU interrupt、内存配额、崩溃隔离和诊断 Spike；若 Gate 失败，只延后 Script 层，不改用 C# 动态编译、Lute、MoonSharp、WASM 或 DLL 建立第二运行时。

初始版本完全拒绝社区 Managed Assembly、Native DLL、可执行文件与动态库。PVE 不做竞技反作弊，不等于允许陌生 Workshop 内容访问文件、进程、网络套接字、凭据或平台账号。

Graph 或 Luau 都不是安全的魔法标签。Graph 只允许固定节点、有限常量/集合、声明读写能力、显式事件入口与受限迭代；Luau 使用独立 environment、只读共享库、宿主 interrupt、内存类别和不可伪造 Capability Handle。两者都禁止文件、系统网络、进程、反射、CLR/Unity 对象图和账号写入。编译时验证能力与静态成本，运行时按包记账；超预算时按已公布的故障政策中止受影响会话，不能静默删掉合法 Gameplay 结果。官方内容也通过同一 Registry 和规则验证，但引擎内部受审代码不作为可下载 Mod 能力暴露。

## 包结构与信任

MODSEC-002 · DECIDED。

PackageManifest必须包含`package_id, semantic_version, schema_version, sdk_version_range, kind, dependencies, conflicts, content_index, capabilities, distribution_locator, license/provenance`。每个文件记录规范化相对路径、byte size、SHA-256。计算包锁digest时按路径字节序排序，以明确长度前缀串联manifest原始规范发布字节与各路径/文件hash；发布后manifest不得在原hash下修改。构建器输出同一输入得到同一内容索引；平台压缩容器自身字节差异不冒充逻辑内容一致。

`breach.official`命名空间只由本地受信任发布登记/签名认可，不能仅凭字符串自称官方。Hash提供内容身份而非安全背书；publisher签名也不能代替沙箱校验。AssetBundle不是任意文件的安全沙箱：只接受支持版本、目标平台、允许资产类别与Shader策略，限制资源数量/展开大小；拒绝未审组件序列化、未知插件和外部文件引用。URP自定义Shader及复杂表现的公开能力先限制到SDK允许集合，避免GPU/加载型拒绝服务。

## 三类模组与同步集合

MODSEC-SIDE · CANON（分类及加入范围）；字段、依赖和恢复处理为受托DECIDED。来源：SRC-USER-2026-09-06-MOD-SIDE-SYNC。

PackageManifest必填`network_side: host_only | client_only | host_and_client`，纳入内容hash。它描述安装与参与端要求，独立于Data/Graph/Luau/资产类型及脚本执行位置；不得从“脚本只在主机执行”推断整个包为主机专用。

| 类别 | 用途与边界 | 客户端加入行为 |
|---|---|---|
| `host_only` 主机专用 | 主机管理或可完全通过既有共享定义和复制协议表达的权威逻辑；不能要求客户端拥有新定义、资产、预测或消息解码器 | 不下载、不安装、不激活主机的此类包；缺少它不阻止作为客户端加入 |
| `client_only` 客户端专用 | 个人HUD布局、音效或允许的本地表现；不写玩法状态、不改变碰撞或未授权信息可见性 | 不分发主机的此类包；各玩家继续使用自己的合法组合，版本无需彼此相同 |
| `host_and_client` 双方必需 | 新地图、武器、敌人、角色等需要双方定义或资产的共享内容，以及其共享依赖 | 自动补齐本局锁定的精确版本/hash；已有验证缓存直接复用 |

主机玩家同时具有Authority和本地Client角色，因此可以使用自己的client_only模组；这不会使它们成为其他玩家的入房要求。混合包只要含有双方必需内容，整个包必须标为host_and_client；若作者希望单端部分不分发，须发布独立包与独立Workshop item，不能在共享item中捆入单端包后声称没有下载它。

验证器必须检查声明、内容索引、能力和依赖，而非相信作者标签。host_and_client只能依赖host_and_client；host_only可依赖host_only或host_and_client；client_only可依赖client_only或host_and_client，但不得因此向房间增加共享内容。共同库按实际端要求发布，不能用跨端依赖偷渡单端包。发布检查同时核对Workshop依赖，拒绝会连带下载单端包的共享item依赖；Modpack配方不能绕过过滤。无法证明单端边界的包拒绝激活，作者修正分类后重新发布，不在加入时静默改标签。

Package Lock由同一次验证解析生成`shared_packages`（双方必需闭包）与`host_packages`（主机专用闭包）两部分，分别有确定加载序和digest；完整锁固定Run恢复身份。主机专用包依赖的共享包也属于shared_packages。个人`client_packages`单独保存在本地Profile，不参与房间一致性digest。运行注册表按端装配，客户端只装配shared_packages与自己的client_packages。

下载集合严格为`shared_packages`减去本地已验证精确hash缓存。加入握手只要求共享部分精确一致：缺失、错hash或额外激活的共享包均不能Ready；本地多装但未激活的包不构成不一致，合法client_only差异也不构成不一致。客户端自己的其他共享包和host_only包仅在本次Join Profile不激活，不卸载或改写个人配置。

本地client_only包若依赖房间未提供的共享包、版本不兼容或定义冲突，不能拉入额外共享包、覆盖主机锁或偷偷停用。进入Ready前定位冲突并让玩家选择仅在本次会话停用受影响的客户端包及其依赖者，或取消加入；兼容的个人客户端包继续启用。取消、失败和退出恢复原Profile，保持已安装内容与订阅偏好。

host_packages仍属于权威恢复必需内容，但不得以热备名义随加入自动安装。备份可保存有界、带schema的主机模组状态记录，不运行对应脚本；这不代表有选主资格。换主资格另按[迁移协议](主机迁移与恢复协议.md)检查完整权威锁。Official/Modded和奖励资格取决于实际规则与能力，不能因主机专用包未分发就把自定义玩法标成官方。

## 加入与激活状态机

MODSEC-003 · DECIDED。

`Discover → CompareLock → ConsentPolicy → Download → Validate → Stage → Activate → Handshake → Ready`。Host发布按MODSEC-SIDE分区的锁与digest；客户端仅为shared_packages生成下载计划，并与自己的client_packages编译临时Join Profile。客户端验证分发地址仅为许可的Steam Workshop locator或本地已验证缓存，不能跟随Host指定任意HTTP地址。自动同步操作是一次整合流程，不要求用户逐个找Mod；外部共享内容显示缺失大小、来源和支持的能力。玩家可取消，取消保持当前profile不半激活。所有阶段绑定同一房间锁revision；激活或握手失败撤回临时Profile，回到原Profile；主机锁变化则重新比较，不沿用旧Ready。重连仍使用原Run共享锁，不强制匹配个人客户端组合。

下载由ISteamUGC完成；Loader验证完整依赖拓扑，确定同层排序，不允许重复覆盖定义、循环依赖、隐藏能力升级、presentation标签夹带玩法修改。验证成功后复制/建立应用管理的不可变hash缓存，再一次切换profile；Steam更新安装目录不能直接改写正在进行的Run。失败返回明确错误码和修复操作，不清空用户订阅或覆盖旧hash。

## 旧版本、缺包和授权

MODSEC-004 · DECIDED。

Steam Workshop已有分支兼容版本能力；官方发布在升级游戏branch前先准备兼容mod版本和回归矩阵。它不能被解释为“任意历史hash永远可重新下载”。活跃/挂起Run固定精确hash，保留正在使用的完整本地缓存；磁盘清理不能删除被引用包。已安装且许可允许的旧内容可继续本地使用，但不绕过撤销授权、平台限制或删除要求。

新加入者无法取得Host需要的旧hash时**拒绝本次加入**，显示缺失包、所需版本/hash、现有版本以及“等待提供者恢复正确版本 / 返回 / 新建使用一致新版本的Run”。不静默升级旧Run、不伪造兼容、不通过Host直传第三方资产、不自建镜像规避许可。整局玩家明确选择新版本时也应创建新Run或经过专门验证的显式迁移，不能因某人点更新就改变他人当前Run。

## 存储、撤回和排错

MODSEC-005 · DECIDED。

Profile记录启用包集合、加载顺序和玩法锁，订阅列表不是实际激活状态。共享缓存用引用计数和磁盘预算；GC仅回收无活跃/挂起Run引用的artifact，执行前展示空间和影响。导出诊断仅含包IDs/hash、错误码、游戏/SDK版本和脱敏日志，不导出第三方内容、账号票据或个人聊天。退订与停用不同；卸载需要用户明确操作，不能加入好友房就改变其长期偏好。

多人安全验收覆盖Zip Slip、symlink、zip bomb、超深JSON、重复ID、hash篡改、Graph无限环、恶意能力声明、未知DLL、非法Shader、大纹理内存、磁盘满、断下载、Steam更新竞态、被删除旧版本。独立安全审查和真实恶意包测试仍未运行；文档不保证能防住所有恶意创作者。
