# 入门：如何把文档做成游戏

开始任何实现前先看[开发准备度矩阵](制作/游戏开发准备度与责任覆盖矩阵.md)：它按责任域指出应读的唯一文档、目前能否实施，以及缺的是构建、试玩、审阅还是外部证据。不要因为某个目录很长就假定它已经通过验证。

## 这是什么项目

BREACH: ECHO 是一款 1–4 人合作游戏。玩家是服务于城市“壁垒”的固定外勤小队。城市需要补给和仍能工作的机器；小队进入废弃或敌对设施，决定如何分配有限弹药与资源，完成合同并设法活着撤离。开路或恢复供电既可能提供帮助，也可能唤来危险。

基础版只制作 **Operation**，不是同时开发两款游戏。任务由经过设计的房间和情境组装；随机化负责重排兼容内容，不指望算法凭空发明有趣关卡。节奏更快、偏 Roguelike 的行星远征模式 `Descent` 属于未来工作，并有独立批准 Gate。

## 已决定与未决定

本基线是一套制作与测试指令，不证明游戏已经好玩或完成。`CANON` 表示所有者明确要求；`DECIDED` 表示在所有者授权下作出的选择；`TEST` 表示必须实测的初值或实验。需要所有者批准的叙事候选会保持明确标记。[完整权威规则](治理/文档编写与权威规则.md)说明如何处理冲突。

普通技术问题必须选出方案，不会要求所有者在陌生的网络库或代码架构之间盲选。需要所有者回答的是游戏最终身份、四名角色、最终故事、真实预算与合同，以及任何对明确要求的改动。[所有者裁决清单](治理/项目所有者裁决清单.md)是这些批准事项的唯一入口。

## 所有者不需要亲自写代码

所有者的实际职责是批准身份与支出，在需要时通过安全连接提供账户访问，试玩构建并描述哪里好或不好。实现智能体或开发者负责创建和测试项目、诊断缺陷、编写构建说明并提供可执行版本。若某项 Gate 无法通过，动画、美术、声音、平台或安全仍可能需要专业人员；本文不假设这些人员已经受聘。

所有者不应为了评估构建而复制无法解释的脚本、编辑服务器数据库，或逐字段修复 Inspector。每个可玩里程碑都必须附一份简短指南，明确“打开什么、按什么、反馈哪些观察”。

## 制作顺序

里程碑和通过条件只由[实施交接](制作/实施交接与制作入口.md)维护。入门时先理解一个短而完整的单人合同，再验证合作可靠性，之后才扩大程序内容和发行范围；不在本页复制另一张 M0–M6 表。

## 不必一次读完全部文档

先读[首发范围](产品/产品范围与首发合同.md)与[所有者裁决](治理/项目所有者裁决清单.md)。体验设计从[愿景](产品/游戏愿景与设计支柱.md)、[Operation](玩法/系统化战术行动模式.md)和[BLACKSTART](内容/任务/换流器黑启动任务合同与灰盒规格.md)开始。故事从[待审完整总览](世界与叙事/完整故事总览.md)开始，再读其中链接的角色与世界文档。

新开发者从[实施交接](制作/实施交接与制作入口.md)与[技术栈](技术/Unity与Steam模组技术栈.md)开始，再沿链接找到规则所有者。写作者、美术或测试人员使用[文档总览](文档总览.md)中的角色路径。[文档登记](治理/完整文档登记.md)列出全部 Markdown，包括历史来源、模板和项目技能；任何信息都不依赖记住某次聊天标题。

## 小型术语表

**原型（prototype）**用于低成本验证高风险想法。**垂直切片（vertical slice）**是体量小但完整、具有代表性的游戏片段。**主机（host）**是运行共享世界的玩家设备。**权威（authority）**表示谁有权决定真实结果。**内容包（package）**是有名称和版本的内容集合。**Gate** 是继续投入前必须通过的测试。**决策记录**解释选择及哪些证据可以推翻它。更多定义见[术语表](术语表.md)。
