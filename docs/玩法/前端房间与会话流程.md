# 前端、房间与会话状态流

## 玩家目的与单一责任

UIFLOW-001 · DECIDED。

玩家从启动到开始行动、处理中断并返回壁垒的路径必须可预测、可返回、可用控制器完成。本文拥有页面层级、会话状态和错误恢复；具体HUD信息归[UX](../表现与资产/界面信息与可访问性.md)，匹配规则归[合作与社交](合作单人机器人与公共匹配.md)，Mod包流程归[Mod Manager](游戏内模组管理器.md)，网络真相归[网络与持久化](../技术/网络权威存档与版本固定.md)。

## 顶层状态机

UIFLOW-002 · DECIDED。

顶层页面顺序固定为：`Boot → LegalAndSafety → ProfileLoad → ServiceCheck → Title → BastionHub → MissionBoard → SessionSearchOrCreate → Lobby → Loadout → ReadyCheck → Loading → Operation → Debrief → ReplayOptional → BastionHub`。已经在好友小队中的玩家仍从同一任务板选择Offer；好友关系不是一套绕过任务锁定的替代状态流。

离线Solo在`ServiceCheck`后进入`OfflineProfile`，不创建Steam Lobby。在线服务不可用时给出“重试 / 查看状态 / 离线Solo / 退出”，不能无限转圈。活动Run存在可恢复证书时，在Title显示“恢复行动”，并在覆盖本地较新或较旧状态前展示Run、时间、成员、包锁和恢复水位。

界面采用单一`ScreenStack`：基础屏幕占底层，设置、确认、错误、邀请、文本输入和下载进度是Modal；只有栈顶接收UI输入。在线Operation打开暂停菜单不会暂停模拟，离线Solo才允许暂停SimulationTime。返回动作关闭最上层，不能从深层设置直接误退整局。

## 页面清单与完成条件

UIFLOW-003 · DECIDED。

| 页面 | 必须显示/允许 | 离开条件 |
|---|---|---|
| Title | 继续、进入壁垒、训练、Mods、设置、制作人员、退出；服务/版本状态 | Profile合法或明确错误 |
| BastionHub | 小队、任务板、配装、Archive、训练、Mods入口；不做50人社交Hub | 选择一个明确目的 |
| MissionBoard | 全服同轮8个普通Offer，特殊行动另列；按UX-008分层显示目标、交战合同、条件、限制、收益、难度与新开截止；精确选择或显式多选快速加入 | 选定一个普通或活动Offer/难度，或一组玩家明确接受的Offer/难度；后续轮换或活动到期不中断已锁Run |
| SessionSearchOrCreate | 按精确选择或可接受集合显示现有公开房，或创建Solo/好友/私密/公开房 | 进入一个任务身份、版本与隐私明确的Session；最终锁定前显示实际命中项，无结果时不暗改筛选 |
| Lobby | 已预约任务完整卡、隐私、成员、语音/静音、Ping、包锁、邀请/踢出权限与进入配装入口 | Seat与依赖合法；所有成员都能复查任务后进入配装/Ready |
| Loadout | 角色Seat、两枪/专用近战/工具/模块、队友配置、冲突、资源与详情比较 | 每名真人配装合法；返回Lobby不丢已提交合法选择 |
| ReadyCheck | 最终任务卡、难度、成员、Seat、配装、包锁和未Ready原因 | 全部真人明确Ready且依赖齐全；UIFLOW-005规定的共享变化清除全队Ready |
| Loading | 阶段、成员与包状态、取消规则、错误归属 | 全员进入或明确恢复/失败 |
| Operation HUD/Pause | 当前任务、队友、资源、Ping、设置、离队/恢复说明 | 权威结果或明确离开 |
| Debrief | 团队结果、个人/团队详细统计、关键因果、奖励领取 | 玩家确认返回或打开回放 |
| Replay | 简化地图、时间轴、事件筛选、播放速度 | 返回Debrief，不改变奖励 |
| Settings | 显示/性能、音频、控制、可访问性、语言、网络/隐私 | Apply成功或放弃未提交改动 |

Archive、训练和Mod Manager是独立基础屏幕，可从Title或Hub进入；离开后返回原入口。制作人员、许可、隐私告知和第三方声明在发行前必须可离线打开。

## 会话创建与加入

UIFLOW-004 · DECIDED。

标准创建流程为在MissionBoard选择Offer与难度→选择Solo/好友/私密/公开→创建Session并预约任务卡→分配Seat/验证包锁→进入Lobby→协同配装→Ready。预约固定正在讨论的OfferRevision，不等于已开始或取得过期活动的新局资格；房间期间可明确改选并清除Ready。全部真人Ready的启动提交才冻结RunManifest、MissionSeed及规则，原子复查Offer仍可新开；若轮换失效，回任务板重新选择，不自动换卡。标准公开加入有两种明确入口：精确选择一份Offer/难度；或玩家主动勾选一组可接受的Offer/难度后快速加入。搜索只匹配该明确集合与兼容规则，显示实际任务、地区、延迟估计、任务阶段、人数、是否Modded及下载量→确认→身份/版本/包锁验证→下载与Staging→分配Seat→进入Lobby或中途加入快照。系统不能为缩短等待暗加未选择的难度、任务、地区或Mod状态。Steam邀请和已存在好友小队可以直接进入房间，但加入者必须先看到完整任务卡、难度、规则和包状态，不能被直接推进Ready。

活动合同沿用相同流程，但搜索条件额外包含EventID/Revision与Modifier Bundle Hash。玩家可主动把“普通合同”和“特殊行动”同时加入可接受集合；系统不能默认代选。活动详情页展示正负效果、禁用槽位、所需内容包、奖励资格、结束时间和Mod政策。Run开始后继续显示已锁Revision，不用当前服务器活动覆盖历史卡。

匹配筛选首发只提供地区/延迟、难度、任务长度、语音偏好、Modded/Vanilla和空位；不建立隐藏技术评分或战力分数。搜索无结果时提供扩大地区、放宽筛选、创建公开房和返回，不自动改变玩家选择。中途加入前明确任务已进行时间、回放前段缺失、当前配装限制及奖励资格。

## Ready、倒计时与取消

UIFLOW-005 · DECIDED。

Ready表示“我接受当前任务规则、成员和配装版本”，不是阅读测验，也不是永久预约。Mission、Difficulty、Ruleset、共享Package Lock、成员加入/离开、Seat或任一玩家已提交Loadout变化，均清除全队Ready及未提交的启动倒计时。即使新配装合法，也要让队友重新确认；不替换玩家预设，不重置其他人的合法选择。房主不能在倒计时最后一秒静默换难度或包。启动倒计时只是UI阶段，最终开始由Authority在全员合法后提交唯一`RunStartTransaction`；重复消息不创建第二个Run。

仅浏览装备、未提交的预览、无效选择，以及语言、字幕、字号、音量、键位和允许的纯客户端表现包变化，不清除Ready；若包解析结果实际改变共享图，则仍按共享变化处理。提示写清改变了什么，例如“铆钉更换了团队工具，请重新准备”，不只显示“状态失效”。谁尚未准备、正在下载、选择非法或仍在看战报分别呈现；不以倒计时替人同意。

启动提交按同一个已核验版本处理：变更先提交则旧Ready失效；RunStart先提交则本局锁定，后来的Lobby改装不能写入正在加载的Run。启动响应超时应查询同一事务结果，显示“正在确认是否已出发”；不得把未知结果当失败重开另一局。取消只在当前阶段确实允许时生效，已锁Run的恢复/离开走既有会话规则。

下载、构建包验证或服务请求可以取消，取消不得半激活Profile。已经进入Operation后，离队确认必须说明Seat保留时间、队伍影响和本地临时回放处理。Host离开优先进入迁移界面；只有恢复被判定不可能时才显示挂起/结束选项。

## 从任务板到入场的信息交接

UIFLOW-BRIEFING · 受托DECIDED；设计验收未运行。信息内容与披露层级由[UX-008及UX-BRIEFING-BOUNDARY](../表现与资产/界面信息与可访问性.md)拥有；本文拥有何时显示、确认和失效。

| 阶段 | 玩家此时必须知道什么 | 状态与交互要求 |
|---|---|---|
| 浏览任务板 | 当前八份普通合同；已验证可用的特殊行动；选中难度下的公开目标、规则、限制、收益与新开截止 | 卡片按稳定OfferID保持焦点；轮换不把旧按钮位置悄悄换成新合同。失效卡保留“已结束轮换”状态，玩家主动刷新/改选；不能点击旧卡开到新任务 |
| 选中合同/匹配 | 实际选中的合同和难度；规则全文、Mod/版本/下载条件；新局或中途加入 | 快速匹配命中后显示实际合同，确认前不下载或Ready；拒绝命中项可返回原筛选，不暗扩大集合 |
| Lobby预约 | 正在讨论的版本、新开截止、成员与包状态 | 显示“已选定，尚未出发”，不是“本合同已保留”。预约期间到期即不能新开，保留队伍和配装，显式选择下一合同；不提供隐藏宽限期 |
| 配装 | 当前各槽合法目录、单件行为/成本、活动实际影响、队友已提交装备 | 共用Lobby规则摘要；禁槽显示原因，预设原件只保留在账号预设，不偷偷换枪。极端但合法的配装可Ready；重复装备不是错误 |
| Ready/开始 | 当前实际任务、规则、成员和配装；阻止开始的具体原因 | 各真人确认当前版本；最终核验新开资格、包锁和配置。锁定成功才显示“本局规则已锁定”，并停止把轮换倒计时当本局倒数 |
| 加载/同步 | 当前加载阶段、同队同步状态、可取消性；可复查本局规则 | 不播必须听完的讲解，不加阅读最低时长。不得展示作者俯视图、房间兵力表或秘密入口；技术失败不是玩家团灭 |
| 入场 | 当前主目标、可选目标入口、当前合法权限及下一步行动意图；已知危险与队友状态 | 默认简短HUD，全文随时可复查；没有合法定位证据时写“位置未确认”，不生成假waypoint。交互提示显示实际绑定键，不强制拉镜头或关闭操作 |

线上八Offer的刷新按控制面时间显示绝对截止与倒计时；离线或缓存视图明确标出来源、最后更新时间及准入不可确认状态，不假装全服实时。普通离线Solo仍按原入口可用。服务、下载和包错误保持单一错误恢复流程，不让玩家为了读规则另开网页。

开局只交代本合同任务，不把全套世界历史塞入简报、不假装老队员不知道内战或虚空兽。规则可随时查阅，但不会自动替玩家查询终端、选择路线、标出薄弱配装或安排分工。纯信息面板可关闭；紧急任务/危险提示继续按优先级显示，不因玩家没读介绍而暂停在线世界。

### 中途加入与重连

UIFLOW-JOIN-BRIEFING · 受托DECIDED，接管资格仍唯一遵循[合作合同COP-SEAT及COP-END-ADMISSION](合作单人机器人与公共匹配.md)。

加入预览先给已锁任务规则、在局时长、当前阶段、是否允许接管、可接管Seat的Alive/Downed状态及装备/资源概况、奖励资格与本地回放缺段说明。它不是一次重新配装：接管继承原身体的装备、生命、库存与已提交行动。角色身份不构成职业钥匙，不能带着Lobby预设和满资源替换现场身体。

预览中的席位状态带更新时间；实际接管前再验证。同一席位被抢占、已Out或准入已关闭，给明确原因并返回选择/等待下一局，不生成新身体、不将请求自动转成Ready。下载完成不等于已经接管：首次合法撤离扫描产生进度后，尚未取得席位的新玩家不能补进本局；扫描暂停不重开准入。原玩家合法重连按原席位恢复，不受“禁止新补位”误拦。

接管成功才同步团队已合法取得的任务进度、地图、查询记录、权限、已发现危险和最后确认位置；保持信息来源、作用域和年龄。终端旧扫描不是当前敌人数，有效探测点仍按其剩余寿命跟随敌人，不把过期信息重新激活。不能从主机完整世界状态反推出“加入摘要”。简报是可随时重开的短面板，不把身体冻结在危险区等待阅读，也不凭空给无敌。

活动到期不终止已锁Run；是否继续允许新匹配/补位，还须按该Revision的暂停、HardStop及准入政策判断，不能拿“能否新开Run”代替接管检查。正常重连仍核验该Run锁定版本，不拉当前活动的新规则替换。

## 训练入口、跳过与局内帮助

UIFLOW-TRAINING · 受托DECIDED，未实现。学习内容与提示状态唯一归[ONB-001至008](新手教学首局与长期学习.md)。首次可选校准后可直接去壁垒，训练不插入Boot或Ready的强制通关条件；菜单保留操作手册和分项练习入口。没有训练成绩准入、强制低难或读取完毕确认。

Hub打开独立练习时保留正式配装预设，进入非奖励的练习实例；可随时重置本项或退出到原入口。处于小队时本人保持未准备，不能一边留在练习一边自动Ready进入正式Run。接受好友邀请前明确退出当前练习，再执行原加入/包检查；失败返回Hub，不丢预设，不以练习资源新建席位。重复退出、重置或迟到的练习结果不能写入正式Run。

正式行动菜单可打开操作说明，但“进入练习”不可用并说明需先返回壁垒；不提供在局身体挂起避险或训练补给。离开正式Run仍走原放弃/离队规则，不能由教程按钮隐式执行。在线帮助不暂停世界；离线暂停沿原会话规则，不另造教学暂停权。返回帮助前所在页面或战场时恢复正确焦点，并消费关闭输入，避免顺手误开枪。

教学记录仅是本地参与者的显示偏好，不放入Ready版本或全队待办。开关提示、字号、语言和主动查看手册不清全队Ready；实际共享规则和已提交配装变化仍按UIFLOW-005处理。迟加入不播放完整教程，不拦其他人合法提交设备；接管状态和合法知识按UIFLOW-JOIN-BRIEFING，不从教程补发资源、情报或奖励。

## UI数据与所有权

UIFLOW-006 · DECIDED。

UI读取只读`ViewModel`，通过语义Command请求变化，不直接写Simulation、库存、Ready或包状态。每个异步操作包含`OperationID`、当前阶段、可取消性、进度单位、超时责任与结构化错误码；旧响应因页面重开或revision变化到达时丢弃，不覆盖新状态。

任务板、Lobby、Ready和加载页共用编译后公开任务说明，不各写一套活动效果文案。只读投影显式选取公开字段，不把完整RunManifest、生成种子、语义Zone槽或实例绑定序列化后交给通用详情控件自动展开；运行时仍可持有必要数据，本文不是PvE反作弊或防数据挖掘承诺。现场地图/目标另读合法TeamKnowledge，加载页不能提前消费它。控制面作者预览与玩家预览明确分开，诊断导出需显式操作，不能成为默认信息面板。

设置采用`Draft → Validate → PreviewOptional → Commit → Applied`。显示模式等可能导致黑屏的设置使用15秒回退确认；重绑定发现冲突时必须选择替换、互换或取消。语言、字幕、文字大小和降低动态效果可在Operation中修改并立即作用于表现，不改变权威玩法。

## 响应式、控制器与本地化

UIFLOW-007 · DECIDED。

uGUI使用CanvasScaler参考1920×1080、锚点与Layout Group，不用单分辨率绝对定位。关键HUD和按钮遵守安全区；16:10 Steam Deck、16:9、21:9和32:9采用扩展画布并保持关键内容在可读列宽。每页打开时有明确初始焦点、可见且不只靠颜色的焦点态、显式邻接与Modal焦点陷阱。键鼠与控制器可随时切换，不清空焦点或重复提交。

全部文本使用本地化键和内容自适应容器；中文、英文至少用最长实际字符串做伪本地化压力测试。图标与文字分离，错误不能只给代码；代码可作为诊断详情复制。

## 错误与恢复矩阵

UIFLOW-008 · DECIDED。

| 失败 | 必须解释 | 合法下一步 |
|---|---|---|
| Steam离线/认证失效 | 哪项在线能力不可用，本地档案是否安全 | 重试、离线Solo、返回 |
| Build/Protocol不一致 | 本机与房间版本 | 更新、返回；不硬读 |
| Mod缺失/旧hash不可得 | 包、版本、hash、来源和下载状态 | 重试、等待作者恢复、创建一致新Run、返回 |
| Lobby满/Seat冲突 | 变化后的成员与可用Seat | 选其他Seat、重新搜索 |
| Host迁移 | 冻结原因、认证恢复点和预计阶段 | 等待、挂起或在明确失败后离开 |
| 存档冲突 | 两份时间、进度摘要和设备 | 明确选一份，不合并资源 |
| 生成失败 | Offer或内容包无法产生合法任务 | 标记内容错误并换Offer；不把坏Seed交玩家 |

所有仍在小队的真人必须退出Reviewing、收到新的最终任务卡并明确Ready，才能提交下一次RunStart。可以在别人复盘时浏览任务和配装，但不能将其自动记成Ready；无强制关闭倒计时。想先走的玩家可自行离开另组，不新增公开房单方面踢人权限。结算后房主离开只进行小队协调权交接，不恢复已结束的战斗；各账号待领取凭据不依赖新房主重签。

**同合同重试：**旧Run正常终结后，以新RunID、空事件/领取流水和初始资源从入口重新开始；保留上一局冻结的MissionSeed与生成配方，不取失败现场快照。相同人数、规则与内容版本下，地图、原始资源和敌人布置相同，供队伍改配装与计划再试。人数变化只按原公开人数配置重算对应名单，不按新武器挑图或补资源；装备实例重新生成，账号知识与外观保留。规则/难度/内容变化属于另选合同，不冒充原图重试。

普通Offer过期或活动停止接受新Run后，不可复制旧准入重试：保留小队，返回当前任务板说明原因。已锁且未结束的Run仍可恢复并按原规则结算；恢复不是重试。原Run技术挂起时先提供恢复/明确放弃，不让两个实例消费同一恢复权利。缺原版本内容时明确拒绝同图重试，不用当前包静默生成不同地图。

另选合同创建新的MissionInstance；同一已锁实例的失败、离队重连、查看战报和重复按钮不重新Roll，不提供“刷新本图”。程序反重复用于新合同生成，不改写明确选择的同图重试。新Run普通奖励正常结算，唯一档案/外观继续账号去重；仅保留上一合同的最小配方引用供重试，换任务即替换，不保存永久战报。
