## 放置与取得

全部采用既有终端档案／数据载体检查交互，不新增六套小游戏。每篇可独立合法取得；同一终端可装多篇，分别列明并一次确认取得当前列出的记录，不要求逐页读完。不同记录可以跨局补齐，但不强制每局只出一篇、不强制六次出勤；具体生成权重随内容密度实测，不在这里杜撰概率。

| 集合 | 允许的语义场景与来源说明 | 不允许的生成 |
|---|---|---|
| 断箭 | 人类使用过的安保资料室；清楚标作“训练资料节录”，当事人仅保留呼号、无关人员匿名 | 作为古代守门人原生日志；在任意门边声称这里就是事故原址；未经解释散落完整私人处分档案 |
| 回声 | 近期外勤维护终端的交接附件；笔记经整理进入技术案例库的副本 | 放在从未有人类进入的封闭设施；要求回声当前在队才能理解 |
| 铆钉 | 人类维护站的维修案例资料；标明来自壁垒生活设施，不是该关卡居民来信 | 把样稿的热水泵当作所有地图的真实设备；免费增加维修能力 |
| 蝶 | 人类采集准备区的接收案例节录；脱敏交接记录，不投放真实未知样本实体 | 拾取即感染；没有内容声明就生成必须带回的额外实体样本 |
| 载波 | 旧人类通信维护区的历史修复档案；记录本地设备与相邻站的恢复 | 仅因终端亮着便称通信已恢复；揭示当前未知房间和全部字形密码 |
| 配电 | 人类使用过的动力维护区，存放一次检修交接案例副本 | 把历史停机单挂成当前通电状态；要求眼前必须有那只货箱或损坏电梯 |

上述标签是内容匹配条件，不是新引擎接口。使用已有Cluster元数据表达“人类使用痕迹、资料用途、记录时代与副本来源”；缺少条件就不投放该集合。相关实体证据若被采用，必须随完整语义场景生成，不能将“这里”所指设备拆走。首稿主要用档案副本，所以不要求重建六个事故现场。

资料副本不是全体玩家已获知的公共教材：它是局部维护站保存、尚未收入玩家档案的案例；公共世界历史照常可知。来源说明随条目保存，不只写在地图装饰上。副本在不同地图出现时仍是同一历史事件、同一条目ID，不能随机改死伤、作者或结果。

## 保存、奖励与阅读

十九篇均为叙事收藏，默认贡献档案与集合完成度；本批不绑定新Credits数额、回收额度、字形密码、武器属性、成就名称或外观承诺。它们不是可消费字形知识，也不因档案谈到设备就授权操作。以后如为集合配置展示奖励，引用同一完成事实，不复制一套发现账本。

合法发现、队员资格、重复记录和迟加入统一按PRG-004/005/014/015；永久保存只认既有合法Bank或撤离结算。读取顺序不影响资格；失败时没有保存凭据的发现不能因为“看过”而永久留下。已保存条目可在档案补读；本局刚发现的文字也可补读，但应显示尚未保存。集合完成条件是所有成员条目已合法永久保存，不是全部朗读过。

历史记录不触发当前警报、资源消耗或门控命令。交互完成只短提示已取得记录，不自动展开长文或占用角色语音。阅读界面支持退出、滚动、回看和语言切换；中文／英文全文保留句意，不挤成战术字幕。200%文字缩放、输入焦点和长文换行须按既有UX规范实测；本文未验证游戏显示，也不承诺新增旁白录音。
