# 首轮程序任务内容池与重复可玩性矩阵

## 目的、范围与真实性

PROC-CONTENT-001 · 受托决定 / 全部内容组合尚未实现或试玩。

本文拥有首轮三个主任务的路线骨架池、任务定义池、环境局势池、设施组合、回收来源、支线配对、变体签名和反重复规则。各Mission Contract仍拥有目标状态机、成功/降级/失败、交战合同、权限、资源保底和结算；[程序生成架构](../../技术/程序化行动生成架构.md)拥有确定性、验证器和实例化顺序；本文不建立第二套任务规则。

目标不是宣称“程序生成等于无限内容”，而是让同一个Primary在再次出现时改变队伍的路线、准备、资源与风险决定。房间旋转、材质变化、走廊长度、敌人数微调、目标换名和回收点换一面墙都不算新体验。首轮只批准少量完整组合，再用真实玩法证据淘汰无聊组合；未进入批准组合表的笛卡尔积不得出现在任务板。

## 什么才算一局真的不同

PROC-CONTENT-002 · DECIDED / 阈值TEST。

每个生成实例写入`VariationSignature`。签名包含七个决策维度：

| 维度 | 签名字段 | 必须改变什么 | 不计变化 |
|---|---|---|---|
| 路线结构 | `routeArchetype` | 哪条路先到目标、分支成本、重接点或撤离方向 | 房间旋转、走廊加长 |
| 任务定义 | `objectiveDefinition` | 本局真正处理的故障、案件或货批及其约束 | 只改名称、颜色、数值 |
| 设施耦合 | `facilityCouplingSet` | 一项投入会关闭哪项收益，怎样改变门、环境、扫描、防御或运输 | 多一个无代价开关 |
| 环境响应 | `environmentResponse` | 玩家可观察、可操纵的危险及其替代路线 | 纯屏幕滤镜、被动减速 |
| 敌人与入口 | `encounterPlan` | 初始传播群位置、职责组合、实体入口与可封口关系 | 同一房间多两只血量相同敌人 |
| 支线取舍 | `secondaryPlan` | 是否有支线、它占用何种可选资源并怎样重接 | 只提高Credits数字 |
| 回收机会 | `recoverySourceSet` | 当局二至四种回收动作、主路/支路价值分布及条件型来源 | 同一种插盘点移位 |

同一Primary的两个Offer要被判为可区分，必须同时满足：

1. `routeArchetype / objectiveDefinition / facilityCouplingSet`三个承重维度中至少一个不同；
2. 七个维度中至少三个不同；
3. 差异至少让队伍改变两项可复述计划，例如配装用途、先走哪条路、先封哪个入口、把电力给谁、是否强制覆盖、何时叫补给或是否做支线；
4. 交战合同仍保持该Primary的公开事实，不得把“全程潜行可行”随机改成“必然警报”来制造差异。

自动比较只能判断签名不同，不能证明玩家感到不同。人工盲测时，测试者不知道Seed和签名；如果多数人仍用同一路线、同一配电、同一站位和同一资源顺序完成，两局即使哈希不同也视为重复。

## 共同空间与节奏语法

PROC-CONTENT-003 · DECIDED / 数量TEST。

标准35–45分钟完整原型使用七至十个功能Cluster；40–50分钟正式长局的数量只能在实测步行、战斗和等待时间后确定。每张图必须有一条可验证关键路径、两次以内的短Branch-Rejoin、零至两条Optional Loop和一个不同于插入点的前方撤离出口。Branch只在路线风险、权限、资源或设施结果不同的情况下存在；没有决策的平行走廊应合并。

节奏统一使用锯齿而不是单调加压：

`建立问题 → 第一次路线/权限决定 → 执行与反馈 → 可读缓冲 → 第二次设施/价值决定 → Point of No Return准备 → 任务特有高潮 → 前方撤离`。

高潮前必须有一个能够观察入口、放下双手物、分配Resource Pack和理解设施后果的准备Cluster；它不承诺安全或免费补给。任何Optional离开主路后，应在一至两个Cluster内前方重接；除玩家自己返回遗漏物外，主任务不能要求回到两次Beat以前的Terminal。已经Active且仍能到达玩家的敌人可以进入缓冲区，但生成器不能在缓冲区创建无来源新敌人。

## 设施与环境局势的共同池

PROC-CONTENT-004 · DECIDED / 尚未灰盒。

每局先选任务要求的固定设施，再从合法池补到三至六套主导系统，并生成至少两项真实耦合。环境局势不是额外的负面词条，而是设施出现了可观察问题，玩家能用资源、路线或权限改变它。首轮允许以下六类：

| 局势ID / 名称 | 现场事实 | 可用操作 | 真正改变的计划 | 兼容限制 |
|---|---|---|---|---|
| `ENV-PARTIAL-DARK` 分区失光 | 部分照明母线失效，轮廓和标识仍有非颜色提示 | 给照明供电、带便携照明、走有应急灯的维护线 | 扫描完整度、远程视线、潜行接近路线 | 不能删除关键提示或让高难只靠黑屏 |
| `ENV-COOLANT-VEIL` 冷却雾幕 | 低处冷却雾遮挡视线并暴露泵组故障 | 恢复排风、隔离泄漏、走上层线 | 下层路线、射界、Energy充电与货物完整度 | 不能只做持续扣血区 |
| `ENV-PRESSURE-SECTORS` 压力分区 | 两个相邻区压差异常，门开启会真实交换环境 | 平衡压力、一次只开一侧、走维修气闸 | 门序、噪声、货物/档案安全与敌人通路 | 必需主线始终有可读安全操作 |
| `ENV-ARC-LANES` 电弧通道 | 裸露母线周期性形成固定危险线 | 断电、接地、等待诚实周期或改走机械旁路 | 配电机会成本、掩体位置、设施单位供电 | 不以随机无前兆伤害制造难度 |
| `ENV-RESONANT-DECK` 共振甲板 | 货运/节点启动会沿标记结构传递强刺激 | 恢复隔振、封分段门或接受更大激活范围 | 事前清场、同步清除、入口优先级 | 不改变任务已公开的交战合同 |
| `ENV-AUTOMATION-DRIFT` 自动化偏移 | 机械臂、门或转盘仍按旧坐标工作 | 校准、断电锁止、接管控制或走人工旁路 | 掩体、货路、人员捷径和设施威胁 | 不能变成随机移动平台惩罚 |

同一局最多选一个主导环境局势；任务自身的固定故障不计第二个局势。局势必须与FacilityTheme、Cluster实体和任务定义兼容，并在任务板用“失光、冷却泄漏、压力异常、裸露电弧、结构共振、自动化偏移”等玩家能理解的语言公开。纯粹的敌人加速、资源减半、视野滤镜和无解释随机故障不进入该池。

### 路线骨架

| ID / 骨架 | 关键分支 | 前方重接与撤离 | 形成的决定 |
|---|---|---|---|
| `BS-ROUTE-TWIN-SPINE` 双脊交汇 | 安保短路对维护长路 | 配电厅前重接；换流台后撤离 | 弹药/警报风险对时间/探索机会 |

### 黑启动故障定义

每个`BlackstartDefinition`仍由三种不同动作组成：安装/搬运、分离位置的顺序操作、破障或实体旁路。生成器只能选择整套作者配置，不能把三项都换成终端保持。

| DefinitionID / 名称 | 安装槽 | 分布操作槽 | 末段空间槽 | 主要设施耦合 |
|---|---|---|---|---|
| `BS-DEF-PHASE-LOSS` 相位丢失 | 搬运同步耦合器并插入母线座 | 校准两个分区断路器 | 释放被相位锁卡住的出口联接器 | 扫描精度与防御供电竞争 |
| `BS-DEF-COOLANT-LOCK` 冷却闭锁 | 安装旁路调压件 | 依次恢复前后泵组 | 排放压力并打开前方检修闸 | 冷却在主节点、Energy端口与货运间竞争 |
| `BS-DEF-CARRIER-MISMATCH` 载波失配 | 安装载波采样头 | 在两个隔离区写入同一版本 | 机械断开旧路由并释放新出口 | 通信、安控和地图快照互相制约 |
| `BS-DEF-GROUND-FAULT` 接地故障 | 搬运接地模块到裸露母线 | 锁定两个物理接地点 | 切断电弧结构或走维修架旁路 | 照明、运输和安全断电范围竞争 |

### 设施、回收与支线

每局固定配电、门/隔离、通信/扫描、运输，再从通风、安保选一至两套；至少一项可选投入必须在B05–B07改变真实终段。推荐回收来源池为`DiagnosticExtract、SignalCapture、SystemImage、AssetSurvey、BlueprintImprint`，每局选二至四种：主路优先让已恢复换流/通信设备产生条件型诊断，支路用资产标定或蓝图映射，敌对设施被接管/停机后才允许系统镜像。不能在未修设备上提前领取“修复诊断”。

支线按现行兼容矩阵：辅助防御接管优先；黑匣子和字形暗仓为条件组合。若本局已经用安控作为主要配电收益，防御接管必须占用不同操作或明显资源，不能把同一按钮同时算主线设施选择和完整支线。

### 黑启动反重复要求

连续两个黑启动Offer不得同时复用路线骨架、故障定义和终段设施收益。初始传播群、必然来源入口和友军设施射界必须共同留下至少两种合法准备方案；如果所有批准Seed都让“开侧闸+炮塔”成为唯一答案，该设施组合从批准池移除，而不是让Director暗中加强敌人。

|---|---|---|---|

| `FR-ROUTE-MIRRORED-WINGS` 镜像双翼 | 系统记录和物理现场分处对称翼 | 时基舱是前方联接点 | 四人分组节省时间但可能同时惊动两群 |

### 作者案件定义池

下列五项只描述本地设施事件，不改变中央历史。每项在成为内容包前必须由叙事负责人批准最终文本、时间位置和可公开层级；程序生成器不能改真相。

| CaseDefinition / 本地真相 | 常见错误假设 | 两类以上独立证明 | 玩法区别 |
|---|---|---|---|
| `CASE-IDENTITY-DRIFT` 身份漂移事故 | 守备机被外敌远程接管 | 重启后的身份波形与本地机械时基一致；弹痕/门态证明守备机按旧白名单开火 | 安静断电可保现场，强制覆盖能拿完整安控镜像但会起事故 |
| `CASE-COOLANT-DIVERSION` 冷却改道 | 有人偷走冷却导致设备报废 | 阀门机械位置、独立流量计与配电日志证明冷却被转给紧急设施 | 玩家在照明/扫描和恢复流量计间分配电力 |
| `CASE-CARGO-MISROUTE` 货批误投 | 货运人员带走了研究设备 | 货单时钟、道岔物理位置与撞击方向证明批次进入错误支线 | 需要进入事故货格校验序列，不搬大宗货 |
| `CASE-UNAUTHORIZED-PULSE` 未授权载波脉冲 | 电磁风暴制造了全部记录异常 | 隔离天线波形、手动计数器和烧蚀方向证明设施主动发出过一次脉冲 | 完整证据支路提供字形暗仓线索，但不把秘密当主线 |
| `CASE-QUARANTINE-BREACH` 隔离破坏 | 虚空兽从外侧直接撞开检疫门 | 内侧手动释放痕迹、压力记录与尸体/设备位置证明有人先解除机械锁 | 物理现场更重要，文本少；错误门序会扩大局部环境风险而非改真相 |

每个案件至少准备一项支持证据、一项反驳证据和一个明确“仍然未知”的细节。最低可信封存只回答合同要求的问题，不把缺失细节猜成事实。普通RecoveryRecord、字形采录和案件证据使用不同凭据与反馈。

### 设施、回收与支线

每局固定通信/扫描、安保/身份、门/隔离、配电，再从照明、字形路由选一套。推荐回收来源池为`DataTap、SignalCapture、MaterialTrace、SystemImage、BlueprintImprint`，每局选二至四种：DataTap只取工程资料；SignalCapture只能取非案件关键的设施波形；MaterialTrace只在作者标记的独特现场样点；SystemImage要求设施单位已停机/接管；BlueprintImprint只在研究/制造设备。任何来源若能同时完成案件证明和增加后勤额度，必须拆成两个清楚的提交，防止玩家误解“真相就是奖励点”。

字形暗仓为优先支线；辅助防御接管只在存在安静路径且覆盖尚未访问区时允许；黑匣子保持拒绝，因为它会复制取证、完整性和携带动词。

### 取证反重复要求

连续两个取证Offer不得复用同一案件与同一路线骨架。两次Branch至少有一次在入口方式、证据可信度或设施收益上改变，不允许只把“系统记录A/B”放进左右镜像房。玩家必须能在无外部解释下指出本局哪个物理事实支持或反驳哪项陈述；如果测试者只记得“找三个电脑”，该案件或空间实现失败。

### 设施、回收与支线

每局固定运输/物料处理、配电、门/隔离、通信/货单，再从安保、冷却、工业危险选一至两套。推荐回收来源池为`AssetSurvey、SalvageBeacon、DiagnosticExtract、BlueprintImprint、DataTap`，每局选二至四种：大型货柜、吊车和完整机组使用标定/信标；修复后的运输设备使用诊断；制造或标准化设备使用蓝图映射；DataTap只承担普通库存/维护资料。若货批是界桥中继核心，可用`SignalCapture`代替DataTap；若搭配辅助防御接管，可用`SystemImage`代替一种普通来源。任务货批本身不能同时算RecoveryRecord或后勤额度。

黑匣子为优先支线；辅助防御接管兼容但只能覆盖一个前方扇区；字形暗仓仅在独立Optional port、额外供电和货物Commit前的前向重接成立时允许。

### 货运反重复要求

连续两个货运Offer不得复用货批、路线骨架和同一对故障类别。隔离与全吞吐在每个批准组合中必须同时合法，并改变动作、刺激和世界结果，不得只改奖励倍率。若货物累计迫使玩家等待超过合同阈值、最优策略是贴车走或动态异常重复前两个故障，组合直接移出批准池。

## 八Offer任务板与反重复

PROC-CONTENT-006 · DECIDED / 窗口TEST。

共享任务板的反重复发生在服务端轮换，不做每账号隐藏掉落适配。首轮只有三项Primary时，八个Offer按`3/3/2`分布，并由轮换种子决定哪项出现两次；同一Primary的多个Offer必须引用不同`ApprovedCombinationProfile`和不同`VariationSignature`。最终内容池扩大后再按批准任务数量改权重，`3/3/2`不是长期产品承诺。

生成使用确定性洗牌袋：

1. 每个Primary的批准配置进入自己的轮换袋；配置被抽出前不会在同一袋中重复；
2. 同一八Offer中，完全相同的`routeArchetype + objectiveDefinition + facilityCouplingSet`出现零次；
3. 每个Primary的四个批准配置全部抽过以前不回填；当一轮抽取跨过袋尾时，相邻轮允许出现袋重置后的最少配置复用，但同一轮不能重复同一配置，也不能把复用宣传成全新任务；
4. Secondary单独使用兼容袋，连续两轮不让同一个Primary只配同一支线；
5. 奖励、敌人数量或房间装饰不参与“已经不同”的判定；
6. 锁定Run后，轮换历史、玩家进度、队伍配置和失败重试都不能改其Seed、公开风险或奖励。

四个配置而每轮可能抽取三个，决定了相邻两轮在袋重置附近可能出现复用；声称“相邻轮零重复”在数学上不成立。该规则只把复用推迟到配置池耗尽并限制为最少，不保证某位玩家永远不见重复内容。全服共享任务板与个性化反重复互相冲突；首发选择共享匹配和可比较Seed，不建立按玩家历史偷偷改地图/掉落的第二套系统。

## 生成顺序与硬拒绝

PROC-CONTENT-007 · DECIDED。

内容层固定顺序为：

`批准组合 → 路线骨架 → 任务定义 → 必需设施 → 可选设施与耦合 → 环境局势 → Cluster绑定 → 权限与任务物 → 初始威胁/实体入口 → 主路资源保底 → 回收来源 → 支线 → 字形秘密 → 撤离 → VariationSignature与全部验证器`。

以下任一情况必须拒绝Seed或整个组合，不能静默重掷后假装内容健康：

- 七个签名字段变化不足，或承重三维全相同；
- 同一主任务在八Offer中出现近似重复；
- 任务定义与现场实体、物理痕迹、货物属性或设施主题矛盾；
- 设施系统多于六套、少于三套、没有两项真实耦合，或不同操作最终都是同一终端读条；
- 支线抢占主线唯一资源、双手携带时窗冲突、无前方重接或暗改交战合同；
- 环境局势只造成被动惩罚，没有可观察机制、选择或WorldOutput；
- RecoveryRecord来源与空间不符、三连同动作、同Cluster超过两个、主路少于8额度或任务货物被当作额度；
- 敌人超过Threat/ActiveSimulation/远程/重型任一上限，来源没有真实入口或入口关闭后继续生成；
- Blackstart三项故障同动作、Forensics无唯一作者证明、Freight故障重复或货物制造强制等待/回跑；
- 关键路径只有数学可达但相机、NavMesh、携带、敌人体型、信息或资源无法实际通过。

## 明确淘汰的假变化

PROC-CONTENT-009 · DELEGATED DECISION。

- **房皮随机：** 同一图旋转、换灯色、换箱子、换门号；只算表现变化。
- **目标改名：** “启动A/恢复B/上传C”使用同一动作和同一防守位置；合并或删除。
- **随机真相：** 取证记录按Seed决定谁说谎；禁止。
- **奖励替代设计：** 同一路线仅用更高Credits诱导重复；禁止计入多样性。
- **强制回跑凑时长：** 任务物、货物或档案必须送回插入点；禁止。
- **全程高压：** 用不停刷怪掩盖路线与设施没有区别；禁止。
- **资源彩票：** 用不可预见的弹药极值决定成败，再称每局不同；禁止。
- **玩家画像暗调：** 根据某账号近期失败偷偷增减敌人、资源或奖励；禁止。
