# 交互式现场回收与后勤额度

## 决定

普通局内支援货币不再表现为自动吸取或随身携带的散落废料。玩家通过多种短现场动作生成唯一`RecoveryRecord`；记录同时增加本局可消费的`LogisticsQuota`（玩家界面“后勤额度”）与成功撤离结算读取的`GrossRecoveryLedger`。后勤额度只支付Ammo、Medical或Tool补给投送，现场设施继续消耗实体部件、电力单元、工具和介质。

本决定只替换通用支援货币的表现和账本命名。大宗资产仍可作为任务货物经工业物流回收；弹药、医疗、部件、电力、冷却、样本、证物和数据核心仍是不同的实体资源或任务物，不全部改成下载。

## 理由

自动拾取没有玩家动作，也无法解释四名外勤人员怎样携带大量废料。全部改成终端下载又会让设施、研究、仓储和工业空间只剩一种读条。混合格式让常用回收足够快，同时保留物理物资的体积、放下、转交和任务意义；双账使玩家可以为了生存花后勤额度，而不必在“救队友”和撤离外观Credits之间做反直觉选择。

## 被拒绝的方案

- 散落废料走近自动吸取：缺少动作和携带逻辑。
- 所有价值都做数据下载：空间与奖励动作同质化。
- 长时采矿、拆解和格子背包：把高压合作任务变成搬运劳动。
- 击杀换后勤额度：形成刷怪—补弹正循环。
- 同一抽象余额同时支付设施与补给：掩盖实体世界成本，让数据凭空修门。

## 约束与重审条件

首轮参数是每局5–8个记录、10–14额度、主路至少8、标准Pod 4；DataTap约1秒，同Cluster最多两个普通回收互动，连续相同动作最多两个。它们全部是TEST，不是已平衡事实。若新手不能区分RecoveryRecord、任务证物、字形和实体部件，或玩家把回收概括成重复给终端插盘，应减少普通DataTap并增加资产标定、实体封存箱和设施条件型诊断；不得只延长读条。

该决定不授权账号付费、资产采购、实现或Credits经济数值。现行细节分别由[经济与支援](../../玩法/资源回收额度与公共物资.md)和[现场资源格式](../../内容/设施与资源/现场资源与回收交互格式.md)拥有。
