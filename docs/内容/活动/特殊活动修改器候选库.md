# 特殊活动Modifier候选库

## 使用规则

EVENT-MOD-001 · 候选内容池。

本目录不设固定数量目标，只收录能改变队伍计划的Modifier。纯粹“敌人生命提高、奖励提高”不单独成立。每项都是候选，未经过灰盒、组合、性能和可读性测试前不能进入公开活动。复杂度为初始相对成本：1是单一清楚变化，2是需要重新配装或改变路线，3是会改写整局节奏。

## 敌群与来源

| ID / 工作名 | 公开规则与玩家问题 | 代价/补偿 | 复杂度与冲突 |
|---|---|---|---|
| `MOD-SWARM-WITHOUT-HEAVIES` 轻群过载 | 禁止重型单位，把可用Threat预算换成更多轻型；仍受在场成本硬顶 | 群控与弹药效率更重要；少量后勤额度加成 | 2；互斥重型专场 |
| `MOD-HEAVY-SILENCE` 重压静默 | 大幅减少轻型来源，提高重型出现权重 | 精确破部位和控制更重要；总实体更少 | 2；互斥轻群过载 |
| `MOD-CLOSE-QUARTERS` 贴身潮 | 来源偏向近战、破阵和侧袭，减少远程 | 走位与门控更重要 | 1；不得突破重型硬顶 |
| `MOD-CROSSFIRE` 交叉火线 | 在既有少量边界内提高远程单位权重 | 掩体、屏障和压制价值上升 | 2；与“无远程”互斥 |
| `MOD-DORMANT-DENSITY` 密集休眠 | 初始休眠传播群更大，但活动来源预算不增加 | 同步清除更难，清场收益更大 | 2；不改变唤醒后持续追杀规则 |
| `MOD-DELAYED-REINFORCEMENT` 延迟迁入 | Alarm来源启动更慢，但每批更集中 | 给布防窗口，失败后压力更尖锐 | 2；必须公开批次前兆 |

## 推荐首轮组合

EVENT-MOD-002 · 受托建议 / 尚未测试。

| 活动 | Modifier | 为什么适合先测 | 主要失败风险 |
|---|---|---|---|
| 日常：轻群演算 | 轻群过载 + 工具盈余 | 清楚改变群控与工具价值 | 退化成无脑扫射 |
| 日常：主武器校验 | 主武器超驱 | 直接验证用户示例和槽位代价 | 双倍伤害让挑战反而更简单 |
| 每周：断电接管 | 全域熄灯 + 敌对安保 + 回收热潮 | 把情报、设施和贪取绑在一起 | 规则过多或接管成为唯一答案 |
| 每周：孤立行动 | 通讯封锁 + 分区协议 | 强化预先资源规划和分工 | 单人无解或资源Seed波动过大 |
| 每月：字形回声 | 地图盲区 + 字形共振 + 档案追索 | 把探索、知识和叙事组合 | 变成查攻略而不是现场推理 |

首轮不要同时启用超过一个复杂度3的Modifier。每套组合先在固定Seed验证，再过程序Seed、单人、四人、五档难度、迟加入、迁移和回滚。这里的五套只是验证组合，不是公开活动日历承诺。
