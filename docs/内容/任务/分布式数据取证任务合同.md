## 作者真相与程序变化边界

FORENSICS-CONTRACT-002 · DECIDED。

程序生成器不得创作历史真相，也不得随机决定哪一派“其实说谎”。每局先选择一个由叙事负责人批准的版本化`CaseDefinition`，其中固定：真实事件顺序、每份记录知道什么、哪份记录损坏/过期/带立场、哪些物理痕迹可以支持或反驳某项陈述、允许向玩家揭示的正史层级及结算文本键。生成器只改变证据所在的语义兼容Cluster、进入成本、可用替代证据、敌情、权限路线和支线。

一个`CaseDefinition`至少包含三类证据中的两类合法解：

1. **系统记录：** 门态、配电、身份、物流或终端事件，带本地时钟与完整性状态。
2. **独立时基：** 未联网维护机、机械计数器、隔离传感器或实体校准件，用于判断断网后时间偏移。
3. **物理现场：** 破口方向、熔蚀、尸体/设备位置、门的机械状态、被移动的货物或人工封锁痕迹。

生成时必须输出机器可验证的唯一证据证明：至少一条两类独立来源组成的主线能支持一个可封存结论；快速降级路线只允许缺失细节，不能把错误事实包装成完整真相。重要正史事实必须能在未来兼容合同中再次获得，不因单一Seed、任务失败或轮换永久错过。

## Beat Graph、提交点与失败状态

FORENSICS-CONTRACT-003 · DECIDED。

`插入并读取案件缺口 → 在预测终端定位两个候选证据域 → 从第一组替代路径取得系统记录或本地副本 → 在前方事故现场完成物理验证 → 从第二组替代路径取得独立时基或完整性校验 → 汇合到交叉验证舱 → 选择最低可信封存或继续进入补全支路 → 把档案筒送至前方上传/撤离口 → 结算`。

| 状态 | 玩家动作与原子提交 | 世界输出 | 故障与降级 |
|---|---|---|---|
| `CaseLocated` | 查询公开案号或直接读实体标识 | 标出两个候选证据Zone，不显示具体房间敌人 | 起始Terminal失效时，由实体档案路牌和本地读头提供同等最低信息 |
| `SourceARegistered` | 取出数据梭/复制维护记录并登记来源签名 | 解锁一组可比较陈述 | 载体损坏时转为部分记录；不凭空生成完整副本 |
| `SceneVerified` | 对两个以上物理锚点观察、扫描或机械复位 | 支持/反驳一项陈述并更新团队知识 | 玩家可选择只做最低两个锚点；全部锚点属于可选完整度 |
| `TimebaseRegistered` | 带回独立时基或在原位完成校准握手 | 修正事件排序，不直接宣告结论 | 设备失效时启用另一条前向证据支路；生成器须预先证明可达 |
| `CrossCheckReady` | 两类独立证据已提交 | 校验台显示可证明、冲突与仍未知三栏 | 不允许依据单一日志进入完整封存 |
| `CaseCommitted` | 操作者预览并封存案件包 | 生成唯一`VerifiedCasePacket`与完整度 | 证据只够最低结论时生成`Degraded`，明确遗漏；错误组合在提交前被解释性拒绝，不吞证据 |
| `PacketDelivered` | 档案筒进入前方上传座或由存活队员带入撤离 | Primary Resolved，开启前方撤离 | 上传中断保留已提交区块；档案筒遗失回收到最近合法已知点 |

封存后不能回到未决定状态，也不能靠重连重选奖励。可选补全支路关闭或其中证据损坏只降低完整度；最低可信结论仍可完成。全队Wipe、唯一已封存档案筒在不可恢复环境故障中被明确销毁，或玩家主动放弃行动，才产生主任务失败。档案筒毁坏必须提前有危险提示，且正常战斗伤害不能随意删除主任务。

## 空间语法与节奏

FORENSICS-CONTRACT-004 · DECIDED。

关键路径使用两次短`Branch-Rejoin`，不是要求单人清完两个平行分支：

`F00插入闸 → F01预测终端 → {F02A在线档案 / F02B离线维护副本} → F03事故现场 → {F04A隔离时基 / F04B设施完整性台} → F05交叉验证舱 → [F05O补全/字形支路] → F06前方上传与撤离`。

每对分支只要求完成其中一条，另一条提供更完整、不同风险或更低权限的替代。单人始终沿一条前向路线完成；多人可以同时侦察两条，但只有经Authority登记的证据影响结论。F02与F04的出口在下一必经Cluster前重接，支路完成后不会把玩家送回F01。F03事故现场是无文本也能读出部分事件的核心地标；其破坏方向、门态与记录陈述必须相互对应。

必需Cluster Tags为`insertion-lock、terminal-hall、research-lab、incident-scene、evidence-validation、extraction-bay`；可选为`maintenance-loop、security-control、glyph-branch、storage-grid`。使用Personnel、Maintenance、Data、Optional与至多一个Fold port；ThreatIngress只在可选安保事故存在时生成，不能藏在撤离口。关键任务物回收点只落在已清楚发现且仍可达的前向Cluster。

节奏采用“低压定位 → 第一段潜行执行 → 安静物理推理 → 第二段权限/路线压力 → 校验释放 → 可选高风险补全 → 撤离”。F05前必须存在一段无新增来源的可读缓冲，使队伍能比较证据；缓冲不是永久Safe Room，未处理的Active敌人仍可进入。

## 权限、设施系统与取舍

FORENSICS-CONTRACT-005 · DECIDED。

起始旧身份允许公共案号查询和只读低完整度日志。每个受限证据域从以下三条访问方式中实际生成至少两条：

- 绕入维护侧路，找到仍可验证的本地凭证；耗时和路线较多，但不触发安保。
- 使用一次协议重映射，在暴露位置连续提交校验；产生群组级设备声，不产生设施级事件。
- 强制覆盖直接开门，触发只覆盖当前安全域和一个相邻域的`SecurityIncident`，启动旧防御并产生区域级警报声；后续安控台可停止广播和改写设施单位，但已激活虚空兽不回眠。

每局固定通信/扫描、安保/身份、门/隔离、配电四套系统；再从照明与字形路由中选择一套。至少两项耦合必须成立：

1. 有限现场电力只能优先给证据校验、照明/扫描或安控恢复；最低证据链由固定紧急电源保障，额外完整度才竞争可选电力。
2. 高权限扫描能给出带时间戳的Zone敌人数量快照和档案完整度，却可能需要强制覆盖；维护凭证路径保静默但不给完整地图。
3. 切断安保广播会同时失去部分摄像头时间戳；玩家必须在更安全与更完整证据之间选择。
4. 字形支路只有在案件证据提供有效序列且额外门户供电时才出现，不能成为主线证据来源。

设施输出必须体现在实际门态、照明、摄像头可用性、设施单位阵营、地图快照、证据完整度或可走路线中。校验台只聚合玩家已经物理取得的事实，不从未知房间补答案。

## 潜行、敌人和可选来源

FORENSICS-CONTRACT-006 · TEST。

完整四人Standard灰盒初始目标为18–26敌人角色点，分成4–6个有限传播群；首轮使用逐能体、压射体，基础战斗通过后的设施对照可加入一台哨戒炮塔，库存见首轮支线合同；其他旧防御单位不在此对照随机替换。所有必要目标动作最高只产生群组级刺激，因此熟练队伍可以同步清除、低特征处理或绕过全部威胁并安静撤离。档案筒取得本身不唤醒敌人。

主任务没有默认IngressSource。只有玩家选择强制覆盖时，才可启用一个`ForensicsSecuritySource`：基础总预算6角色点，再应用统一难度与有效Seat倍率；来源必须从当前安保域的实体维修闸或守备机库进入，局部前兆不少于2秒。停止广播、切断该入口或预算耗尽即停止新单位；已出现设施单位和Active虚空兽仍按正常规则存在。

五档初始实体数、角色/设施组合、重型/远程比例与强制覆盖来源上限见[首轮任务难度、敌人和配装用途矩阵](首轮任务难度敌人与配装矩阵.md)。更高难度仍不得给本任务添加默认来源，也不得改变`CaseDefinition`真相或最低可信证明。

如果程序Seed无法提供至少一条不触发`SecurityIncident`的完整主线路径，生成器必须拒绝该Seed，因为那会违反“全程潜行可行”。玩家自己失误唤醒敌人不导致任务失败，也不改变案件真相；战斗只改变资源、时间、路线和档案筒完整性风险。

## 资源、携带与合作语义

FORENSICS-CONTRACT-007 · TEST。

最低可信证据链不消耗LogisticsQuota或可选电力单元。完整度路线可以消耗一枚额外电力单元、一次协议工具或一处可选安控恢复机会。完整原型保证一处主路Ammo容器、一处主路Medical容器、一处可选Tool容器（单位见经济合同；Ammo放在首个证据域之后的前向公共路线，Medical放在封存前可达工位，不藏在强制覆盖后）和至少8点主路RecoveryRecord额度；无限探索区允许把更多价值放在高价值回收记录、字形与资料，不能把必要战斗资源乘到零。普通DataTap必须标明为工程/设施回收数据，不能被案件系统误认成证据，也不能用同一次互动同时完成案件链和领取普通回收额度。

系统记录与时基在登记后成为团队知识，不要求手搬到终点。最终`ArchiveCanister`是可放下、转交、越界回收的双手物件，从F05到F06只经过一个前向Cluster；携带不降低走、跑、跳跃或翻越速度，但切枪前必须放下。F05提供一次封存，因此不会与多个介质形成搬运清单。

单人顺序完成两次“择一路径”与现场验证；多人可分头侦察替代证据、控制门和观察现场，但不能在没有共享证据的情况下各自提交不同真相。第一个合法封存提交赢得同一ResultID，其余陈旧预览被拒绝并显示新状态。断线时未登记介质落地，已登记事实保留；迟加入者读取当前证据表和来源，不重新获得一次性记录。Host Migration恢复CaseDefinition版本、已登记证据、物理锚点、权限、安保状态、档案筒与唯一奖励凭据。

## 结算、支线接口与验收

FORENSICS-CONTRACT-008 · TEST。

主结果按“最低可信 / 完整验证 / 主任务失败”结算，不用隐藏分数冒充真假。完整验证增加Archive上下文、字形记录资格或Credits依据，但不能给纵向战力。统计至少记录：候选路径、每份证据来源与完整性、物理锚点、冲突被排除的依据、强制覆盖/协议重映射、终端停留和队友等待、档案筒携带/掉落/上传、潜行破坏、敌人来源、资源账、案件完整度、撤离/Wipe。战报只使用作者提供的结算文本键，不让生成式系统编造历史总结。

首轮优先兼容`side/glyph-cache`；与辅助防御接管和黑匣子的条件见[首轮支线合同与兼容矩阵](首轮支线合同与兼容矩阵.md)。字形暗仓只能由案件中的额外证据提示，不提供最低主线证据，也不能要求固定Wiki序列。

Seed streams分离为`case-definition / topology / evidence-alternatives / physical-anchors / permissions / facility-coupling / initial-threats / resources / optional / rewards`。生成器硬拒绝：没有两类独立证据；证据位于需要它自己开启的门后；所有权限路径都会触发警报；物理现场与作者事实矛盾；主线依赖秘密字形；两个替代分支都成为必经；档案筒需原路送回；可选支线无重接；任务结论无机器证明。

首轮四种路线骨架、五项本地`CaseDefinition`候选、环境局势、回收来源和批准配置规模由[首轮程序任务内容池与重复可玩性矩阵](首轮程序任务内容与重复可玩性矩阵.md)统一拥有。案件候选进入内容包前仍需叙事负责人批准最终文本和公开层级；生成器不能改真相。

每个CaseDefinition先通过正常、最低可信、完整验证、强制覆盖、证据载体损坏、档案筒越界、资源耗尽、单人、四人并发、断线和Host Migration固定测试。程序阶段至少1000 Seed自动验证，批准组合至少20 Seed结构检查并人工完整游玩5 Seed；记录错误结论率、迷路、队友等待、文本停留、安静完成率和玩家能否复述“哪项证据证明了什么”。当前没有玩法、叙事理解、性能或乐趣测试结果。
