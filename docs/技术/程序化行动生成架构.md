# 程序Operation生成、种子与验证架构

## 单一责任与生成边界

PCG-001 · DECIDED。

生成系统分成共享任务图与当局实例两层。服务端任务图从已批准的区域、设施、任务和公开奖励规则生成同一轮八个`MissionOffer`；队伍锁定其中一个后，Authority再从已批准的Cluster、设施系统、敌人Source、秘密与奖励表组合`MissionInstance`。它不创作任务规则、不修改内容定义、不动态照顾玩家Build，也不把无解地图交给玩家。生成先写入纯数据图并完成验证，最后才实例化Unity场景对象；场景`Awake`、PhysX结果、客户端时间和全局Random不得参与内容选择。

## 确定性种子树

PCG-002 · DECIDED。

`OfferRotationSeed/OfferRevision`定义全服共享的八份合同，`MissionSeed`定义队伍锁定后的具体实例；两者与game build、ruleset、content package lock一起写入RunManifest。每个生成阶段用语义路径独立派生子种子：`board/offer`、`region`、`site`、`primary`、`secondary`、`facility-system`、`coupling`、`graph`、`clearance`、`objective-placement`、`resource`、`initial-enemy`、`alarm-source`、`node-source`、`ambient`、`glyph-secret`。新增一个装饰随机调用不能改变任务物或敌人位置；禁止共享一个顺序敏感的全局RNG。

同一Manifest必须得到相同逻辑MissionInstance、稳定InstanceID和验证摘要。表现性散布可有独立种子，但不能阻挡导航、遮挡交互或改变权威掩体。哈希算法和字段规范作为Protocol版本的一部分固定，升级后不假装旧Seed在新内容包下生成同一地图。

## 生成管线

PCG-003 · DECIDED。

共享Offer阶段依次为：`RotationSeed/Revision → 八个互相可区分的Region/Facility/Primary组合 → compatible Secondary → 公开交战合同/已知环境/奖励/预计长度 → Offer验证 → Published MissionBoard`。当局阶段依次为：`Locked Offer → MissionSeed → FacilitySystemSet(3–6) → CouplingGraph(至少2项) → Situation/Mutator → Cluster Graph → Port binding → Clearance paths → Objective placement → Required resources → Optional rewards → Initial finite enemies → optional Alarm/Node Sources → Glyph secret candidates → Navigation/visibility metadata → Validators → Frozen MissionInstance`。

每一步只读取前一步冻结结果与自己的内容表，并输出带revision的纯数据。失败包含阶段、规则、内容ID和Seed。轮换发布前必须凑齐八个已验证Offer；单个候选最多尝试32个派生Seed TEST，超限后拒绝该候选并从已验证的不同组合继续选取，不能把坏卡发布后再让不同客户端各自替换。锁定Offer的MissionInstance只能使用已锁定的种子与内容版本；实例验证失败则拒绝开局、保留失败输入并报告内容错误，不静默删目标、改公开合同或把资源塞到玩家脚下。CI或内容Cook出现稳定高拒绝率时阻止发布相关组合。

## Cluster Graph与端口绑定

PCG-004 · DECIDED。

先生成房间级有向多图，再选择满足端口类型、尺寸、方向、区域套件和任务Tag的Cluster变体。关键路径使用`Forward → Branch → Rejoin`，至少一个可解主路径；Optional支路长度、回接和风险受模板约束。连接后验证实体空间不重叠、所有行走/货运/维护/Fold端口相容、门两侧NavMesh链接存在、声学区和ThreatIngress归属明确。

图算法只证明结构，节奏由任务Beat约束：Introduce、Commit、Release、Escalate、Climax、Exit映射到可达Cluster，并保证已处理威胁且无合法新增来源时可以真实结束战斗。生成器不能为满足时长插入无任务、无信息、无风险选择的空走廊。

PCG-010 · DECIDED · 来源：SRC-USER-2026-09-05-FACILITY-MANIPULATION-AND-CARRY；设计合同见[任务MIS-021](../玩法/任务语法空间生成与可解性.md)。

`FacilitySystemSet`只能从FacilityTheme兼容池选择三至六套主导系统。每套定义必须提供实体操作点、输入资源/权限、WorldOutput、FailureState、AlarmScope、兼容Cluster/Port和可观察反馈。`CouplingGraph`至少连接两项竞争关系，例如扫描与炮塔争电、节点与Energy端口争冷却、电力单元在安全闸与字形门户间竞争；没有跨系统取舍的独立开关不能占主要设施槽。

生成器先算主线保底，再分配可选设施预算。主目标需要的电力单元、权限、搬运路径和返回路线必须在不取得最高权限、不进入秘密节点的情况下成立；额外电力单元、可拆部件、冷却、RecoveryRecord和权限收益才可用于资源仓、捷径、防御、扫描、补给接收与秘密路由。双手搬运路径按完整走/跑/跳跃/翻越速度验证，但沿途必须允许物件合法放下、拾回且不与Resource Pack槽混淆。

环境差异必须改变计划。`MissionFingerprint`纳入FacilitySystemSet、CouplingGraph、ClearancePath、Power/Cooling allocation、Transit state、Alarm/Node ingress和GlyphSecret条件；仅移动发电机、旋转房间、更换材质或延长走廊不计新体验。高权限只生成当前Site声明的能力子集；生命扫描为有时间戳的Zone数量/大型信号快照，不生成实时精确敌人位置。

## 目标、资源与敌人布置

PCG-005 · DECIDED。

目标物放置使用显式约束求解：前置物不能在自己解锁的门后，多个模板不能争用唯一实例，任务物必须能被合法携带到目标，损坏/丢失有已设计降级。资源预算对每条批准主路径计算保证供给、必要设施成本、代表性战斗消耗和安全余量；标准枪械世界补给统一为Ammo，再由实际配装的武器效率换算，不能生成队伍无人可用的弹种。每个Seat最多持有一个Resource Pack，任务物/电力单元使用独立双手状态。具体数值来自测试Profile，不因玩家表现实时改变掉落。

敌人先锁定有限的休眠个体和设施守卫；没有本地警报或设施主节点启动时，MissionInstance的敌人总量只能减少。只有任务合同公开的AlarmSource或NodeSource可持有额外有限Budget与Ingress；每个Source要有生态/设施理由、Telegraph、合法入口、作用域和结束条件，封闭全部入口后不能补怪。节点启动默认只激活目标房与合同列出的连接Zone，不全图唤醒。

字形秘密候选与额外威胁、电力/电力单元、校验、时间和返回路线在同一生成事务验证。候选必须匹配玩家可能拥有或当局能够完整发现的字形知识，永久已知地址仍可要求Site兼容与本地校验；主线、必要资源和核心公共事实不能依赖秘密、单一Seed或限时Offer。每个RecoveryRecord与字形记录生成唯一凭据，局内使用不回退成功撤离CreditBasis，也不能重复登记。DataTap只能落在数据端口，AssetSurvey只能绑定可见大型资产，DiagnosticExtract必须有合法设施前置；同一Cluster最多两个普通回收互动，连续相同动作最多两个。

## 验证器集合

PCG-006 · DECIDED。

| 验证器 | 必须证明 | 拒绝示例 |
|---|---|---|
| Schema/Package | 所有ID、版本、依赖与能力合法 | 缺定义、旧hash、禁止能力 |
| Topology | 插入到主目标/撤离可达，端口相容 | 孤岛、重叠、死端关键路径 |
| Objective FSM | 至少一条事件序列到Resolved/合法Degraded | 目标互锁、重复完成 |
| Resource Safety | 必需资源与任务物守恒 | Cell在需该Cell的门后 |
| Facility Systems | 三至六套兼容主导系统、至少两项真实耦合、操作产生WorldOutput | 全能高权限、不同名字同一读条、发电机位置变化冒充新局 |
| Seat/Loadout | 1–4任意角色Seat、合法首发配装可完成 | 要求某角色/Staff/强制Bot |
| Navigation | 玩家、常规敌人、特殊体型与不降速双手搬运路径成立 | 敌人只能穿墙抵达、物件无合法放下/拾回点 |
| Encounter | 初始数量固定；Alarm/Node Source、Ingress、预算、预兆、作用域和结束成立 | 普通状态补怪、节点默认全图唤醒、封门后凭空spawn |
| Economy Ledger | Ammo换算、Resource Pack、LogisticsQuota/GrossRecoveryLedger、RecoveryRecord与字形唯一凭据守恒 | 自动吸取废料、局内花额度扣成功Credits、返费刷CreditBasis、重复记录/字形发奖 |
| Pacing | 危险有可识别预兆，操作说明和成本在不可逆提交前可查；存在高低压与高潮前准备 | 无预兆惩罚、隐藏承诺成本、连续全程高压 |
| Secret/Narrative | 字形证据、门户兼容、本地校验、代价与返回成立；核心事实不永久错过 | 盲猜Glyph、固定无风险宝箱、唯一故事只在稀有Seed |
| Performance Budget | Cluster/灯光/AI/物件在静态预算内 | 已知超预算仍Cook |

验证通过后写`MissionDigest`并冻结。客户端加入只接收权威MissionInstance/必要表现数据，不自行重新Roll；本地重建摘要不符则拒绝进入。

节奏验证检查内容提供了什么线索和操作机会，不检查玩家是否读过教程。[ONB-007](../玩法/新手教学首局与长期学习.md)的个人学习记录不进入生成输入、难度派生或Seed；不同熟练度组队仍共用同一实例。可选训练使用独立夹具，不复制正式待出发地图作为免费侦察，不向正式Run导出物资或完成事件。

## Authoring、Cook与诊断

PCG-007 · DECIDED。

内容作者通过JSON/Graph定义约束，CLI可执行`validate definition`、`generate seed`、`sweep seeds`、`render graph summary`和`explain rejection`。Unity Editor仅预览和摆放Cluster表现；关键端口、任务与资源合同必须可从文本检查。失败报告包含Seed、阶段、相关ID、最小冲突集合、图摘要和复现命令，不只显示“Generation failed”。

每日内容CI对每个主任务、区域和支线组合进行固定回归Seed与随机分层Seed扫描；失败Seed进入夹具。通过自动验证仍需人工评审路线、迷路、重复和节奏，因为连通图不能证明好玩。

## 网络、重连与版本

PCG-008 · DECIDED。

只有Authority创建MissionInstance；锁定后地图、目标、奖励与Source不因加入、离队、难度窥探、失败重试或Host迁移重Roll。恢复记录保存Frozen graph、实例、RNG子流状态和Digest，不依赖重新执行当前版本生成器。难度在RunStart前进入Manifest并影响公开Profile，不修改已经批准的任务事实。

## 验收与未证明项

PCG-009 · TEST。

每个合法组合至少自动扫1000个Seed，零崩溃、零无限循环、零无提示软锁、零非确定摘要；轮换中所有客户端必须得到同一八Offer与Revision，已锁定Run不受下一轮影响。每组人工评审20个Seed，确认路线、设施耦合、权限、资源、回收动作、敌人/入口和秘密条件确实改变计划，而非装饰变化。验证普通状态实体总量只减、警报/节点来源不超过总ThreatBudget或在场成本/远程上限、节点作用域不越界；回收总量10–14额度、主路至少8、每Cluster密度与动作重复符合内容合同；Host迁移前后MissionDigest、经济总账和所有实例ID一致。所有结果当前为NOT RUN。

## 批准组合、变体签名与轮换袋

PCG-011 · DECIDED / TEST NOT RUN · 内容池见[首轮程序任务内容与重复可玩性矩阵](../内容/任务/首轮程序任务内容与重复可玩性矩阵.md)。

Authority只能从版本化`ApprovedCombinationProfile`生成MissionInstance。Profile冻结路线骨架、任务定义、允许的设施/局势/支线和关键约束；Seed在其内部选择兼容Cluster、落点、敌人、入口与资源。未经批准的理论组合不参与运行时抽取，也不得用自动重掷掩盖高拒绝率。

每个实例输出七维`VariationSignature`：路线、任务定义、设施耦合、环境响应、敌人/入口、支线和回收来源。同一Primary要算可区分，承重三维至少一项不同且总计至少三项不同；表现种子、奖励数字与敌人数微调不计。验证器把签名、MissionDigest和拒绝原因一起写入Manifest与诊断。

共享八Offer使用由`OfferRotationSeed/Revision`驱动的确定性洗牌袋，不读取账号近期成败、配装或消费历史。首轮三Primary按3/3/2分布，同一Primary在一轮内引用不同批准配置；四个配置全部抽过前不回填。抽取跨越袋尾时允许相邻轮出现袋重置后的最少复用，但同轮仍不得重复，也不得把复用记作新内容。批准池不足以生成当轮内部差异时减少该Primary权重或阻止发布，不能伪造差异。锁定Run不受袋状态或下轮刷新影响。
