# 玩家、配装与输入

## 玩家目的

从第一局就能移动、射击、切出专用近战、快速推击、使用工具和救人；角色提供身份，玩家不必先招齐固定职业才能开始。

## 范围与术语

Primary与Secondary是系统能力完全平等、仅以固定合法目录区分的两个枪械槽；Dedicated Melee是独立近战平台；Quick Melee是持枪推击；Tool是有限资源的团队工具；Personal Utility是自由选择的个人战术动作；Ping只表达沟通意图。资源见[经济](资源回收额度与公共物资.md)，伤害见[战斗](战斗与武器家族.md)，完整候选见[装备候选库](../内容/装备/装备完整候选库与首发筛选.md)，UI见[可访问性](../表现与资产/界面信息与可访问性.md)。

## 已确认规则

PLY-001 · DECIDED · 来源：当前产品基线；历史见Git。

官方Operation入场固定一把Primary、一把Secondary、一把专用近战、一件团队Tool和一件自由选择的Personal Utility，另有Quick Melee、手电、Ping。四名固定角色同局不重复Seat、行动内不换身份；装备可重复。人物只固定叙事/视听身份，不锁职业能力。武器与工具身份在Run中稳定，通过明确挂点改装而非彩色等级换枪；世界Team Ordnance独立，不是免费第三把随身枪。

PLY-002 · DECIDED · 来源：当前产品基线；历史见Git。

保留手电、Sprint、Jump/Crouch/Slide/Mantle/Air Control与Quick Melee lunge，无全局体力税。Gun点R执行真实Reload/Cycle；只有实际具有上下文动作才长按R显示轮盘。Operation不显示Staff/Spell入口。移动、输入缓冲和取消初值见[测试参数](../制作/初始测试参数.md)，阶段提交不随渲染FPS变化。

PLY-003 · DECIDED · 来源：当前产品基线；历史见Git。

键盘默认1/2切枪、3切专用近战、4选择/使用工具、5个人战术模块，E交互、Q语义Ping、R换弹、F手电、V快速近战；所有键可重绑并进行冲突检查。控制器默认Y点按切枪、长按切出/收起专用近战，工具与战术动作使用独立语义映射；长按方案必须允许拆分重绑，并在首轮测试检查误切。模块需新动作/战场解法/效果连接至少满足两项，不能成为主任务必带钥匙。

PLY-004 · CANON · 来源：SRC-SSOT-2.0 §8.2、§8.4、§37。

手持生命探测器属于个人战术装置，可无限重复近距隔墙探测，显示逐渐变淡消失的点状信号，不描怪物轮廓、不加伤害或承伤倍率、不揭秘密；Ping不附加扫描。具体点标与资源合同归个人装置目录。其他消耗型个人装置使用有限耗材或预充电量，独立冷却只约束使用节奏，不凭等待恢复消耗次数。普通 Healing 不能自动 Revive，须有明确 ReviveEffect。

## 玩家流程

PLY-005 · DECIDED · 来源：当前产品基线；历史见Git。

选角色与Primary/Secondary/专用近战/团队工具/个人Utility→查看资源成本与声学职责→进入任务→实际遇到时学习潜行、工具、救援、支援和改装。改装显示收益、代价、冲突与拆出物去向；取消不消耗，原子提交后才改变装备。不教授首发不存在的法术轮盘或自动Fusion。

## 状态与所有权

PLY-006 · DECIDED · 来源：本轮系统扩写。

Authority 拥有 CharacterLock、LoadoutRevision、装备 InstanceID、动作阶段、当前合法姿态；Client 拥有绑定、轮盘焦点、镜头偏好。动作命令携带 player、sequence、instance、input phase；权威检查角色存活/允许动作/物品仍装备后提交。UI选择不直接改装备。

| 起点 | 事件/前置 | 结果 |
|---|---|---|
| Ready | 按下攻击，装备合法 | 枪械按自身模式起手；专用近战进入蓄力，松开才出手；即时本地输入反馈 |
| Windup/Reload | 被允许的取消动作 | 保存已完成阶段，进入新动作 |
| Ready | 长按上下文且存在候选 | RadialOpen；模拟继续 |
| RadialOpen | 松开且候选仍合法 | 提交选择；否则维持原选择并解释 |
| 任意可行动状态 | FatalEvent | 转生命系统，取消未提交动作 |
| Connected | 断线/接管 | 保留角色与配装，不生成新实例 |

## 模式配置与内容接口

PLY-007 · DECIDED · 来源：当前产品基线；历史见Git。

动作语义由共享系统实现，资源与允许内容由规则集控制。Character卡不声明独占Signature；PersonalUtility卡独立声明verb、目标、成本/冷却、动作阶段和禁止场景。Tool与Personal Utility资源分账。序列化保存CharacterID和PersonalUtilityID为两个字段，不保留绑定与自由选择两套逻辑。

## 边界

PLY-008 · DECIDED · 来源：当前产品基线；历史见Git。

抢取世界物按首次合法事务提交，失败者不丢原物。死亡取消未提交切换，已发弹保留。拆下/dormant修改不监听新事件；轮盘目标失效时取消并解释，不能暗选另一个动作。重连以当前权威装备重建，不以客户端缓存覆盖；所有合法Seat组合均可完成主任务。

## 专用近战输入与可访问替代

PLY-MELEE-INPUT · 所有者CANON：左键按住蓄力、任意时刻松开攻击、蓄力中右键取消；控制器映射与边界受托DECIDED。时序见[近战合同](../内容/装备/首轮近战攻击与资源合同.md)。

左键按下只开始准备，不立刻造成伤害；松开提交一次攻击，短按也是有效攻击，没有最低蓄力失败门槛。按住达到满蓄后仍等待玩家松开，不自动出手、不自动连续攻击。近战持用时右键/LT是取消，不是ADS；R不承担取消或虚构换弹，控制器X保留合法交互用途。

取消优先于同一Tick的释放。取消后即使左键仍按住也不自动重新蓄力，随后松开不得出刀；须先松开，再重新按下。枪械切入时同样不能把尚未松开的近战攻击键解释为自动开火。切换设备、窗口失焦和打开菜单取消尚未释放的准备；在线模拟继续。已释放的动作不能用右键撤回已提交的攻击或返还恢复时间。

切换式替代使用同一个攻击动作：第一次按下开始准备，第二次按下提交，取消动作撤销；时间、伤害与恢复和按住方式相同。无需快速双击或持续握住扳机也可操作，但不得提供自动满蓄释放或额外射速。动作重绑与设备提示由语义键`input.melee.attack / input.melee.cancel`驱动；状态键`hud.melee.charging / hud.melee.ready / hud.melee.recovering`显示“准备中 / 已就绪 / 收招中”。提示不得硬编码鼠标图标。

关键反馈以武器姿态、简洁进度/形状变化与声音表达；不要求震屏、镜头晃动或运动模糊。所有动作按[全动作手感验收](../表现与资产/全动作手感与舒适性验收.md)执行。没有打包界面、伪本地化截图或手柄测试，不宣称可访问性已验收。
