# 游戏内Mod Manager：页面、状态与玩家流程

MODUI-001 · DECIDED。使用游戏内一个统一入口，不要求玩家安装外部管理器。鼠标键盘和控制器均能完成安装、组包、加入同步、失败恢复及诊断；后台下载不夺走游戏内危险场景的焦点。

## 页面责任

| 页面 | 玩家能做什么 | 必须看见的状态 |
|---|---|---|
| 我的内容 | 查看已安装/已订阅；启用/停用；按作者/类型/更新筛选 | 订阅≠已下载≠已验证≠当前启用；官方/社区来源与磁盘占用 |
| 浏览Workshop | 搜索、打开详情、订阅；必要时打开Steam Overlay | 依赖、兼容游戏/SDK版本、大小、权限类别、来源与报告入口 |
| Profile | 创建/复制/改名/删除命名配置，验证依赖，一次应用 | 当前profile与待应用差异；活动Run锁定状态 |
| 加入同步 | 一次确认支持内容的自动同步；取消；重试 | Host所需hash、下载进度、总大小、缺包/不支持能力、无需逐项手装 |
| 下载与缓存 | 暂停可暂停任务、重试、查看空间、清理未引用缓存 | 活跃/挂起Run引用不可误删；预计回收空间 |
| 诊断与帮助 | 查看定位到包和字段的错误，复制/导出脱敏报告 | 游戏/SDK版本、错误码、所需动作；不展示密钥和账号票据 |

## 关键流程

MODUI-002 · DECIDED。

从主菜单进入Mods，选profile并验证；只有没有活跃Run时可改变Gameplay包。进入朋友房时比较Host锁：全匹配直接准备；缺包进入汇总同步页；存在不支持脚本或冲突则阻止加入并解释。下载成功仍需校验和激活，界面不能在100%网络下载时就显示Ready。

取消同步保持原profile和订阅偏好；部分下载可保留为不可激活staging以便重试。依赖的自动选择在确认页可见，删除被其他包依赖的项目要列出影响。加载顺序由依赖图和稳定排序得出，不用任意拖动来“解决”定义冲突。多人房只修改本次session profile，不永久覆盖个人默认组合。

## 错误与无障碍

MODUI-003 · DECIDED。

至少区分：Steam离线、下载失败、磁盘不足、hash不符、依赖缺失、循环/定义冲突、SDK不兼容、旧hash不可获取、禁止的脚本/组件、正在使用不能删除、权限受限。每种错误有中文/英文短解释、具体包/版本、可执行修复按钮及返回路径；禁止只显示堆栈或“Unknown error”。

状态不只靠红绿区分；进度具备文本与可读焦点标签；详情长文可滚动而不丢失返回焦点；高风险确认默认不在“删除”上。重启后恢复下载队列和profile，不自动恢复未获同意的能力升级。关闭声音也能知道成功/失败。

## 验收

MODUI-004 · TEST。8名新玩家中至少7人无口头指导完成：加入两个缺失安全包的房间、识别一个被禁止的脚本包、取消后保留原profile、找到旧hash缺失原因、在控制器上导出诊断；无误删除、半激活、偷偷执行代码或隐藏下载。超过15秒仍无法理解的错误由UX重写，不让玩家学习底层包管理概念。
