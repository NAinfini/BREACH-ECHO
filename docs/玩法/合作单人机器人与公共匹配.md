# 合作、单人、Bots 与公共匹配

## 玩家目的与范围

每个人都能对局势有用，不开麦也能完成必要合作。固定好友队通过不能证明随机匹配和单人成立。

COP-001 · CANON · 来源：SRC-SSOT-2.0 §20.1–§20.3。

Bots可选默认OFF，单人无Bot可独立玩，最多0–3 AI队友；使用同样角色、武器、弹药、倒地规则，无隐藏无限资源。Human join可替代Bot slot。Bots不做Glyph/Forbidden/Gamble/Fusion/唯一团队资源的最终战略选择，不自主浪费稀缺物资。命令含Stay Here、On Me、Defend Here、Take this、Use Tool/处理Ping对象；真人全倒可打破Stay去救人。

COP-002 · CANON · 来源：SRC-SSOT-2.0 §19.6、§20.3、§20.5、§37、§40。

Public语音可用且默认Push-to-Talk；Global Team Voice不因房间/距离失声，非proximity-only；Party/Team成员相同可合并。语音独立于gameplay authority，迁移不应切断。Ping纯沟通，Quick Chat用Need Ammo/Healing/Group Up/Wait/Ready/Thanks/Sorry/Enemy/Go Here等semantic intent；Text默认Team/Party。无默认长期raw voice录制，沟通不暂停在线模拟。同一局四名固定角色的Seat不可重复，但武器与Build可以重复；物资公共，draft规则归经济。

COP-003 · DECIDED · 来源：SRC-SSOT-2.0 §20.4。

颗粒度mute/block、Recent Players；公开Vote Kick且NetworkHost无单方owner kick，Private owner可移除私局玩家。AFK先警告、可接管/保护、投票/admin移除，不因轻微AFK永久惩罚。最小留存；Host可靠性与社会信用分开。

## 内容接口与边界

### Ping与请求：指出意图，不替人执行

COP-FIELD-PING · 2026-09-07受托DECIDED，寿命/限频为TEST；来源SRC-USER-FIELD-COLLABORATION。复用COP-002的Ping和Quick Chat，不增加战术指挥模式、自动分工或同步攻击计时器。

| 玩家主动动作 | 团队收到的信息 | 不获得的能力 |
|---|---|---|
| 指向已知地面、门或设备并Ping | 发起人、位置/对象及已有合法信息；可用共同区域名和上下层关系 | 不是寻路答案，不预测门后兵力或替人开门 |
| 对可见敌人/有效探测点Ping | 发起人关注这个已知目标；敌人仍只以简洁点标表达 | 不增加扫描、轮廓、弱点、伤害或有效追踪寿命 |
| 从终端/地图结果标目标 | 原记录允许的Zone/物件位置及来源时间 | Zone级结果不变成精确坐标，旧扫描不变实时 |
| 选择等待/集合/准备/物资请求 | 显式语义、请求人和玩家选择的合法对象；没有目标时不暗选最近队友 | 不要求响应，不指定最优装备，不替队友同意或预约物资 |
| 主动回应“收到” | 已读该请求，不是承诺执行 | 不产生掩护、救援或装备使用动作 |
| 主动回应“我来”或真实开始相关行动 | 前者只记录本人意图；后者可记录“正在操作/救援” | 不是任务分配锁，不移动真人或提前报成功 |
| 撤回自己的标记/请求 | 移除自己的意图与回应关联 | 不撤销别人已提交的动作或删掉团队合法知识 |

敌人Ping只指向标记当时有合法知识的对象。持续可见时可更新可知位置；失去目视且没有有效探测授权后，最多留下当时最后确认位置，不继续跟随隐藏实体。来源是有效探测点时，只在该点剩余寿命内跟随，到期移除关联敌人点；重复Ping或“收到”不能续期。玩家可在已知地图放普通位置标记，但它不自称那里仍有敌人。被遮挡且未知的对象不能通过反复Ping试出目标名。

默认每名真人只保留一个主动空间Ping和一个无空间请求；新合法提交替换自己的旧项，不删队友标记。空间Ping与请求8秒后结束，同对象同语义重复只更新原项，不堆叠；普通主动更新最短间隔1秒，不延长信息来源的有效期。值是初始TEST，不是对白时长或探测寿命。多人指同一对象合并空间符号并保留发起人列表，各自到期/撤回；地图里手动追踪的一个已知静态目标可保持至取消/完成，但不能拿这个入口固定隐藏敌人的实时位置。

拒绝/限频只在发起者本地给轻量反馈；不向全队广播“某人操作太快”。新出现的合法迫近危险、真实倒地、警报或设备故障是系统事实，不受主动Ping数量和限频约束。人物语音仍独立按[NDL-CONTEXTUAL-CALLOUTS](../世界与叙事/叙事交付对白与本地化.md)去重与限频，不能把文字刷新当成再播语音的许可。

回应绑定具体请求及版本；请求已结束、目标失效或被替换后不补发旧“我来”。没有回应不显示“拒绝配合”或催促计数。多人愿意处理同一目标可以共存，系统不挑一个赢家；实际动作仍走原资源/交互事务。Bot只有明确收到合法Bot命令才执行，普通Ping/“收到”不变成Bot代花资源；执行失败应说明实际限制，不能先答应再假装完成。

玩家可按成员屏蔽其主动标记/Quick Chat/声音，不隐藏由权威状态生成的倒地、设备后果或警报；关闭人物语音不关闭文字请求。发送者只知道请求已合法发出，不获知别人是否静音。1人无Bot时不制造假回应，Bot默认关闭不因求援自动生成。断线/接管不由新控制者继承旧人的“我来”承诺；重连只显示仍有效事实和标记，不重播过期请求。

COP-005 · DECIDED · 来源：本轮系统扩写。

任务动作声明所需并发人数；官方主线必须有单人顺序解法。Bot只执行可验证的局部移动、射击、救援与明确工具指令，不规划最佳Cart、替玩家探索秘密或自动做战略经济。关键动作必须有non-voice表达：请求等候/集合/物资、提议路线、解释已提交配置、标记可接管资产。

抢拾取和并发花费归[经济](资源回收额度与公共物资.md)；Cart失误归[世界](设施信息与控制规则.md)；Team Ordnance归[战斗](战斗与武器家族.md)。离队/被踢不能删除已提交世界后果。Public不能让网络Host获得资源优先。恶意反复丢关键物、耗Support仍可能伤害队伍，UI日志不足以保证解决，列入风险Gate。

## 撤离扫描附近的入场与重连

COP-END-ADMISSION · 受托DECIDED。第一次合法撤离扫描产生进度时，关闭本Run的新匹配/新补位准入；暂停扫描不重新开放。此前已入场成员的合法重连仍可进行，继承原身体、库存、位置和资格，不把Downed/Out重置成Alive。尚在下载或等待首次身体接管的加入者若未在关门事务前完成入场，只能留在房间等下一局，界面明确说明，不收费、不替换既有身体，也不补发本局奖励。

扫描状态、准入关闭和Seat控制版本随恢复证书保存。终局后返回者只读取本人合法结果/claim及当前小队状态，不恢复旧世界。明确离队者按参与区间截止，断线保留期限沿COP-009；两者都不因房主交接变成额外奖励Seat。新一局全体重新Ready后才开放新的入场周期。公开移除权限不变，房主不能靠踢人改变已经提交的结果。

## 单人独立完成与机器人分工

COP-SOLO-PATH · 2026-09-07受托DECIDED；来源SRC-USER-SOLO-BOT-COLLABORATION。单人是完整参与方式，不是四人任务缺三个操作者。这里的Bot是由AI控制的一名外勤员，沿用同一角色Seat，不是新机器人种族、额外第五人或职业；可接管的设施机器人另归设施系统。

无Bot主路必须具有一份逐动作见证：走到哪里、手里拿什么、在哪里放下、怎样腾手、动作完成后哪项状态保持、下一处怎样到达。所有必要操作可由同一人先后完成；远处持续按住开关、两地同时确认、必须另一人看终端解锁本人的门均不进入官方主路。多人可以更快分工，但不新增只有多人才能取得的必要权限。全部合法配装要查能力依赖，不代表每套配装在最高难或任意浪费后都保证通关。

三任务的具体顺序见各自单人段：[黑启动](../内容/任务/换流器黑启动任务合同与灰盒规格.md#单人动作见证)、[取证](../内容/任务/分布式数据取证任务合同.md#单人动作见证)、[货运](../内容/任务/货运线夺回任务合同.md#单人动作见证)。关键物放下不丢进度、恢复设备不需要人一直守台、扫描可暂停，才能让一个人实际有时间开枪；安全来自真实清线和空间，不来自单人无敌或敌人暂停。

COP-BOT-ROSTER · 受托DECIDED。Bot数量、角色、配装及断线接管许可在局前明示，变更清除Ready；采用既有房间配置提交权限，公开房的网络Host没有额外战斗权限。Bot只用同一合法装备目录和公开活动规则，不自动优化队伍配装，也不借用不在当前合法池内的道具。人数与资源规模按已锁有效Seat计算，Bot转真人不增加人数。

Run中不能通过添加、删除或重建Bot获得新身体和入场库存；启用过Bot的会话，只允许按既有许可控制现存身体。没有合法空身体时等待下一局，不用空角色名额生成满血援军。断线接管不等于AFK后自动花费关键资源，关闭Bot的单人局也不会因倒地临时出现救星。

## 机器人命令与战斗边界

COP-BOT-COMMANDS · 受托DECIDED。命令必须显式选择Bot和已知对象/位置；普通Ping仍只传递意图。任一仍连接的真人可发局部命令，没有另设指挥职业；每个Bot只保留一条当前任务，不建立跨图自动工作清单。新命令可以明确替换旧命令，已产生的世界后果不能撤回。

| 命令 | Bot实际执行 | 限制与失败处理 |
|---|---|---|
| 跟随 | 沿合法人员路线跟随指定队友，避让其枪口、门口与操作位 | 不穿门、传送或读取未知捷径；道路封闭时停在可达处并说明阻隔 |
| 留在这里 / 守住这里 | 在指定可达位置附近避险、守已知接近线 | 不守点到站进喷流；短暂躲避后返回，不能自行扩成清下一间房 |
| 停火 / 恢复开火 | 停火禁止主动枪械、投掷和爆炸；恢复后可攻击合法感知到的Active威胁 | 停火不自动解除；可近战自卫、躲避或救援，不能背着玩家开枪“保护潜行” |
| 攻击这个目标 | 对合法已知目标执行一次明确攻击；休眠目标只接受这种主动授权 | 目标丢失、友军挡线或射界不成立便等待/失败，不转打另一只休眠体；不自动同步全队蓄力或替玩家判断传播群 |
| 拿取 / 放下 / 搬到这里 | 取指定可携物并送到已知可达落位，保留实体与余量 | 遵守单包及双手限制；不默认安装、消耗、上传或选择配电；不能自动搜刮附近物件 |
| 使用工具 / 补给此人 | 对指定对象使用本机实际装备或持有资源，数量和落位明确 | 不会的动作直接拒绝；缺弹、缺份额、被占手、非法放置分别反馈，不改用另一种稀缺装备 |
| 救援 / 搬离伤员 | 到真实伤员处按生命合同拉起，或搬到玩家指定位置 | 普通医疗不能救Out；无路不承诺成功，禁止原地远程拉人 |
| 到撤离区 | 沿已知路线进入已开放扫描区，服从同一站圈规则 | 不替玩家中止主任务或自动放弃区外队员；100%仍是全队一次结束 |

“攻击这个目标”是一次性例外，不清除持续停火设置；执行完回到原开火政策。潜行默认不主动攻击Dormant/Stirring目标、不自动开灯扫房、不破门追击。Bot接近时照常产生脚步、碰撞和装备噪声；只用合法目视、声音及有效团队探测信息规划近处绕行，不拥有休眠免疫。开火允许时可自行对已知Active敌人换枪、瞄准、换弹和射击，遵守实际枪口、射线、弱点、弹药和前后摇；不让机器人依靠全图真相或零耗时操作承担四人完美同步。

已许可的手持探测器可以按明确持续探测命令使用，切出设备时不能同时射击；点标仍用原寿命和跟随规则。持续战斗不授权无限部署盾、泡沫、C4、定点探测器或投掷物；每次消耗型动作须有明确授权。新命令替换、多人成本竞争和控制交接由[AI-BOT-CONTROL](../技术/人工智能运行架构.md)验证，不以先播放回应作为命令成功。

指定攻击须明确使用当前哪件枪/近战及合法攻击方式；一次指一轮该武器定义的射击或一次近战挥击，不是“自动杀死为止”。蓄力、松开提交、取消和目标失效都沿原武器动作，不凭命令跳过蓄力。攻击预览显示所选装备和噪声类型，不泄露预计必杀或隐藏弱点；没有明确装备时先让玩家选择，不自动把静默近战换成爆破枪。持续开火政策只负责后续已知Active战斗。

## 物资、救援与接替的实际后果

COP-BOT-RESOURCES · 受托DECIDED。Bot的装填、受伤、资源包和世界重资产全部走真人同一规则。默认不自动拿公共包、不自动治疗别人或自己、不调用Pod、不吃掉电池/部件；缺资源只给一次状态反馈。拿取命令只授权搬持，不顺便授权使用。使用命令可以指定一份或当前包的实际余量，按有效补充扣费并保留溢出余量；Bot没有赠品库存。持续开火使用已装配枪弹不要求逐弹指令，有限工具/物资仍按上节逐次授权，避免把“守门”变成整包自动消耗许可。

调用补给、Cart选择、主节点启动、危险权限覆盖、字形组合、秘密房开通及主目标最终方案仍由真人提交；Bot可以搬材料、掩护、接收明确物资指令，不替人猜战略意图。供给按[ECO-007](资源回收额度与公共物资.md)沿Seat一次领取；机器人不是一个额外账号，奖励不产生可转交真人的虚拟分红。

COP-BOT-RESCUE · 受托DECIDED。可达队友倒地时，Bot可自动进入普通救援，不需玩家在倒地后操作菜单；留守命令在仍有其他真人站立时继续有效，此时可显式指派救援。全部真人倒地且至少一个Bot站立时，救援优先于留守/跟随/搬物。先在合法位置放下双手物，选有实际到达和救起机会的伤员；多个Bot不同时反复抢同一救援位，其余处理近处威胁或另一伤员。救起仍受攻击中断和出血限制，不保证成功，不自动花药、丢C4或叫补给。

近身攻击或当前危险会使Bot暂时躲避/清线再救；不能要求全房无敌人才肯救，也不能在同一条受击线上无限重启读条。无合法路径时标明阻隔，等待门态/队友位置等真实变化，不把寻路失败包装成“正在救援”。最先救谁按可达性及剩余救援窗口判断，同条件以稳定Seat顺序消除抖动，不优先房主。

Downed/Out的仍连接真人可用上述局部命令处理团队已经合法知道的目标；Out仍不能凭观战视角发现/标记未知敌人，也不能借命令直接进行本人已禁止的设施战略操作。全真人Out但Bot仍Alive，不伪装成全员Wipe，也不让Bot自动通关：仍可指挥已知局部行动、前往已开放出口，或沿现行真人一致机制中止/放弃。主目标未解决时Bot不会私自做最终选择；界面显示真实阻塞，不假装正在推进。

真人接替遵循COP-SEAT-CONTINUITY及COP-END-ADMISSION：同一身体、生命、两枪、现存包、已领份额与已提交动作不变。接替取消旧AI尚未提交的动作与战术命令；已经发出的弹体与已生效部署物继续。Bot之后再接回该身体也只读取现状，不重新套用局前库存。接替不继承旧操作者账号奖励或“我来”的承诺。

## 断线身体、补位与两种等待时间

COP-SEAT-CONTINUITY · 受托DECIDED，实际联机未运行。

断线保留的Seat与物资首轮分配资格使用不同计时：Seat归属保留见COP-009；Pod首轮等待见经济参数。Pod等待结束只释放该次未领取物资，不使身体复活、不解除Seat保留，也不重置旧领取记录。明确离队使未提交物资资格按Pass处理，但身体、已消费与世界后果保留。

只有已在入场会话启用Bot且有合法接管政策时，断线身体才允许交给Bot；默认Bot关闭时不暗中生成一名保护机器人。无控制者身体不获无敌或自动弹药，敌人仍按同样规则攻击。重连者接回当时真实状态，可能是Alive、Downed或Out；不把连网恢复当医疗。

中途新玩家优先继承现有Alive/Downed空Seat，完全继承装备、资源包状态、已领取记录和贡献epoch。不得把Out换成新的满状态同名角色。没有可玩空Seat时不让公开匹配假装有即时游玩位置；选择是否等待观战属于明确加入意图，不是无限转圈。已Out的原成员仍可以正常重连观察本局。

真人接替Bot时冻结交接点的输入所有者，旧Bot不能再提交下一步动作；已提交弹体、维修和世界交互保留。Bot不能一边交出身体一边掉出另一套装备。战术命令只请求已经存在的设施/队友能力，不把Ping变成绕权限、代花关键预算或替玩家解字形谜题。

验收覆盖断线时正在搬物、倒地掉包、Pod等待短于Seat保留、Bot接替、Out重连、离队后新成员加入、旧操作者迟到命令、已提交弹体迟到命中。共同断言是同一身体、一次库存、一次领取与清楚的可玩状态，不以修复联网体验为由赠送战力。
