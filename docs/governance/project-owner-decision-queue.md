# 仅需项目所有者裁决的事项

项目所有者不需要选择网络方案、编程模式、存档格式、日常平衡、目录名或每一件装备；这些选择已委托并会记录。下列事项仍由所有者决定，因为它们定义游戏身份、花费真实资金、需要账户权限，或修改所有者的明确要求。它们都不妨碍先制作零采购灰盒。

## OWNER-01 — 故事与四名角色

**需要所有者决定：**批准或修改完整[故事总览](../gdd/story-overview.md)，包括串联历史、四个代号 `断桥 / 回声 / 铁砧 / 寒蝉`、人物性格与关系。已经明确批准的历史事实不因本次审阅而失效。**当前建议：**批准世界结构进入写作；代号单独判断，不要仅为了不阻碍技术工作而草率通过。

**为何由所有者决定：**角色身份与作者表达属于创作权，不是库选择。此前要求明确保留这次审阅，并延后年龄、体型、外貌和选角。**决定前：**灰盒使用 01–04 号席位与中性战术呼号；不制作不可逆角色美术，也不安排付费配音。所有者审阅后，再委托一个真正全新、只读且不了解项目上下文的故事评审。本轮文档整理没有冒充完成这项盲审。

## OWNER-02 — 资金、账户、商业身份与产能

**需要所有者决定：**批准初期资产/工具预算上限、周期性服务预算上限和任何付费专家工作；后续批准商店最终名称、价格与发行日期。账户访问只能通过适当的安全连接提供，绝不粘贴凭据。**当前建议：**M1 证明核心交互并确认某项采购能解除实测瓶颈前，不购买任何内容。多人协调服务只有在限制、费用预测、告警与停用流程齐备后才可获准部署。

**为何由所有者决定：**文档不能擅自承诺支出、许可条款、云服务账单、法律实体或公开发行。Unity、Steam、Meshy 与其他供应商条款，以及具体资产许可，都必须针对实际账户和采购核查。这个公共 Git 仓库不得接收购买的原始模型或保密合作资料。**决定前：**使用本地工具、原创灰盒资产与模拟的平台/控制面测试；真实在线服务、Steam 合作伙伴启用和商业许可仍是部署 Gate。每周可用时间与人员尚不明确，因此路线图按里程碑管理，不承诺日期。

## OWNER-03 — 角色外貌、声音与不可逆品牌呈现

**需要所有者决定：**在角色性格获批后，接受角色外貌、声音、演员和不可逆品牌呈现。全局 Visual DNA 已按本轮委托锁为“分层壁垒”的中等多边形风格化工业科幻，不再把普通材质、模型预算或工具选择退回所有者投票。

**为何由所有者决定：**角色身份、声音和商店级品牌承诺属于创作与商业身份。**决定前：**采用中性灰盒比例和临时音频；不擅自指定年龄、性别、面孔、体型或演员。Unity Style Target 和性能测试属于生产 Gate，若测试只要求调整材质、灯光或局部资产档位，不重新打开 Visual DNA；只有证据表明核心语法不可行时才回到所有者队列。

## OWNER-04 — 削减任何明确要求

**仅在证据要求时由所有者决定：**是否删除或修改可选 TPS、可选机器人队友、Steam Deck 60 FPS、主机迁移、详细统计、临时本地回放、固定正史角色或自动安全模组同步等明确需求。**当前建议：**保留这些合同，按依赖顺序逐项验证；只有性能分析或原型确认成本后，才提交范围明确的取舍。本条是变更控制规则，不是要求所有者重新决定全部功能。

## 无需等待所有者选择的事项

以下事项已经有基线：基础版只做 Operation；两把枪/一件工具/自由战术模块；有限能量弹药；Operation 不自动融合；Unity 6.3 LTS + URP；FishNet/Steam 联机；小型在线权威协调服务；快照恢复与有限回溯；JSON 创作数据加版本化二进制运行记录；Data/Graph/Luau 公共模组架构，其中 Luau 上线前必须通过安全/性能 Spike；禁用社区 DLL；精确哈希缓存政策；单一集成模组管理器；中文文档与文本基线；分阶段实施计划。测试可以推翻实现细节，但“尚未测试”不等于“让所有者挑技术”。
