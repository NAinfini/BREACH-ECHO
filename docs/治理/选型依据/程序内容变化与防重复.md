# 程序内容变化与反重复

## 决定

DEC-PROCEDURAL-CONTENT-VARIATION-001 · 受托决定 / 尚未测试。

程序Operation采用“通过验证的完整组合 + 确定性种子变化”，不直接开放路线、目标、设施、环境、支线和奖励的任意笛卡尔积。首轮为黑启动、分布式取证和货运线夺回各建立四个`CandidateCombinationProfile`，合计十二个；只有通过固定合同、结构Seed与人工玩法Gate后，候选才升格为`ApprovedCombinationProfile`并进入任务板。

每局写入七维`VariationSignature`。同一Primary的两局只有在路线/任务定义/设施耦合至少一项不同、七维总计至少三项不同，并能让玩家改变至少两项计划时，才算不同体验。房间旋转、材质、走廊长度、目标换名、敌人数微调和回收点移墙均不计。

共享八Offer使用服务端确定性洗牌袋：同轮同一Primary不重复配置，配置池耗尽前不回填，跨过袋尾时只接受数学上不可避免的最少复用；不做每账号隐藏自适应。只有通过任务合同、可解性、资源、设施、敌源、性能和人工节奏验证的组合能进入任务板。

## 理由

未经验证的组合乘法会产生大量合法但无聊、叙事矛盾或资源软锁的地图，并制造虚假的内容量。完整候选配置先保留作者节奏，通过Gate后才成为运行时批准配置；签名使自动系统能拒绝明显近似，人工盲测则检查签名差异是否真的转化为玩家决策。全服共享反重复与任务板/匹配承诺一致，也避免玩家因隐藏难度或掉落调节无法比较同一Offer。

## 拒绝方案

- 纯手制固定长关：重复游玩会退化为背板，且违背已锁程序Operation方向。
- 完全自由的生成器：组合爆炸、难以验证，并会让算法编造任务逻辑或叙事真相。
- 只以Seed/hash不同计新局：无法证明体验不同。
- 按玩家历史秘密调敌人、资源或奖励：破坏共享任务板、公平归因和可复现性。
- 对理论组合数量做宣传：未经生产和玩法验证，不构成内容承诺。

## 影响与重审条件

该决定增加了内容作者为每个完整组合编写约束、走读和维护批准表的成本，但显著减少无解组合和“随机走廊”风险。十二个配置是M4首轮验证规模，不是最终首发数量。

若人工盲排20 Seed中明显无聊或不公平超过15%，或同一策略在超过70%的可比较局势无条件占优，先删除/重做组合，而不是扩大理论池。若共享任务板在实测中因批准池过小频繁重复，则增加通过同一Gate的新配置或降低同一Primary出现频率；不得放宽签名规则或用奖励数字伪造差异。
