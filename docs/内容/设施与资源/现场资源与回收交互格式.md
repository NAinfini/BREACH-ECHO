# 现场资源与回收交互格式

## 目的与唯一所有权

RESOURCE-COLLECTION-001 · DECIDED / 参数TEST / 尚未实玩。

本文拥有Operation内“玩家看见什么资源、怎样取得、是否携带、用于什么、如何结算”的内容格式。经济账本、补给投送与永久Credits由[经济与支援](../../玩法/资源回收额度与公共物资.md)拥有；设施用途由[设施系统](../../玩法/设施信息与控制规则.md)拥有；任务是否要求某件物品由各Mission Contract拥有。

普通支援价值不再表现成走近后自动吸入背包的散落废料。壁垒真正需要的是可以远程复用的技术资料、设备诊断、材料位置与合法回收权；外勤队在现场生成可验证的`RecoveryRecord`，壁垒据此增加本局**后勤额度**`LogisticsQuota`并在成功撤离后结算Credits。玩家看到“后勤额度 +N”，它表示壁垒愿意为这次行动追加的运输、装填与物资能力，不是第二种信用点，也不是角色携带的代币。无法随身携带的大型机械、金属和库存由玩家标定，后续工业队处理；四名玩家不把几吨废铁塞进口袋。

这不是“所有东西都变成下载”。弹药、医疗、工具、电力单元、冷却罐、样本、任务核心和可拆部件继续拥有实体世界状态。数据只取代原先没有动作、没有体积解释的通用废料货币。

## 首发资源格式

RESOURCE-COLLECTION-002 · DELEGATED DECISION / TEST。

| 格式 | 玩家现场动作 | 初始时长 | 是否携带 | 主要用途 | 明确不做 |
|---|---|---:|---|---|---|
| 数据接驳 `DataTap` | 靠近有可读端口的设备，抽出通用外勤盘，插入并完成一次短接驳 | 1.0秒 | 否；提交后写入团队账 | 常见RecoveryRecord，1额度 | 长终端菜单、自动吸取、重复下载 |
| 资产标定 `AssetSurvey` | 对大型机组、库存架或报废结构的铭牌/关键材料区近距扫描 | 1.25秒 | 否；记录位置、成分与回收权 | 工业空间RecoveryRecord，2额度 | 假装把大型废料背走、隔墙扫描 |
| 诊断抽取 `DiagnosticExtract` | 对已供电、已修复或已接管的设施执行短诊断，抽取状态与蓝图差分 | 1.5秒 | 否；写入团队账 | 条件型RecoveryRecord，2–3额度 | 每台终端都能刷、无前置条件白拿 |
| 回收信标 `SalvageBeacon` | 把一次性定位贴附在完整大型资产上，再短按确认结构轮廓 | 1.25秒 | 信标提交后留在物体上 | 无数据端口的大型资产，2额度 | 要求玩家搬资产、信标贴空墙 |
| 蓝图映射 `BlueprintImprint` | 将外勤盘贴近制造机/原型台，沿可见导轨扫过关键组件 | 1.5–2秒 | 否 | 稀有工程RecoveryRecord，2–3额度 | 普通箱子也产蓝图、同一型号无限刷 |
| 信号截获 `SignalCapture` | 在天线、界桥线圈或通信缓冲器插入感应夹，保持至一帧完整波形 | 1.5秒 | 否 | 通信/路由RecoveryRecord，2额度 | 与字形知识混账、全图被动收取 |
| 系统镜像 `SystemImage` | 对已禁用、已接管或停机的炮塔/机器人接入维护口，复制故障与协议状态 | 1.5秒 | 否 | 安保设施RecoveryRecord，2额度 | 从每次击杀掉落、边打边自动领取 |
| 材料微样 `MaterialTrace` | 用探针在已标记的合金、冷却沉积或生态残留上取微量样并现场光谱化 | 1.25秒 | 微样当场分析，不占Resource Pack | 环境/生物材料RecoveryRecord，1–2额度 | 从所有尸体反复剥取、替代任务样本 |
| 物资封存箱 `SupplyCache` | 拉闩、切封或双手掀盖；内容在开启时一次生成/显露 | 1.0–1.5秒 | 内容进入Resource Pack或留在世界 | Ammo、Medical、Tool | 转成后勤额度、远距秒开 |
| 可拆部件 `ComponentPack` | 打开检修板并拆下标准模块；高价值件可要求工具或断电 | 2–4秒 | 是；首轮实体部件占双手，可放下/转交，不占用或新增Resource Pack槽 | 修理、冷却、旁路、可选设施 | 通用货币、无重量含义的数据 |
| 电力与工业介质 | 从插座/支架拔出电力单元、冷却罐、燃料或压力瓶 | 依物件合同 | 是；电力单元仍双手且不减速 | 设施、任务、重资产 | 被Ammo Pack或RecoveryRecord替代 |
| 样本与现场证物 | 装入采样管、封袋或专用容器并登记来源 | 1–3秒或任务合同 | 由任务卡声明实体载体；首轮需搬运者占双手，已登记事实不占物理槽 | 主线、支线、叙事、研究 | 与普通数据接驳混淆、直接兑本局补给 |
| 字形采录 `GlyphCapture` | 用外勤盘/摄像头完整记录字形、节点响应与校验 | 约1秒 | 否；进入GlyphRecordLedger | 秘密路由、Archive、成功撤离Credits | 消耗为补给货币 |
| 黑匣子/数据核心 | 物理拆取后搬运，或在合法设备进行明确上传 | 任务合同 | 是，直到交付/上传 | 主线或高价值支线 | 当成普通1秒接驳、提交后还能复制 |

八种RecoveryRecord不是要求每局全部出现。每个MissionSite从中选择二至四种，且至少包含两种不同手部动作：插盘、近距扫描、贴附信标、沿组件映射、夹取波形、接维护口或探针取样。“数据接驳”和“诊断抽取”必须通过端口、屏幕、进度灯、外勤盘动作和设备状态做出视觉差异；“资产标定”和“回收信标”必须指向真实可见的大型对象。若多种来源只剩相同的圆圈读条，内容即使数值不同也算失败。

## RecoveryRecord交互合同

RESOURCE-COLLECTION-003 · DECIDED / TEST。

每个可回收来源有唯一`RecoveryRecordID`、`sourceKind`、`worldInstanceID`、`value`、`requirements`与`state`。默认状态流是：

`Available → Interacting → Committed → Drained`。

玩家必须位于合法距离并拥有视线；互动开始后武器降低，但不锁死视角。移动离开、切枪、倒地、受击达到打断阈值或设备失去前置状态，会在`Committed`前取消且不发部分额度；1秒DataTap的设计目标是让动作可见、可被风险打断，但不把拾取变成劳动。Authority只在Commit事务中将唯一记录同时写入`LogisticsQuota`和`GrossRecoveryLedger`。重传只返回同一结果；断线、主机迁移、两人同时接驳或重复进入房间都不能再次登记。

成功提交后设备必须有明显的已抽取状态：拔出的盘、熄灭/变色指示灯、空槽、已标定标识或UI中的共享记录。全队立即共享额度和记录，不以最后一击、先按键者或背包归属决定奖励。

## 额度、分布与补给关系

RESOURCE-COLLECTION-004 · DELEGATED DECISION / TEST。

标准40–50分钟四人合同的首轮起点：

| 参数 | 起始值 | 原因 |
|---|---:|---|
| 唯一RecoveryRecord总数 | 5–8个 | 足以产生探索选择，不把每个房间变成下载站 |
| 可取得LogisticsQuota | 10–14后勤额度 | 允许2次标准投送，并以可选探索争取第3次 |
| 主路保底 | 至少8额度 | 即使不贪支路也能合法投送2次 |
| 标准Pod成本 | 4额度 | 与10–14总量形成明确机会成本 |
| 同一房间/Cluster的普通回收互动 | 最多2个 | 防止一进房连续按五次互动键 |
| 连续相同交互 | 最多2次 | 三次同样的插盘动作直接判定为内容重复 |

主路可用DataTap保证最低额度；支路优先放AssetSurvey和有设施前置的DiagnosticExtract，让额外回报来自理解空间与恢复系统，而不是搜遍墙角。无限探索区可以提高高价值记录、字形与原始研究密度；限界探索区更常直接留下物资封存箱、可接管炮塔、机器人和维护件。区域差异不能只改同一图标的数字。

普通击杀不掉RecoveryRecord，敌人尸体不产后勤额度，反复开关设备不刷新记录。MaterialTrace只能来自生成时登记的独特环境/生态样点，SystemImage只能来自登记过的设施实例；两者都不能把杀敌变成刷点。任务战略货物、人工太阳燃料、关键冷却介质与控制部件不得拆成通用额度。调用补给只减少`LogisticsQuota`，不回退`GrossRecoveryLedger`；已登记记录在成功撤离时仍可形成Credits，失败撤离不把未结算记录写入账号。

## 任务与程序生成约束

RESOURCE-COLLECTION-005 · DECIDED / TEST NOT RUN · 生成约束尚未运行。

生成器必须先保证主线解法、关键任务物和撤离，再放回收记录。每个记录要落在语义匹配的位置：服务器/研究台承载DataTap，成套工业资产承载AssetSurvey/SalvageBeacon，已恢复设施承载DiagnosticExtract，制造/原型空间承载BlueprintImprint，通信与界桥空间承载SignalCapture，安保空间承载SystemImage，有作者定义独特样点的环境才承载MaterialTrace；随机把数据口、信标点或样本贴在空墙上无效。生成事务同时验证唯一ID、前置状态、可达性、交互空间、同Cluster密度、来源族多样性、后勤额度总量、接收点覆盖和返回路线。

RecoveryRecord不能充当路线钥匙，也不能被最高权限自动全收。可选警报、供电或深路可以提高取得效率或打开高价值来源，但主路保底额度不得依赖秘密字形、最高Clearance、单一随机掉落或强制三次往返。若一条支路只有一个1额度DataTap且没有信息、资源或空间变化，它不值得存在。

## 可读性、合作与失败测试

RESOURCE-COLLECTION-006 · TEST NOT RUN。

首轮灰盒至少验证：

- 12名首次玩家中至少9名在首局后能区分“后勤额度记录、实体物资、任务证物、字形知识”；
- 12名首次玩家中至少9名能解释“标定大型废料，而不是把它装进口袋”；
- DataTap互动中位时长接近1秒，玩家不会因为它太短而看不见动作，也不会因重复停顿把探索称为杂务；
- 每份40–50分钟合同不存在三个连续相同回收动作，同一Cluster不超过两个普通回收点；
- 两人并发、取消、受击、断线、主机迁移和重复载入都保持唯一记录与额度守恒；
- 2次Pod是主路可达，第三次需要额外探索或条件型记录；补给没有消除末段资源压力；
- 玩家能仅凭外观和一条短提示判断至少四种当局RecoveryRecord来源及任务上传，不必打开教程词典；同一局出现的来源族不少于2种、不多于4种。

若“插盘一秒”在测试中仍被玩家概括为给每个宇宙路由器装驱动，优先减少普通DataTap数量并增加资产标定、实体封存箱和设施条件型诊断；不得用更长读条掩盖内容重复。

## 被拒绝的格式

RESOURCE-COLLECTION-007 · DELEGATED DECISION。

- **散落废料自动吸取：** 没有现场动作，也无法解释携带体积；拒绝。
- **所有资源都做数据下载：** 会把不同空间和奖励压成同一个终端动作；拒绝。
- **重复5–10秒采矿/拆解条：** 与40–50分钟高压任务不匹配，只增加劳动；除任务专属大件外拒绝。
- **格子重量背包：** 会把合作射击变成整理库存，并与单Resource Pack槽冲突；拒绝。
- **击杀掉支援点：** 形成Kill→Support→Ammo正循环，奖励刷怪而不是任务规划；拒绝。
- **全图自动扫描领取：** 删除探索、风险和空间语义；拒绝。

## 程序任务内容接口

逐任务的来源池、主路/支路分配、动作差异和反重复规则已经落入[首轮程序任务内容池与重复可玩性矩阵](../任务/首轮程序任务内容与重复可玩性矩阵.md)。该矩阵只能引用本文的八种RecoveryRecord来源和密度合同；若需要新增第九种来源，必须先回到本文说明现场动作、语义位置、凭据与结算，不能在任务配置里临时创造同义下载点。

## 物理槽位与供给单位

RESOURCE-PHYSICAL-SLOTS · 受托DECIDED。

首轮只有一个Ammo/Medical/Tool资源包槽和一个双手持物状态，不存在未定义的通用“任务背包”。电力单元、实体部件、档案筒、黑匣子与伤员按任务各自声明占双手，可放下再作战；已登记的记录、字形和证据知识是数据，不伪装成可复制的实体。未来小型样本容器若需要独立携带方式，必须先定义容量和手部动作，不能默认无限装。

内容卡区分“容器/补给舱”和“个人份”：容器可能装多份，但玩家一次仍只能带一个容量内的包。容量、使用和拆合守恒由[经济合同](../../玩法/资源回收额度与公共物资.md)唯一拥有。固定主路资源只按任务预算生成一次，开启箱子、接管、重新通电或重连不重新填满。

## 资源动作的声学映射

RESOURCE-INTERACTION-NOISE · 受托TEST。动作时长只取RESOURCE-COLLECTION-002，补给时序只取ECO-DELIVERY-TIMING；半径、刺激、频率、取消与去重只取[战斗交互声学](../装备/战斗原型数值.md)，不在此配置第二套值。

| 来源/动作 | 输入档 | 实际声源 |
|---|---|---|
| DataTap、AssetSurvey、DiagnosticExtract | 接口 | 外勤盘或设备端口；不同手部动作仍须保留 |
| SalvageBeacon、MaterialTrace | 卡扣 | 贴附装置或取样器；不是大型资产倒塌 |
| BlueprintImprint、SignalCapture、SystemImage | 校准 | 读头、感应夹或维护口；按实际持续时间发脉冲 |
| SupplyCache | 卡扣 | 真实箱闩；拆封声与完成声同根，不重复生成内容 |
| ComponentPack、电力/介质拆取 | 卡扣；实际机构动作另用机构 | 检修板与插座；不凭物品价格扩大声源 |
| 样本封装、黑匣子/核心取出 | 卡扣，任务声明的加工另计 | 实体容器；任务原时长不被普通下载替代 |
| GlyphCapture | 接口 | 外勤盘；打开秘密路由是另一件设施动作，不包含在采录中 |
| Ammo/Medical/Tool包拾取、拆合、使用 | 卡扣 | 玩家手中物品；使用时间仍为经济合同2s |
| 残量能量端口 | 校准 | 固定端口，支付有限权益，不补重资产 |

开始动作前被权威拒绝不发刺激；合法操作中途取消保留已发刺激，不生成部分回收记录。拆合资源包不能反复生产余额，噪声去重也不能被当成免费重试隐身机制。环境损毁另走真实冲击事件，不把每次按取样器当爆炸。
