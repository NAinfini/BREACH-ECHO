# 全动作手感与舒适性验收

## 完成不是“能触发动画”

FEEL-ALL-ACTIONS · 所有者CANON目标；执行方式受托DECIDED，测试未运行。

所有枪械、近战、工具以及移动、设施操作、搬运、补给、救援和撤离交互都须通过手感验收。先保证输入可靠、实际结果清楚、动作衔接顺畅，再添加必要的表现；不把手感留到量产结束再统一修。每项进入首轮的内容先达标再扩量，未入选候选不提前制作。

手感不是伤害高、特效大或镜头乱动。短刀应能精准放手，重锤应有可读的承诺和接触，狙击应有清楚的复位节奏；玩家应知道为什么没出手、为什么打中甲板、什么时候已经能换枪。

## 稳定镜头是基础，不是降级模式

FEEL-COMFORT · 不依赖震屏、镜头晃动与运动模糊为所有者明确要求；默认设置受托DECIDED。

震屏、移动头部晃动、冲刺镜头滚转、装饰性落地颠簸与运动模糊默认关闭；冲刺自动拉伸FOV默认关闭。首轮不把制作这些效果列为任务，不用速度线、强闪光或强制镜头拉扯替代。既有可选表现若未来保留，必须由玩家主动开启，且不能携带独占信息。舒适基线不能成为少功能、慢反馈或减弱命中确认的模式。

真实瞄准后坐、玩家主动转向、所选瞄准镜倍率和必要的摄像机碰撞不等于装饰震屏；其公平规则不因舒适设置改变。后坐图样应平滑、可学习，无额外随机抖镜；不得以“真实后坐”为名加入冲刺头晃或被击中强甩视角。武器模型可以表现机械运动，但不能遮住目标或带动整个世界摇晃。

速度感靠实际位移、近远场景参照、脚步节奏、姿态转换和操作响应。打击感靠接触位置、材质音色、武器短暂形变/机械回弹、敌人的合法受击与部位变化。冲击不能虚构玩法硬直：只有伤害系统批准的打断才改变敌人动作。停止渲染某个武器部件可作待测表现，但不得冻结全局时间、输入、瞄准、敌人或多人模拟；首轮不使用全局hit-stop。

## 全动作验收表

| 动作 | 玩家必须看懂或感到什么 | 必须拒绝的情况 |
|---|---|---|
| 移动、起跑、跳跃、落地、滑铲、翻越 | 实际位移与输入相符，脚步/接触和动作姿态有节奏，落点能预判 | 用模糊或FOV猛变遮盖慢响应；落地强甩镜头；为动画偷改速度 |
| 开枪、点射、持续射击 | 触发、机械循环、弹道与命中反馈分明；射速和后坐可学习 | 子弹已发却等动画才反馈；预测开枪即显示假击杀；枪焰挡住连续瞄准 |
| 换弹、切枪、开镜 | 装入、可开火与完整动画结束分清；合法预输入可靠 | 看着装完仍无解释禁射；取消复制弹药；切枪漏输入 |
| 近战准备、释放、取消 | 任意时刻放手有对应攻击；右键撤销有简短退势；满蓄可保持同步 | 蓄力不足吞攻击；取消后松开偷偷出刀；收招中释放无提示丢失 |
| 接触、弱点、护甲、断肢 | 位置与材质准确，普通命中/甲板/弱点/真实失能可区分 | 单靠大伤害数字或颜色；扫描点暴露器官；假动作硬直取消敌人攻击 |
| 盾、C4、泡沫、烟、监测与驱雾 | 放置面、落点、作用区、资源提交及耗尽清楚 | 显示可放却提交失败无原因；回收重置耐久；烟清除无反馈 |
| 扫描与Ping | 点标跟随、淡出可读，操作占手与换枪衔接明确 | 描边淹没敌人姿态；实时更新偷偷续期；扫描完成卡住切枪 |
| 门、断路器、阀门、终端、字形 | 输入后有对应实体变化，危险和不可逆提交先说明 | 所有动作都只是同一种读条；动画结束才决定开门；取消误扣资源 |
| 收集、合包、补给、拿起与放下 | 物品唯一、归属和余额清楚；双手占用但不减速 | 连点重复领取；放下落到墙里；拿重资产额外限制转向 |
| 受伤、倒地、爬行、救援 | 状态和剩余机会清楚，准星仍可操作，救援中断有明确原因 | 被打强震屏；遮满画面看不见敌人；救援失败不解释 |
| 任务提交、撤离、战报退出 | 主目标与离场不是同一提交；剩余敌人和回放删除提示明确 | 完成任务偷删追兵；撤离点吞按键；看战报必须忍受摇镜过场 |

此表只拥有验收，不复制各系统时长/伤害。参考[输入](../玩法/玩家配装与输入.md)、[近战合同](../内容/装备/首轮近战攻击与资源合同.md)、[战斗参数](../内容/装备/战斗原型数值.md)、[生命规则](../玩法/生存倒地与失败恢复.md)与[摄像机时序](../技术/摄像机动画与玩法时序.md)。

## 实施与证据

每项动作必须绑定开始、合法提交、取消、完成和拒绝原因；本地预测只反馈输入已接收，权威结果才确认命中、资源与任务。动作表现跟随模拟阶段，不能反过来决定何时伤害。关键状态至少两种可替代通道，静音仍可操作，禁用震动/数字/闪光也不得失去必要信息。

先在稳定镜头、无模糊、无额外镜头效果下做单动作，再做“换弹→切近战→短按→取消→切枪→开镜”“拿任务物→放下→交战→救人→再拿起”等衔接。分别测试正常、空资源、被挡、同Tick取消/释放、倒地、菜单与设备切换、恢复中松开、断线和重复命令。

使用现行30/60/120/144FPS、键鼠/控制器与联机延迟矩阵，不另建更宽松Gate。操作至可见反馈目标引用PLY参数；输入时间、提交Tick、表现开始与结果确认分别记，不能拿本地音效速度冒充网络命中确认。保存构建、设备、设置、实际延迟/帧时、动作日志、失败复现；观察玩家是否能说明失手原因及是否出现不适，不能宣称所有人都不会晕。

硬失败：漏掉合法输入、重复攻击、取消后误攻、动画导致命中偏移、关闭效果丢关键提示、舒适设置改变伤害或资源、全局暂停影响多人。主观手感通过需真实玩家体验，使用既有战斗与输入Gate，不用“特效数量足够”代替。

当前只有设计要求，无Unity构建、动画样片或舒适性试玩证据。

## GTFO式控制感的对照目标

FEEL-MELEE-BENCHMARK · 所有者方向：保留其喜爱的按住、释放与取消控制感，并争取更好的整体操作体验。这里记录的是用户偏好，不是对GTFO技术实现的核验。

对照重点是短按即时响应、满蓄等待队友、右键取消、恢复中连续准备、取消后换枪开镜，以及压力下是否仍能准确表达意图。改进优先消除吞键、假命中、难读阶段和不必要的动画阻塞，不额外添加按键税、完美取消伤害奖励或镜头特效。其他武器与动作沿用同一要求，不要求所有武器相同速度或失去各自承诺。

批准开工后，以相同输入设备和舒适设置做可玩的对照，再记录玩家偏好、误操作、响应和不适。当前没有对照构建，不声称已经超过GTFO；若基础按住/释放都不可靠，停止扩充内容，先修动作系统。
